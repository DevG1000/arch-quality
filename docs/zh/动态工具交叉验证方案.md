# 与 Verrou/Valgrind 动态工具输出交叉验证方案

## 当前状态

**无项目提供实际的 Verrou/Valgrind/CADNA 运行时报告。** 
`has_dynamic_tool = True` 均来自源码中的关键词提及，而非运行结果。

交叉验证框架已就绪（`scripts/cross_validate_dynamic.py`），但需要**有人实际运行动态工具**才能工作。

## 实际操作流程

### 步骤 1：在项目上运行动态工具

#### 用 Valgrind 检测浮点异常

```bash
# 在编译好的可执行文件上运行
valgrind --tool=exp-float --xml=yes --xml-file=valgrind_report.xml ./solver input.cfg

# 检测内存错误（间接反映数值问题）
valgrind --tool=memcheck --track-origins=yes ./solver input.cfg
```

**适用项目**：MOOSE（TestHarness 内置 --valgrind 模式）、MFEM（sample-runs.sh -v 模式）

#### 用 Verrou 检测相消损失

```bash
# Verrou 基于 Valgrind 的动态插桩
valgrind --tool=verrou --rounding-mode=random ./solver input.cfg

# Verrou 输出 SQLite 数据库（verrou_*.sqlite）
# 可用 sqlite3 查询相消损失详情
sqlite3 verrou_report.sqlite "SELECT * FROM cancellations"
```

**适用项目**：任何可编译运行的可执行文件

#### 用 CADNA 检测数值不确定度

```bash
# CADNA 需要源码级编译
# 在 CMake 中插入 CADNA 类型
cmake -DUSE_CADNA=ON ..
make
./solver  # 运行时自动输出精度诊断
```

**适用项目**：FreeFEM（已内置 CADNA 支持）

### 步骤 2：将报告转换为标准格式

```bash
# Verrou SQLite → 标准 JSON
python -c "
import json, sqlite3
conn = sqlite3.connect('verrou_report.sqlite')
# ... 查询并输出 JSON
"

# Valgrind XML → 标准 JSON
python scripts/cross_validate_dynamic.py \
    --static tests/regression/snapshots/numerical_baselines/MOOSE.json \
    --dynamic valgrind_report.xml --tool valgrind

# 或直接使用 JSON 中间格式
python scripts/cross_validate_dynamic.py \
    --static MOOSE.json \
    --dynamic dynamic_report.json --tool json
```

### 步骤 3：运行交叉验证

```bash
# 使用模拟数据演示（本工具已内置 FEniCSx 的模拟报告）
python scripts/cross_validate_dynamic.py --mock FEniCSx

# 使用真实基线 + 真实动态报告
python scripts/cross_validate_dynamic.py \
    --static tests/regression/snapshots/numerical_baselines/MOOSE.json \
    --dynamic path/to/verrou.sqlite --tool verrou
```

输出示例：
```
| NVR | 静态触发? | 动态触发? | 一致性 |
|:----|:---------:|:---------:|:------:|
| NVR-001 | True | True | 一致 |
| NVR-003 | True | True | 一致 |
| NVR-004 | False | False | 一致 |
| NVR-008 | True | False | 误报 |
```

### 步骤 4：解读结果

| 一致性 | 含义 | 行动 |
|:-------|:------|:------|
| **一致** | 静态检测与动态工具结论一致 | ✅ 不需修改 |
| **误报** | 静态认为有问题，动态确认无风险 | 需要放宽检测阈值或优化模式 |
| **漏报** | 静态未检出，动态发现风险 | 需要补充检测模式 |

## 框架能力

| 功能 | 状态 |
|:-----|:------|
| Valgrind XML 解析器 | ✅ 已实现（`ValgrindReportParser`）|

| 标准 JSON 中间格式 | ✅ 已定义 |

| 交叉验证对比 | ✅ 一致/误报/漏报三类判定 |
| 报告生成 | ✅ Markdown 格式 |

## 阻碍因素

1. **需要运行环境**：Valgrind/Verrou 在 Windows 上支持有限，建议在 Linux/WSL 上运行
2. **需要可执行文件**：工具需要目标项目可编译运行，纯库项目（如 deal.II）需要配套的测试用例
3. **性能开销**：Valgrind 插桩会使运行速度慢 10-50 倍，建议选取小型测试用例
4. **无 CI 集成**：目前没有项目的 CI 管道中运行动态工具，缺少持续性产出

## 最小可行实验

如果你想快速验证这个方案可行的"最小成本实验"：

```
1. 选取 FEniCSx（最小项目，504 文件）
2. 在 WSL/Linux 上编译 FEniCSx 的某个测试用例
3. 用 Valgrind 的 exp-float 工具运行
4. 获取 XML 报告
5. 运行本脚本对比
→ 预计耗时：半天
```
