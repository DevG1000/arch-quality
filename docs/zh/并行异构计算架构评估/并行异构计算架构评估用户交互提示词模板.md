# 并行/异构计算架构评估 — 用户交互提示词模板

> 文档编号：HPC-C3-用户提示词
> 说明：面向用户在 OpenCode 中使用的提示词模板，用于调用 `architecture-quality` 智能体执行并行/异构计算架构评估。
> 关联文档：《并行异构计算架构评估指南》v0.8、《并行异构计算架构评估验证案例集》v0.4

---

## 1. 基础评估

```
请对 [项目路径] 执行并行/异构计算架构评估，
汇报 overall、4 个子维得分（backend_consistency / mpi_halo / load_topology / hybrid_parallel）、
适用集（applicability_set）、门禁状态（gate_status）和 HPC 违规清单。
```

**示例**：
```
请对 D:/opensource/OpenFOAM-v2512 执行并行/异构计算架构评估，
汇报 overall、4 维得分、适用集、门禁和 HPC 违规清单。
```

## 2. 单维度分析

```
请分析 [项目路径] 的 [后端接口一致性 / MPI halo / 负载均衡 / 混合并行]：
- 后端：CPU/GPU 是否有双实现不一致？设备守卫是否缺失？
- halo：Isend 是否配对？halo 宽度是否足够？
- 负载：分区是否加权？通信域是否隔离？
- 混合：omp parallel 内是否直接调 MPI？共享变量是否有竞态？
```

## 3. 规则排查

```
请检查 HPC-00X（规则名称）在 [项目路径] 中的具体情况，
说明涉及文件、影响范围和建议修复方式。
```

**示例**：
```
请检查 HPC-005（halo 交换配对）在 D:/opensource/SU2 中的具体情况，
说明哪些 Isend 未配对、是否跨函数，以及如何修复。
```

## 4. 改进建议

```
请基于最近一次评估结果，给出 [项目路径] 的并行/异构架构改进建议，
按 P0（正确性/死锁）、P1（扩展性/负载）、P2（性能优化）排序，并给出验证方式。
```

## 5. 验证域

```
请说明本次评估结论适用的验证域（Re / Ma / 网格规模 / 进程数范围），
以及哪些工况属于未验证外推。
```

## 6. HPC 与 V&V 的关系

```
请解释 HPC-001（CPU/GPU 双实现一致性）与 Validation（E / U_V）的区别：
前者是 code-to-code Verification，后者才是对实验（EFD）的 Validation。
```

## 7. 常见追问

| 问题 | 建议提示 |
|:--|:--|
| 为什么某规则是“候选（candidate）”而不是“确认”？ | 请说明该规则的确认链：LLM 语义精判 → TAU 实测 → 人工裁定 |
| 为什么总分没变但等级被“需改进”？ | 请解释“HPC 维度子分封顶、不回写总分”的展示规则 |
| 不同项目的 HPC 分数能直接比较吗？ | 请检查 `applicability_set` 与 `score_scope=subset` |
| Kokkos 项目为什么 GPU 子维不适用？ | 泛 `Kokkos::` 只表 HPC；GPU 适用需 `KOKKOS_ENABLE_CUDA/HIP/SYCL` 等后端信号 |

## 8. 注意事项

- 评估命令应只读；不要修改项目源码。
- `candidate` 只是风险信号，不等于“已确认缺陷”。
- **HPC-010 首期 output_level 为 WARNING**（severity 仍 HIGH），升级需更多样本 + 运行时确认。
- 综合报告与单引擎报告的分数语义一致（激活子集归一化），但**不要跨不同 `applicability_set` 排名**。
