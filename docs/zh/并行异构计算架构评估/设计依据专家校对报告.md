## 二、问题清单

### P0（阻断，必须清零）

**P0-1 SU2 被当作 GPU / CPU-GPU 双实现样本 —— 证据杜撰**
- **问题**：§1.3、§2.2、§4.3 将 SU2 列为"MPI×OpenMP/CUDA 多后端、CPU/GPU 双实现"的混合/GPU 样本。
- **证据**：全仓检索 `__CUDACC__|ENABLE_CUDA|cudaMemcpy|cudaMalloc|hipMalloc`，唯一命中 `D:\OPENSOURCE\SU2\externals\catch2\catch.hpp`（第三方测试框架），**无任何真实 GPU/CUDA 实现**。
- **修订**：删除 SU2 的 GPU/双实现归属；GPU 样本改用 **MFEM**（63 处 GPU 后端）；SU2 更正为"MPI + 少量 OpenMP（3 文件）"。

**P0-2 案例普遍缺"可溯源锚点" —— 违反编制指南证据要求**
- **问题**：编制指南 1.8 要求"专家校对意见须附可核实证据；AI 生成的行业案例须可溯源"。当前案例只给类名/概念，未锚定 `repo@rev + 具体类/文件`；P0-1 正是"未锚定即杜撰"的实证。
- **修订**：每个 A 类样本补锚点（例：`OpenFOAM-v2512 src/OpenFOAM/.../processorPolyPatch.C`、`deal.II include/deal.II/distributed/tria.h`、`MFEM linalg/...`），并在验证案例集（阶段 4）逐条绑定。

### P1（应修，影响可信度/效度）

**P1-1 deal.II 的"MPI×OpenMP"归属不准**
- **证据**：deal.II `#pragma omp` 31 文件但主并行是 MPI + **TBB/Taskflow 线程**（`Threads::Task` 7 文件）；把 deal.II 当"MPI×OpenMP"典型易误导读者以为其混合方式为 OpenMP。
- **修订**：改为"MPI + 线程（TBB/Taskflow，局部 OpenMP）"。

**P1-2 ASME V&V 20 误引**
- **问题**：§4.4 称 V&V 20"对并行数值验证提出要求"。
- **证据**：ASME V&V 20 是 **CFD/传热的 Verification & Validation 方法学**标准（网格/时间步收敛、比较误差），**不规定并行验证或扩展性**。
- **修订**：改为"V&V 方法学（网格收敛/比较误差）"；并行验证另引"强/弱扩展基准、code-to-code 对比、MPI 正确性工具"。

**P1-3 HPC-009（未用 `comm_split`/cartesian 即缺陷）假阳性高**
- **问题**：大量正确、可扩展的并行代码使用 `MPI_COMM_WORLD` + 自定义邻居通信，未用 `comm_split`/cartesian 拓扑**并非缺陷**。
- **修订**：降为 INFO 或移除；若保留，窄化为"存在多物理场/多网格通信域混用而未隔离通信子"这一具体反模式。

**P1-4 递进扣分（基础层均分<60 → 负载均衡折半）缺依据且耦合可疑**
- **问题**：正确性（halo/后端/混合）与可扩展性（负载均衡）相对**正交**——halo 配对错不代表负载划分差；且"60"阈值无实证。
- **修订**：论证耦合合理性并给出阈值来源；否则改为四个子维**独立**评分（遵循本轮约定的 30/30/20/20），不设递进折半。

**P1-5 静态可检性夸大**
- **问题**：HPC-004（搬运冗余）、HPC-006（热循环集合通信）、HPC-007（通信/计算重叠）、HPC-008（加权划分）本质属**性能/语义级**，静态检测假阳性高、常需调用图/运行时。
- **修订**：设计依据不暗示"皆可机检"；指南阶段必须付**规则可行性分级矩阵**（🟢/🟡/🔴 + KNOWN_HOLES），并标注置信度，禁止低置信度设 ERROR。

### P2（可选，表述精化）

**P2-1 "halo 宽度与子域维度不一致"表述不准**
- **问题**：halo 宽度由 stencil 阶数决定；典型缺陷是"halo 不足以覆盖 stencil / processor patch 寻址错 / 阻塞 `Send` 未配对致死锁"，而非"宽度与子域维度不一致"。
- **修订**：改为上述具体模式。

**P2-2 `MPI_THREAD_MULTIPLE` 的年代归属**
- **问题**：行文易被读作 MPI 4.1 引入线程级。
- **修订**：注明"线程级自 **MPI-2.0** 起定义，现行为 MPI 4.1"。
