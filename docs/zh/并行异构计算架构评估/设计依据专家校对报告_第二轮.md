## 六、MFEM 参照性质补充核验（2026-10-21）

**核验对象**：设计依据中 "MFEM：`Device` GPU 抽象 + CUDA/HIP 后端 → HPC-001/002/003 参照"。

**源码实证**：
- `general/device.hpp:128 class Device`、`:229 Configure`；`device.cpp` `Allows(Backend::DEVICE_MASK)`、`#ifdef MFEM_USE_CUDA`、":438 未编译 CUDA/HIP" 报错 → **设备守卫/运行期查询属实**。
- `config/config.hpp.in` 有 `MFEM_USE_CUDA/HIP`；但 **`.cu/.hip` 文件 = 0**，`MFEM_HOST_DEVICE` **191 文件** → **统一单源内核**（CPU/GPU 同一份源码）。
- launch 抽象在 `general/forall.hpp`（`MFEM_FORALL` 宏）；`<<<` 仅 **8** 处、`dim3` 仅 **11** 处，**全部在后端层** → **算法层无硬编码 launch**。

**结论（细化"参照"性质）**：
- **HPC-002**：MFEM 为**运行期守卫参照**（正样本）。
- **HPC-001 / HPC-003**：MFEM 是**正样本（最佳实践，不应触发）**——统一内核天然避免双实现分歧，抽象 launch 天然避免硬编码；**不得以 MFEM 充当这两个缺陷的阳性样本**。
- **阳性缺陷样本需 C 类合成**：HPC-001 → 两份归约顺序/精度不同的 CPU/GPU kernel；HPC-003 → 算法层写死 `blockDim`/裸 `<<<>>>`。

**已修订设计依据（5 处）**：§1.3（MFEM 改"统一内核规避"正样本）、§2.2（MFEM 正样本定位 + `MFEM_FORALL`）、§4.3 双实现表（去 MFEM 缺陷举例）、§4.3 正样本段（加 C 类合成说明）、附录 A（补 `general/forall.hpp`、`MFEM_HOST_DEVICE 191`、`.cu/.hip 0`）。

**复核判定**：修订后 MFEM 表述与源码一致，无新增矛盾。阶段 3 须据此在 12 规则校准中区分"正样本(MFEM)"与"C 类阳性合成样本"。

## 七、OpenFOAM / deal.II / SU2 参照性质核验（2026-10-21）

| 样本 | 引用规则 | 源码实证 | 参照性质判定 |

| **OpenFOAM** | HPC-005/007 | `processorPolyPatch.C` 用成对 `UOPstream`/`UIPstream`（Pstream 交换）；`initInterfaceMatrixUpdate`/`updateInterfaceMatrix` 支持重叠 | **正样本（健康）**：正确配对 + 可重叠；**非缺陷样板** |

**已修订设计依据**：§2.2 正样本三条（OpenFOAM/deal.II/SU2 标注+锚点）、§4.3 负载表（deal.II 加权能力）、附录 A 用途列、新增"校准原则"注。
