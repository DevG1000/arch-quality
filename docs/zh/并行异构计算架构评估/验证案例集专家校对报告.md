## 二、问题清单

### P1（应修/须说明）

**P1-1 覆盖矩阵 B 列失真，违反 1.8 §4.4 双向核对**
- **证据**：§二 B 类表仅列 ANSYS（HPC-005/010）与 COMSOL（HPC-009），**无 HPC-008 条目**；但 §五 矩阵 `| HPC-008 | ... | ✅ |` 在 B 列标了 ✅。且 §二 明示"B 类…**不参与 KPI 覆盖计数**"，而矩阵仍以 ✅ 计入，构成"声称 > 实际"。
- **修订**：B 列改为"参考(不计)"或删去；HPC-008 的 B 单元格删除。确保矩阵每个 ✅ 可定位且计入口径一致。

**P1-2 A 类可复现性不足（无固定 ref）**
- **证据**：A-1 OpenFOAM 有 tag（`OpenFOAM-v2512`）；但 A-2 deal.II、A-3 MFEM、A-4 SU2 均只给 `D:\OPENSOURCE\dealii|mfem|SU2` 本地路径，**projects.yaml 中这些项目无 `fetch.ref`（仅 occt/salome 有，其余 WARN）**。1.8 §4.2 要求 A 类"复现条件具体（分支/版本）"。
- **修订**：为 A-2/A-3/A-4 补 `fetch.ref`（固定 commit），或显式标注"本地 checkout，rev 待固定（H3-F2）"。

**P1-3 HPC-010 的语义范围 vs 检测范围不一致（TBB）**
- **证据**：A-2 写 deal.II "HPC-010 → N/A 或低（用 TBB 非 OpenMP）"；但 HPC-010 的**语义**是"多线程区调用非 `THREAD_MULTIPLE` 的 MPI"（不限 OpenMP），而指南 §五检测逻辑限定 `omp parallel` **作用域**。
- **修订**：① 指南明确 HPC-010 静态检测**仅覆盖 OpenMP 作用域**（TBB/Taskflow 线程暂不检，交运行时 MUST/TSan）；② 案例集 A-2 改为"HPC-010 静态 N/A（非 omp 线程），运行时由 MUST 复核"。

**P1-4 合成负例判定前提不足（与指南"候选/确认"边界冲突）**
- **证据**：4.5 HPC-005 负例仅写 `MPI_Isend(...&req)` 无 Wait；但指南要求"**同作用域**且确无 Wait"才判 WARNING，跨函数/RAII/异步应记候选。4.8 HPC-008 负例注释称"自适应细化网格"，但代码片段未体现 AMR 迹象。
- **修订**：4.5 补"同函数结束前无 Wait"；4.8 补显式 AMR/多材料迹象代码；否则负例会被判为"候选"而非"触发"，与"负例应触发"预期不符。

**P1-5 C-1 的分数/数据为示意，未标注**
- **证据**：C-1"综合分 58 → 81""HPC-005 告警"等为示例数值，未标"示意"。
- **修订**：标注"**示例数据（示意，非某真实项目实测）**"，避免被当作实测证据。

### P2（精化）

- **P2-1 伪代码未逐条标注**：4.1（并行树归约注释）、4.2（`cnt` 未声明）、4.4（`kernel<<<...>>>` 省略号）、4.8（仅注释）等，应按 1.8 §4.3 标注"伪代码"或补真实 API 签名。
- **P2-2 B 类商业产品断言未实测**："ANSYS Fluent…GPU 加速、封装成熟""COMSOL…通信域隔离良好"为未核实断言；建议弱化为"行业存在良好实践（不针对具体产品特性）"。
- **P2-3 HPC-006 负例"可局部化"未具体化**：应展示"可局部化"特征（如局部累加可延后归约），否则与"每迭代残差归约属常规"冲突。
- **P2-4 A 类"低触发"表述含糊**：建议改"不触发/具体预期"，便于校准断言。
- **P2-5 OpenFOAM "无 OpenMP 混合"过头**：实测 `#pragma omp` 2 文件，应改"OpenMP 极少，混合规则基本 N/A"。
