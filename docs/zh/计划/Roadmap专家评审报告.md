## 二、三大结构性缺口

### 缺口 1：维度完备性未证明，且漏了工业软件命脉面
- 8 维为 P0–P4 自下而上归纳，无对照 ISO/IEC 25010 + 工业 CAE 架构学的自上而下校验
- **数据交换与互操作（STEP/IGES/IFC/单位制/公差换算）完全缺失**——CAD/CAE 的生命线
- ⑥ "HPC 与异构后端接口一致性"命名过窄（漏 MPI 域分解/halo/负载均衡/GPU 路径发散）
- ④ 把几何内核（B-Rep/OCCT Handle）与科学数据结构（网格/场量）两个不同关切混在一维
- ⑦ 与演进质量、⑧ 与设计质量(SOLID-DIP)/多语言绑定层存在双重计分风险

### 缺口 2：H1"可信化"缺"可信"自身的 KPI
- 4 个 KPI（规则覆盖 100% / 性能 P90<10min / 元模型 / 试点）全是工程指标
- deal.II 仍有 1320 条假阳性（P3 评审自有结论），工具却没有每条规则的 precision/recall 数据

### 缺口 3：标准定位过高 + 编号悬空
- 单一团队文档无标准制定程序（意见征求/投票/维护），对标 ASTM E2107 / ASME NQA-1 / ISO 90003 差"测量规程/术语表/置信区间/参考数据集"
- 仓库不存在"标准 v1.0"，直接称"v2.0"编号悬空

## 四、采用门槛排序（真实工业团队视角）

> **假阳性控制 > 单分数不可行动 > 中文化 > 构建产物依赖 > Git 依赖**

| 排序 | 门槛 | 含义 | 后果 |
|---|---|---|---|
| 1 | 假阳性控制 | 阈值按 FOSS 校准，闭源代码库必触发大量误报；无"阈值校准+反馈闭环" | 一票否决，输出不可信 |
| 2 | 单分数不可行动 | 需模块级下钻（模块/规则/行号）、CI 独立评审任务（不阻塞 PR）、豁免审批流 | 落不到工程决策 |
| 3 | 中文化 | README/指南/Skill 全中文 | 挡住外部与外资团队 |
| 4 | 构建产物依赖 | 绑定检测靠 --build-dir，构建期生成绑定的项目需本地构建产物 | 仅影响无构建产物场景 |
| 5 | Git 依赖 | 演进质量依赖 Git 历史 | 最轻，现代项目基本满足 |
