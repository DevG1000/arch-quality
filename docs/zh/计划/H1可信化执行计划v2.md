## 四、工作包分解

### WP-0 基线实测（P0 前置，0.5 周）
- 性能基线：FreeCAD `src/` 全量（12417 文件）当前耗时实测；5 个回归项目各自耗时；声明机型/冷热缓存/分位数（P50/P90）
- 回归基线盘点：绝对路径清单、项目体积、快照依赖的工具版本
- 产出：`docs/zh/计划/H1基线实测报告.md`
- 验收：KPI 数据可复现、可作为 WP-3 对比基准

### WP-1 测试覆盖度升级（1.5 周）— 系统层
| 任务 | 文件 | 改动 |
|---|---|---|
| 评分算法 | `arch_metrics_standard.py` | `calc_testability()` → `calc_test_coverage()`；5 层评分（L1 目录 30% + L2 语言 25% + L3 文件比 25% + L4 绑定层 20%）；单语言 L4 重分配算法明确（按比例并入 L1-L3） |
| 权重键名 | `skills/arch-quality.md` | `"可测试性"` → `"测试覆盖度"`；`_resolve_weights` 双键兼容 |
| 报告同步 | `arch_report_generator.py` / `arch_report.py` | `testability` → `test_coverage`（含 `low_testability` 模板） |
| **全引用面同步** | `README.md`、`integrations/opencode/architecture-quality.md`、`docs/zh/架构质量标准指南.md`、`docs/zh/OpenCode 智能体开发指南.md`、harness 报告模板（共 8 文件） | 键名与术语统一 |
| **out-of-tree 配置** | `arch_core.py` / 新配置项 | 支持声明测试根目录（如 `tutorials/`、外置 tests 树），避免工业项目系统性低分 |
| 单元测试 | `tests/test_test_coverage.py` | 6 用例（无测试/全覆盖/部分语言/绑定层/out-of-tree/单语言重分配） |
| 回归更新 | `tests/regression/snapshots/*.json` | `ARCH_REGRESSION_UPDATE=1` 重生成 |

### WP-2 规则回归补全（1 周）— 系统层
- 合成项目：`tests/mutation/projects/` 下新建 3 个（MLR-002 缺绑定层、MLR-007 TNT 热点、MLR-009 通用类型绑定），内置构建配置与正/负例（`--build-dir` 依赖）
- 完整规则覆盖矩阵：12 MLR（含 001b/004b）+ 12 NVR + 11 MPR + 12 TPL 逐条标注（回归项目/合成项目/触发语义/断言），真实优先、合成兜底
- 矩阵存放位置：`docs/zh/计划/规则覆盖矩阵.md` + `arch_report_generator.py` 动态生成（JSON 可 diff）
- 验收：KPI1 达成（覆盖矩阵 100%）

### WP-3 性能优化（1 周）— 系统层
- profiler 先行：定位 FreeCAD 全量扫描热点（读盘 / 正则 / 图构建）
- `arch_core.py`：`_read_cached` 统一缓存 + `FileIndex` 增量扫描（`cache_file` 参数，适用"跑两遍"场景）
- 过滤策略：Fortran SyntaxWarning 抑制（DEBT-1）+ 生成文件（flex/bison/moc）、构建产物、嵌入式 third_party 统一过滤
- 对比：与 WP-0 基线逐项对比，P90 达标且 5 回归项目劣化 ≤20%
- 验收：KPI2 达成（FreeCAD 12417 文件 P90 < 10 分钟）

### WP-4 报告增强（0.5-1 周）— 系统层
- `arch_report_generator.py`：Markdown 展示 `test_coverage_detail`（4 层明细）
- MLR 覆盖矩阵表（12×5）**动态生成**（替代现硬编码 539-551 行），输出 JSON 供 diff
- 验收：报告含测试覆盖明细 + 覆盖矩阵，口径与 WP-2 对齐

### WP-5 门禁与 CI 工程化（1-1.5 周）— 系统层
- 回归工程可复现：相对路径 + 项目清单化定义（`projects.yaml`：名称/获取方式/校验和/评估配置）；第三方源码获取策略（镜像/裁剪/授权确认）
- `scripts/ci_gate_roadmap.bat`（Windows）+ `.github/workflows/arch-quality-ci.yml`（Linux 重写，非套用 bat）
- 门禁内容：pytest 单元 + 回归 + 一致性 + 快照校验 + 性能基线对比
- 治理：门禁升级准则（先自动记录 → 后阻塞）、失败回滚/豁免流程、owner 职责
- 验收：本仓库在干净环境（CI runner 模拟）一键通过

### WP-6 一致性检查器重构（0.5-1 周）— 能力层
- 从数值专用重构为通用框架：按 `src/arch_quality/skills/*.md` 目录发现，检查 指南/Skill/工具 三方一致（版本、公式、命名、权重）
- 规则编号校验接口预留（依赖 WP-7 阶段1 编码方案，先置 TODO）
- 纳入 WP-5 门禁（先自动后阻塞）
- 验收：5 个维度全 PASS

### WP-7 标准 v2.0 元模型（2 周，两阶段）— 内容层
**阶段 1（1 周，先于 validator）**：规则统一编码方案
- 命名空间方案（建议）：多语言 MLR-001~012 保留；模板 MLR-013~024 → TPL-001~012；数值 NVR、物理场 MPR 保留；补齐 NVR-009、MPR-011 空洞
- 重编号映射表 + 迁移顺序（含 `arch_report.py:263`、skill 豁免协调、验证案例库引用）
- 豁免字段建模修正：**可选字段，存在则必填**（多数规则无豁免机制）

**阶段 2（1 周）**：schema + validator + 注册表
- `docs/zh/标准体系元模型v2.0草案.md`（五元素：维度/规则/权重/豁免/验证资产）
- `standard_meta_model.schema.json` + `scripts/validate_meta_model.py`：权重和=100%、规则编号合法（按阶段1编码）、豁免字段校验
- 8 维度注册表（含 H2/H3 待补 4 个占位）
- 验收：KPI3 达成；validator 对现有 5 维通过

### WP-8 试点（2 周，并行）— 系统层
- 自举优先：本仓库自跑全量门禁（WP-5 产物）→ 1 个内部真实项目（BRL-CAD 已有 checkout；OpenFOAM 无 checkout，先不作为试点）
- 试点报告模板：成功标准、owner、成本记录（算力/时间）、问题清单、假阳性反馈、上线/回滚判据
- 产出：2 份周报 + 1 份试点总结
- 验收：KPI4 达成（门禁全绿 + 试点报告闭环）
