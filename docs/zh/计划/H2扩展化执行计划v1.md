## 一、目标与范围

**主目标**：标准体系覆盖 6/8 维度。补齐 2 项工业软件特有维度（④ 几何内核与科学数据结构一致性、⑧ 外部科学内核与几何内核的封装与防腐层），并按 P3 评审建议落地语义分析与报告标注，交付"新维度开发流程 v1"。

| 层 | 交付要点 | 验收 KPI |
|---|---|---|
| 产品层 | 两维引擎 (AI skill) 落地 + 显式 profile 实施 + 实例化意图推断 + 报告自动标注 | 6/8 维度覆盖；假阳性降 ≥50%；FreeCAD 级时间再降 ≥30% |
| 内容层 | 维度④ 与 ⑧ 四件套（指南 + Skill + 案例库 + 设计依据）+ 元模型 registry 更新 | 每维 12 条规则 + 回归基线 ≥3 项目 |
| 能力层 | 新维度交叉验证（k 折 + 动态-静态）+ 语料扩充（参考样本集首期）+ 开发流程 v1 | 新维度泛化 ≥7/9；流程文档 v1 发布 |

### 2.2 维度注册（H2 落地 8 维中的 ④ 与 ⑧）

|:---:|:-----|:--------|:-------|
| 4 | 几何内核与科学数据结构一致性 | **GCS** | 几何内核族（GCS-001~006）+ 科学数据结构族（GCS-007~012）|
| 8 | 外部科学内核与几何内核的封装与防腐层 | **ACL** | 外部内核封装防腐族（ACL-001~006）+ 外部标准封装族·数据交换（ACL-007~012）|

> 与 PPT H2 页的"新增维度①/②"对应：① = 注册表 #4，② = 注册表 #8。

### 2.3 规则草案（首版，待 skill-audit + 专家评审）

**GCS（维度④）**：几何内核族 — B-Rep 实体闭合性、Handle 智能指针一致性、欧拉公式约束、内核对象生命周期/所有权、拓扑/几何操作容差一致性、单位与坐标系一致性；科学数据结构族 — 网格单元类型一致性、场量组织一致性、网格/场量维度匹配、裸数组替代科学数据结构、数据复制/转换正确性、数据访问封装性。

**ACL（维度⑧）**：外部内核封装防腐族 — 直连内核 API、wrapper 完整性、内核版本兼容层、内核类型泄漏、错误处理封装、内核对象生命周期；外部标准封装族 — STEP/IGES/IFC 读写防腐、单位制换算一致性、公差换算一致性、标准版本兼容层、导入导出错误处理、格式直连检测。

## 三、工作包分解

### WP-0 显式 profile 实施（产品层，2 周）— 前置
- 依据 `显式Profile方案评估.md` §五：`arch-quality.yaml` 解析器 + schema 校验（arch_core.py）；`ComprehensiveReport` 引擎选择逻辑（profile 优先）；CLI `--profile` 参数；回归测试（各 profile 组合 + 配置缺失兜底）；指南 §2.6 说明。
- 与元模型激活子集归一化衔接（`权重归一化模型重做方案.md`）：profile 决定激活引擎集 → 激活维度子集。
- 验收：纯数值项目仅跑 standard+numerical；FreeCAD 级项目时间相对 H1 收尾 560s 再降 ≥30%。

### WP-1 维度④ 四件套（内容层，3 周）
- 产出：`docs/zh/几何内核与科学数据结构一致性评估/`（指南 + Skill + 案例库 + 设计依据）
- 12 条 GCS 规则细化（§2.3 草案）→ skill-audit 6 维审查 → 专家评审
- 案例库：开源 CAD/FEM 真实样本（OpenCASCADE、SALOME 参考）+ 合成正/负例

### WP-2 维度④ 引擎 + 回归（产品层，2 周）
- `arch_metrics_geometry_consistency.py`（GCS-001~012）+ 权重键名（skills/geometry-consistency.md）+ 报告同步 + 一致性检查器注册（consistency_check.py rule_prefix）
- 回归基线 ≥3 项目；`tests/test_geometry_consistency.py`
- 验收：GCS 12/12 有回归（真实优先、合成兜底）

### WP-3 维度⑧ 四件套（内容层，3 周）
- 产出：`docs/zh/外部科学内核与几何内核的封装与防腐层评估/`（指南 + Skill + 案例库 + 设计依据）
- 12 条 ACL 规则细化（含数据交换/互操作外部标准封装族，STEP/IGES/IFC/单位制/公差）→ skill-audit → 专家评审
- 案例库：wrapper 层真实样本（SWIG/pybind11 封装外部内核）+ 合成正/负例

### WP-4 维度⑧ 引擎 + 回归（产品层，2 周）
- `arch_metrics_anti_corruption.py`（ACL-001~012）+ 权重键名 + 报告同步 + 一致性检查器注册
- 回归基线 ≥3 项目；`tests/test_anti_corruption.py`
- 验收：ACL 12/12 有回归

### WP-5 语义分析：实例化意图推断（产品层，4 周）
- P3 评审建议 #1：模板引擎从语法扫描升级为"实例化意图推断"（识别模板被显式/隐式实例化的真实意图，过滤镀金模板误报）
- 验收：模板实例化假阳性率相对现状降 ≥50%（回归项目抽检）；回归评分劣化 ≤20%

### WP-6 报告自动标注 [third-party] / [test]（产品层，1 周）
- P3 评审建议 #2：`arch_report_generator.py` 对第三方/测试代码命中自动标注，避免污染主线架构评分
- 验收：自动标注生效，抽查准确（与手工标注一致率 ≥90%）

### WP-7 交叉验证 + 语料扩充（能力层，3 周）
- 新维度 k 折（LOOCV）+ 动态-静态交叉验证（复用 `cross_validate*.py` 框架）
- 语料扩充：参考样本集首期（每新维度 ≥5 健康 + ≥3 不健康样本），回填元模型 §5.2
- 验收：④⑧ 泛化 ≥7/9（对应 H1 solver-physics 的 7/9 基线）

### WP-8 新维度开发流程 v1 + 元模型更新（能力层/内容层，2 周）
- 用 WP-1~4 实测提炼"新维度开发流程 v1"（四件套 + skill-audit + 专家评审 + 回归 + 交叉验证五步闭环），与 `基于OPENCODE的架构质量评估SKILL开发指南.md` 对齐
- 元模型 registry：GCS/ACL 正式注册（8 维 → 满 8 维含规则族）；consistency_check KNOWN_HOLES 复核
- 验收：流程文档 v1 发布

### WP-9 试点与 closeout（工程闭环，2 周）
- 试点：新维度在 1 个大型 CAE 项目（FreeCAD/BRL-CAD 选一）+ 自举全量门禁
- closeout 报告（对齐 H1 格式）：KPI 达成证据 + 回归基线 + CI 记录 + 遗留项
- 验收：KPI1~6 全部有证据

## 六、风险与开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 几何内核/科学数据结构规则检测可行性不足 | 维度④ 延期 | skill-audit"可执行性"审查前置 + 合成项目先行验证 |
| 数据交换防腐检测需解析 STEP/IFC SDK 用法 | 维度⑧ 复杂度高 | 以 wrapper 形态检测为主（直连 SDK 引用/导入），标准语义解析降级为启发式 |
| 实例化意图推断技术难度高（假阳性降 50%）| WP-5 延期 | 先做规则子集（镀金模板 vs 实际使用），分阶段交付 |
| 双新维度 + 语义分析同周期并行 | 人力/评审过载 | 双维链并行但共享评审窗口；WP-5 独立窗口 |
| 新规则与现有引擎边界冲突 | 双重计分 | 边界裁决矩阵先行登记（④×⑧、⑧×①、④×NVR、⑧×可移植性占位）|
| profile 声明与元模型激活子集归一化未衔接 | 评分语义漂移 | WP-0 与 `权重归一化模型重做方案.md` 同步设计 |

**边界裁决登记（新增维度）**：
- ④ 几何内核 × ⑧ 外部内核：B-Rep 操作点先 ④ 后 ⑧（`维度完备性证明` §五）
- ⑧ 防腐层 × ① 多语言绑定：wrapper 源按主关切归属，先 ① 后 ⑧
- ④ 科学数据结构 × NVR 数值算法：数据组织归 ④，算法正确性归 NVR，不重复扣分
- ⑧ 外部标准封装 × 可移植性占位（H3）：数据交换防腐归 ⑧
