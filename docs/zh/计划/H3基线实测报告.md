## 二、Gate G0 — 运行时 CI 可行性结论（T0.6）

**背景**：决策 3 的 B2/B3/B5 需构建并运行 OCCT 内核。

**证据**

| 证据 | 值 | 来源 |
|:-----|:---|:-----|
| OCCT 源码规模 | 35,415 文件 / 191.3 MB（src 15,518 / 105.3 MB）| 本地实测 |
| 构建系统 | `CMakeLists.txt` 存在（CMake 3.10+）| 本地实测 |
| 样本 ref | **V8.0.1**（C++17）| `projects.yaml` / OCCT release |
| Ubuntu 24.04（ubuntu-latest）apt OCCT | **7.6.3**（noble）| packages.ubuntu.com |
| OCCT 8.0 源码构建 | ~15–30 min，~5 GB 磁盘 | 上游/第三方构建脚本 |
| 本地 cmake | 无（本地试构不可行）| 本地实测 |

**结论：条件可行（Conditional GO）**

- **方法 A（apt 7.6.3）不可用**：版本与样本 ref V8.0.1 不符 → B2/B3 运行时语义对不上静态基线，判定**不可采**。
- **方法 B（源码构建 V8.0.1）可行但重**：~15–30 min / ~5 GB，**不适合每 PR 主门禁**。
- **方法 C（预构建 artifact 缓存）**：可把 V8.0.1 构建产物缓存复用，使 B2/B3/B5 单次运行降到分钟级。
- **推荐落地**：**方法 C + 专用 job（nightly/scheduled）**，即回退矩阵的**选项 2**；主门禁不含内核构建，不阻塞 PR。

**G0 建议**：维持决策 3 实施 B2/B3/B5，但以"**预构建缓存 + 专用 job**"承载，**禁止用 apt 7.6.3**（版本漂移）。

**回退矩阵（若后续缓存方案不成立）**

| 选项 | 触发条件 | 影响 |
|:-----|:---------|:-----|
| ① 永久 KNOWN_HOLES | 无法稳定构建 V8.0.1 | B2/B3/B5 不实施，KNOWN_HOLES 文档化 |
| **② 专用 job（推荐）** | 缓存可建立 | 不阻塞 PR，夜间验证 |
| ③ 仅静态子集 | 运行时成本过高 | 保留 B4 静态近似，B2/B3/B5 不实施 |

**G0 决策落地（2026-10-21）**：已采用 **方法 C + 专用 job（选项 ②）**。基础设施：

| 文件 | 内容 |
|:-----|:-----|
| `.github/workflows/arch-quality-ci.yml` → `runtime-kernel` job | schedule（周一 03:00）+ `workflow_dispatch`，缓存 `.occt-cache/install`，不阻塞 PR |
| `scripts/ci/build_occt.sh` | 按 `OCCT_REF=b8f597c…`(V8.0.1) 构建 + 安装（幂等）|
| `scripts/ci/run_kernel_smoke.sh` + `kernel_smoke.cpp` | 内核探针（BRepPrimAPI_MakeBox + BRepCheck_Analyzer）|
| `docs/zh/计划/H3-G0运行时内核CI方案.md` | 方案 + B2/B3/B5 接入点 |

> 状态：基础设施已落地，**待一次 CI 运行验证**（本地无 cmake/Linux）。G0 = 条件可行，**决策 3 维持，暂不回退**。
