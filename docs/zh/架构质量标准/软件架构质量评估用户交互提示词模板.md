# 软件架构质量评估 — 用户交互提示词模板

> 文档编号：SA-C3-用户提示词
> 面向最终用户的 OpenCode 交互提示词模板，便于调用 `architecture-quality` 智能体进行软件架构质量评估。
> 关联：docs/zh/架构质量标准/软件架构质量评估指南（2.3版）.md

---

## 1. 完整评估

```
请对 [项目路径] 运行标准架构质量评估，
输出 4 维评分（结构/设计/文档/演进）和 SAR 规则违规详情。
```

**示例**：
```
请对 D:/opensource/FreeCAD/src 运行标准架构质量评估，
输出 4 维评分和 SAR 违规详情。
```

## 2. 单维度分析

```
请分析 [项目路径] 的结构质量，
重点检查模块化、耦合度、内聚度、复杂度和测试覆盖度（4 层）。
```

## 3. SAR 规则解读

```
请解释 SAR-00X（规则名）在 [项目路径] 中的具体情况，
说明触发条件、影响范围和建议修复方案。
```

**示例**：
```
请解释 SAR-004（高复杂度）在当前项目中的具体情况，
说明哪些文件导致复杂度过高，以及如何拆分。
```

## 4. 测试覆盖度分析

```
请分析 [项目路径] 的测试覆盖度，
输出 4 层明细（L1 目录覆盖 / L2 语言覆盖 / L3 文件比 / L4 绑定层覆盖），
并指出哪些关键模块缺少测试。
```

## 5. 改进建议

```
根据最近一次的评估结果，给出 [项目路径] 的架构改进建议，
按 P0/P1/P2 优先级分级，并预估每个建议的提分空间。
```

## 6. 与基线对比

```
请将 [项目路径] 的当前评估结果与回归基线对比，
输出评分偏移和 SAR 规则变化，判断是否出现退化。
```

## 7. 专项检查

```
请检查 [项目路径] 是否满足以下专项：
- 模块化健康（平均每目录文件数接近 5）
- SOLID 原则合规（无 God Class / Long Method）
- 文档完备（README/CHANGELOG/ADR）
- Git 活跃度与依赖状态健康
```

---

## 使用说明

- 所有提示词通过 `architecture-quality` 智能体执行（`opencode run --agent architecture-quality`）
- 项目路径支持本地目录或外部目录（需权限配置）
- 完整评估建议加 `--json` 或 `--md` 获取结构化/可读输出
- 评估命令：`python -m arch_quality.arch_report <项目路径> [--json] [--md]`
- 外部测试根目录：`python -m arch_quality <项目路径> --test-dirs tutorials`
