## 1. 数值不稳定检测（NVR-001）

### 1.1 阳性案例：OpenFOAM `rhoCentralFoam` CFL 条件违反

- **项目**：OpenFOAM（使用显式时间推进的 `rhoCentralFoam` 求解器）
- **问题描述**：`rhoCentralFoam` 是 OpenFOAM 中基于中心迎风格式的显式密度基求解器，其时间推进受 CFL（Courant-Friedrichs-Lewy）条件约束。当用户指定的时间步长超过 CFL 条件允许的最大值时，显式格式在特定网格和流速条件下违反 CFL 条件，产生非物理振荡和数值发散。典型表现：`rhoCentralFoam` 在处理激波时若 `Co` 数超过 0.5，仿真迅速发散。
- **检测方法**：
  1. 识别显式时间推进算法（通过静态分析检测时间推进模式）。
  2. 检查是否存在 CFL 条件检查或自适应时间步长机制（如 `adjustTimeStep` 设置）。
  3. 若缺失或配置不当，触发 NVR-001。
- **预期输出**：
  ```
  [NVR-001] 数值不稳定检测 (ERROR)
  模块: src/solvers/rhoCentralFoam/rhoCentralFoam.C
  算法类型: 显式时间推进（中心迎风格式）
  风险: 未检测到 CFL 条件检查或 Co 数控制机制
  建议: 引入 CFL 条件检查，设置 adaptiveTimeStep 或改用隐式时间推进格式。
  ```

### 1.2 阴性案例：隐式时间推进求解器（无告警）

- **项目**：OpenFOAM（隐式求解器如 `simpleFoam`、`pimpleFoam`）
- **描述**：使用隐式时间推进格式，无条件稳定，无需 CFL 条件检查。
- **预期输出**：无 NVR-001 告警。


## 2. 条件数超标检测（NVR-002）

### 2.1 阳性案例：CalculiX 病态矩阵

- **项目**：CalculiX（开源有限元软件）
- **问题描述**：CalculiX 在分析长宽比 1000:1 的薄板单元时，单元形状劣化导致刚度矩阵条件数超过 1e12。矩阵条件数达 1012 时，舍入误差被放大 1012 倍，计算结果完全失真。
- **复现条件**：使用 CalculiX 示例网格 `thin_plate.inp`（长度 1000mm，宽度 1mm，厚度 1mm），四边形单元长宽比约 1000:1。运行命令：`ccx thin_plate`。
- **检测方法**：
  1. 识别线性方程组求解模块（`ccx` 使用 `SPOOLES` 或 `PARDISO` 求解器）。
  2. 通过静态分析估计矩阵条件数，或记录运行时条件数计算输出。
  3. 若条件数 > 1e6，触发告警。
- **预期输出**：
  ```
  [NVR-002] 条件数超标检测 (ERROR)
  模块: src/calculix/ccx_2.20/src/SPOOLES/Solve.c
  条件数估计: 2.3e12 (阈值: 1e6)
  建议: 使用预处理技术（如对角线缩放）降低条件数，或改用 QR 分解等更稳定的求解器。
  ```

### 2.2 阴性案例：CalculiX 良态矩阵求解（无告警）

- **项目**：CalculiX（常规结构分析）
- **描述**：使用边长比 < 10:1 的六面体单元网格，矩阵条件数 < 1e3，求解稳定。
- **预期输出**：无 NVR-002 告警。


## 3. 灾难性抵消检测（NVR-003）

### 3.1 阳性案例：SU2 激波检测中的灾难性抵消风险

- **项目**：SU2（开源 CFD 求解器，v7.0+）
- **问题描述**：SU2 在 `CAdjFlowOutput.cpp` 中的激波检测模块，实现了 `computeSensor` 函数，该函数在计算激波传感器时存在潜在的灾难性抵消风险。代码中直接计算 `sqrt(velocity2)` 与 `sqrt(velocity2 - small)` 的差值，当 velocity2 与 small 相近时，有效位数大量损失。苏黎世联邦理工学院（ETH Zurich）研究人员已在 SU2 代码评审中识别此问题。
- **代码片段**（简化自 SU2 实际代码）：
  ```cpp
  // 危险代码：灾难性抵消风险
  su2double diff = sqrt(velocity2) - sqrt(velocity2 - small);
  ```
- **检测方法**：
  1. **静态分析作为初步筛选**：扫描浮点运算，识别 `a - b` 模式，其中 `a` 和 `b` 可能相近。
  2. **动态分析作为确认**：建议在 CI 中集成 Verrou 或 CADNA 进行运行时检测。
  3. 仅静态分析识别出的模式不直接触发告警，需动态分析确认后方可触发。
- **预期输出**：
  ```
  [NVR-003] 灾难性抵消检测 (ERROR)
  模块: src/output/CAdjFlowOutput.cpp:computeSensor
  模式: sqrt(velocity2) - sqrt(velocity2 - small)
  风险: 当 velocity2 与 small 相近时，有效位数大量损失
  建议: 使用数值稳定的等价公式 diff = small / (sqrt(velocity2) + sqrt(velocity2 - small))
  ```

### 3.2 阴性案例：SU2 数值稳定的距离计算（无告警）

- **描述**：SU2 在实现双曲正切函数描述（`tanh`）时，对非常小的 x 值直接返回 x，避免浮点开销；对较大 x 值使用 `expm1` 以防止 `exp(x) - exp(-x)` 中的抵消误差。
- **预期输出**：无 NVR-003 告警。


## 4. 浮点累加误差检测（NVR-004）

### 4.1 阳性案例：EDF code_aster 浮点累加误差

- **项目**：EDF（法国电力）code_aster（核工程仿真代码）
- **问题描述**：code_aster 在进行大规模数值积分和场量累加时，长时间运行的仿真因浮点累加误差累积导致精度退化。EDF R&D 系统性地开展数值验证工作，研究舍入误差传播对核设施仿真结果的影响。Verrou 工具由 EDF R&D 开发，用于检测 code_aster 等核工程代码的舍入误差。
- **代码片段**（仿真场景）：
  ```cpp
  // 危险代码：大量浮点累加未使用补偿算法
  for (int i = 0; i < num_elements; i++) {
      integral += element_contribution[i];
  }
  ```
- **检测方法**：
  1. 识别循环中的浮点累加操作（`sum += x` 模式）。
  2. 检查是否使用 Kahan 求和等补偿算法。
  3. 若未使用且累加次数 > 1000，触发告警。
- **预期输出**：
  ```
  [NVR-004] 浮点累加误差检测 (WARNING)
  模块: src/aster_integration/integrator.F90:120
  累加次数: 1,000,000 (阈值: 1000)
  补偿算法: 未检测到
  建议: 使用 Kahan 求和或分段累加以减少累积误差。
  ```

### 4.2 阴性案例：使用 Kahan 求和的累加（无告警）

- **描述**：使用 Kahan 补偿求和算法进行大量浮点累加。
- **预期输出**：无 NVR-004 告警。


## 5. MMS 验证缺失（NVR-005）

### 5.1 阳性案例：某开源 FEM 求解器缺乏 MMS 验证

- **项目**：某开源有限元求解器（基于 CalculiX 或 Elmer 的未验证定制分支）
- **问题描述**：数值算法模块未经制造解方法（MMS）进行代码验证。代码验证是确认软件是否正确求解底层数学方程的第一步。
- **检测方法**：
  1. 识别数值算法模块。
  2. 检查是否存在对应的 MMS 测试用例（须在 ≥3 套加密网格上执行）。
  3. 若缺失，触发告警。
- **预期输出**：
  ```
  [NVR-005] MMS 验证缺失 (ERROR)
  模块: src/solvers/custom_solver.C
  状态: 未检测到 MMS 测试用例
  建议: 为每个数值算法模块构造制造解，在至少三套加密网格上执行 MMS 验证，计算观测收敛阶。
  ```

### 5.2 阴性案例：ABAQUS MMS 验证（无告警）

- **项目**：ABAQUS/Standard（商业有限元软件）
- **描述**：ABAQUS 已通过 MMS 验证弹塑性固体力学问题，使用线性弹性、超弹性（neo-Hookean）和拟超弹性（Hencky）本构模型。研究发表于《Int J Numer Methods Eng》（2022），论文 ID: nme.7034。结果表明位移二阶收敛、应力一阶（或更高）收敛，源项使用 Python/SymPy 生成并实现。可用复现方式：从论文获取 MMS 测试脚本。
- **预期输出**：无 NVR-005 告警。


## 6. 观测收敛阶偏差过大（NVR-006）

### 6.1 阳性案例：SU2 边界条件处理导致的收敛阶偏差

- **项目**：SU2（开源 CFD 求解器）
- **问题描述**：SU2 的 `EulerSolver` 模块在无黏激波管问题中，MMS 验证显示观测收敛阶与理论二阶精度偏差超过 0.2。偏差来源于边界条件处理不当（激波捕捉中的数值耗散导致收敛阶降阶）。这一问题是 SU2 代码评审中已识别的标准缺陷。
- **检测方法**：
  1. 读取 MMS 测试结果中的观测收敛阶。
  2. 与理论阶数比较。
  3. 若偏差 > 0.2，触发告警。
- **预期输出**：
  ```
  [NVR-006] 观测收敛阶偏差过大 (ERROR)
  模块: src/solvers/EulerSolver.C
  理论收敛阶: 2.0
  观测收敛阶: 1.3 (偏差: 0.7)
  建议: 检查代码实现中的错误，重点关注边界条件处理和激波捕捉格式的实现。
  ```

### 6.2 阴性案例：ABAQUS MMS 验证通过（无告警）

- **项目**：ABAQUS/Standard
- **描述**：位移观测收敛阶为二阶，应力收敛阶为一阶或更高，与理论预期一致（《Int J Numer Methods Eng》，2022，nme.7034）。
- **预期输出**：无 NVR-006 告警。

### 6.3 阴性案例：SU2 MMS 验证通过（无告警）

## 8. 迭代误差未估计（NVR-008）

### 8.1 阳性案例：PETSc 迭代求解器缺乏收敛判据

- **项目**：PETSc（开源数值线性代数库）
- **问题描述**：PETSc 的某示例程序（如 `src/ksp/ksp/tutorials/ex2.c` 的早期版本）中使用共轭梯度法（CG）求解线性系统，但未设置合理的收敛判据（`-ksp_rtol` 和 `-ksp_atol`），或未在求解完成后报告最终残差。迭代误差未知。
- **复现条件**：运行 `./ex2 -ksp_type cg -pc_type none -ksp_monitor`，若不设置 `-ksp_rtol 1e-8`，求解器可能使用默认容差（1e-5），迭代误差未被精确估计。
- **检测方法**：
  1. 识别迭代求解器模块。
  2. 检查是否设置了收敛判据（如相对残差 < 1e-6）并报告最终残差。
  3. 若缺失，触发告警。
- **预期输出**：
  ```
  [NVR-008] 迭代误差未估计 (WARNING)
  模块: ex2.c (PETSc tutorial)
  状态: 未检测到收敛判据或残差报告
  建议: 设置合理的收敛判据（-ksp_rtol 1e-8），在求解完成后报告最终残差。
  ```

### 8.2 阴性案例：带收敛判据的 PETSc 求解器（无告警）

- **描述**：PETSc 求解器设置了 `-ksp_rtol 1e-8 -ksp_atol 1e-12`，并在求解完成后输出最终残差。
- **预期输出**：无 NVR-008 告警。


## 9. 数值回归测试缺失（NVR-010）

### 9.1 阳性案例：INL BISON 回归测试缺失

- **项目**：INL（爱达荷国家实验室）BISON 核燃料性能分析代码（早期版本）
- **问题描述**：关键数值模块缺乏自动化回归测试。BISON 将验证分为软件质量保证、代码验证和解验证三个层次。核工程等高后果领域要求代码修改后验证数值结果是否在可接受偏差范围内。
- **关键约束说明**：NVR-010 的回归测试要求**仅适用于已完成 NVR-005（MMS 验证）的模块**。对于尚未通过 MMS 验证的模块，其当前输出可能不正确，以错误输出为基准的回归测试无法验证修改是否引入新错误。因此，NVR-010 触发前应确认该模块已具备可靠的数值基准。
- **检测方法**：
  1. 识别所有触发 NVR-001、NVR-002 或 NVR-005 的模块，**且 NVR-005 已解决**。
  2. 检查 CI 流水线中是否存在对应的回归测试。
  3. 若缺失，触发告警。
- **预期输出**：
  ```
  [NVR-010] 数值回归测试缺失 (WARNING)
  模块: src/fuel_performance/thermal_solver.C
  关键模块判定: 触发 NVR-005 (MMS 验证缺失)
  状态: NVR-005 尚未解决，回归测试需先完成 MMS 验证
  建议: 首先通过 MMS 验证建立正确的数值基准，然后建立回归测试，对比修改前后的数值输出。
  ```

### 9.2 阴性案例：SU2 回归测试（无告警）

- **项目**：SU2（开源 CFD 求解器）
- **描述**：SU2 建立了完整的回归测试套件，在每次 PR 合并时自动运行。核心求解器（Euler、Navier-Stokes）的回归测试结果与基准解对比，偏差范围已定义。
- **预期输出**：无 NVR-010 告警。

## 13. 钝体绕流 V&V 研究（综合案例）

### 13.1 背景

- **项目**：ASME V&V 20 钝体（圆柱和方柱）绕流验证研究（Re ≈ 3900，基于 k-ω SST 湍流模型）
- **描述**：对 k-ω SST 湍流模型预测钝体绕流进行系统验证研究。

### 13.2 验证层面（对应 NVR-007）

- **数值不确定度量化**：使用 Richardson 外推和网格收敛指数（GCI），基于三套系统加密的网格进行量化。
- **预期评分计算**（对应指南2.4节）：
  - 离散化误差是否被估计：TRUE（使用 Richardson 外推，50 分）
  - 迭代误差是否被估计：TRUE（稳态求解器，残差 < 1e-8，50 分）
  - 解验证总分 = 50 + 50 = 100 分
- **预期输出**：无 NVR-007 告警。

### 13.3 确认层面（对应附录 A）

- **比较误差**：\(E = S - D\)，其中 \(S\) 为 CFD 预测的涡脱落频率，\(D\) 为实验测量值。
- **实验不确定度**：结合参考数据中报告的实验不确定度 \(u_D = 3\%\)。
- **数值不确定度**：\(u_{num} = 2.6\%\)（通过网格收敛性研究估计）
- **输入不确定度**：\(u_{input} = 3.5\%\)（来流速度不确定度）
- **确认不确定度**：\(u_{val} = \sqrt{2.6^2 + 3.5^2 + 3.0^2} \approx 5.3\%\)
- **关键发现**（特定条件：Re≈3900，k-ω SST 模型）：数值收敛不等于模型被确认。可接受的一致性仅限于尾流特定区域。阻力系数等积分量表现出网格收敛，但显著偏离经验相关性，表明模型形式误差占主导。
- **预期输出**：确认计划文档完整，六项检查要素全部通过。
