# 化石代码与技术债评估指南（0.2版）

> **版本**：0.2（阶段 B 专家校对修订；基于设计依据 v0.3）
> **日期**：2026-11-05
> **状态**：阶段 B 专家校对通过（P0=0；P1×7 已闭合）；待阶段 C 校准
> **适用范围**：含 F77/固定格式 Fortran、废弃 C++ API、K&R C、死代码、克隆、长期技术债的工业软件
> **依据**：`化石代码与技术债评估设计依据.md` v0.3、`H3-WP4实施方案.md`、《AI 架构评估文档编制指南 1.8》

## 概述

### 评估目标

本指南定义**化石代码与技术债**评估维度（注册表维度⑦，引擎前缀 **FOS**）。评估对象是长生命周期工业软件代码库，衡量其“时代特定形态 + 技术债”的健康度：

1. **历史遗留 API 与语言方言**：F77 固定格式/`COMMON`/`IMPLICIT`、`auto_ptr`/`register`/`throw(type)`、K&R C。
2. **死代码与不可达逻辑**：未引用符号/文件、`#if 0`、`return` 后语句、恒假条件、成块注释代码。
3. **重复代码与重复实现**：函数/文件级克隆、跨文件重复常量、同一算法多份实现。
4. **技术债密度与可维护性**：`TODO/FIXME/HACK/XXX` 密度、SQALE 修复成本代理、遗留模块无测试。

本维度**不评估**：单线程算法数值正确性（归 NVR③）、物理场模块化结构（归 MPR⑤）、多语言绑定（归 MLR①）、几何内核数据一致性（归 GCS④）、并行/异构执行面（归 HPC⑥）、外部内核防腐（归 ACL⑧）。

### 适用范围

- **适用**：满足 `is_fossil=True` 的代码库（见 §八），包括 F77/固定格式 Fortran、废弃 C++ API、K&R C、死代码/克隆、债务密度超阈值。
- **不适用**：无任何化石信号且 TODO 密度 ≤5/KLOC 的现代代码库；`is_fossil=False`，引擎返回 `None`，不参与总分。

### 术语约定

| 术语 | 含义 |
|:--|:--|
| **化石形态** | 因语言/API/工具链时代变迁而沉淀的、显著抬高升级或维护成本的代码形态 |
| **形态出现点** | 具体 `文件:行`（如 `auto_ptr`、`COMMON`、克隆块），是清单/工单的基本对象 |
| **基础层** | 历史遗留 API、死代码；升级阻塞/可删性，**不折半** |
| **增强层** | 克隆、技术债；影响理解与偿还顺序 |
| **candidate** | 候选结论，需人工/LLM 复核，不直接 ERROR |
| **confirmed** | 已确认结论；高置信规则直接命中或人工确认 |
| **KNOWN_HOLE** | 已知检测盲区，明确不评分（FOS-013/014） |
| **遗留模块** | 年龄 >5 年（git 首次提交）且无任何测试的模块 |

### 行业标准映射

| 标准/方法 | 对应关切 | 说明 |
|:--|:--|:--|
| ISO/IEC 25010:2011 可维护性/可移植性 | 可分析、可修改、可测试、可移植 | 本指南沿用 2011 术语；2023 版将 Portability→Flexibility、Testability 移入 Flexibility |
| ISO/IEC 5055:2021（CISQ） | 可维护性/可靠性自动化度量 | 结构规则为主，不识别 F77/`auto_ptr`/克隆 |
| SQALE（方法/工具） | 技术债修复成本 | 用于 FOS-011 成本代理，不是 ISO 标准 |
| CK（Chidamber & Kemerer 1994） | OO 结构度量 | 不覆盖时代形态 |
| Cunningham 1992 / Fowler 1999/2018 | 技术债 / 代码坏味道 | 理论基础，不是检测标准 |

## 置信度说明

本指南对每条规则标注**四级置信度**：

| 置信度 | 含义 | 检测方式 | 使用建议 |
|:--:|:--|:--|:--|
| **高** | 符号/结构精确匹配，误报低 | 关键字/扩展名/列规则/符号匹配 | 可作 CI 阻断（校准后） |
| **中** | 结构/作用域/计数分析，边界需关注 | 引用图、`#if 0`、密度计数 | WARNING，人工抽检 |
| **中低** | 启发式推断，需人工复核 | 克隆哈希、成本代理、年龄推断 | 默认 INFO/WARNING，需复核 |
| **低** | 弱信号，仅提示 | 命名/模式偏好 | 仅 INFO，不阻断 |

**硬约束**：

1. 语义级/启发式检测**不得标“高”**；
2. 低置信度规则**不得设 ERROR**；
3. 同一规则在规则表、§七、附录 B 的置信度必须一致；
4. LLM/人工确认只把 candidate 提升为“候选(已确认)”，不改变确定性评分。

## 一、子维度与权重分配

| 子维度 | 权重 | 覆盖规则 | 置信度 | 对应风险 |
|:--|:-:|:--|:--:|:--|
| 历史遗留 API 与语言方言 | **30%** | FOS-001~003 | 高/中 | 编译器升级阻塞、ABI/跨平台失效 |
| 死代码与不可达逻辑 | **20%** | FOS-004~006 | 中/中低 | 理解成本、误改风险、无效维护 |
| 重复代码与重复实现 | **20%** | FOS-007~009 | 中低 | 修复遗漏、行为不一致 |
| 技术债密度与可维护性 | **30%** | FOS-010~012 | 中/中低 | 债务累积、预算失控、无测试保护 |

**权重设计依据**：

- **升级阻塞优先**：历史遗留 API（30%）直接决定“能不能升编译器/标准”，是长生命周期软件的第一道门槛。
- **债务成本并列**：技术债密度（30%）决定“先改谁、要多少钱”，与升级阻塞同为决策核心。
- **死代码/克隆各 20%**：重要但相对独立；死代码偏“可删性”，克隆偏“一致性”，不压过前两项。
- **基础层/增强层不折半**：避免“基础形态被增强层平均掉”；与 HPC 的“增强层不折半”一致。

> **子维适用性**：`is_fossil=True` 时 **4 个子维全部适用**，不做子维剔除/重新归一化。某子维无命中时得 100 分（“没有该类化石”是好事），不记 N/A。

> **豁免对评分的影响**：`@fossil_legacy_ok` 与 `@fossil_not_dead` **影响 scoring（不计数）**；`@fossil_deferred` 仅降级 `output_level`（详见 §九）。

## 二、子维度定义与评分算法

### 2.1 历史遗留 API 与语言方言（30%）

**定义**：评估代码是否仍使用已被标准移除/弃用的语言特性或 API，以及是否停留在固定格式/隐式类型等旧方言，衡量编译器/标准升级的阻塞程度。

**置信度**：高（FOS-001/002）/ 中（FOS-003）

**设计依据**：

- **ISO/IEC 25010:2011 可维护性/可移植性**：可分析、可修改、可移植。
- **C++ 标准**：`auto_ptr`/`register`/`bind1st`/`random_shuffle` C++17 移除；`throw(type)` C++17 移除、`throw()` 为 `noexcept(true)` 弃用别名（至 C++20）；`result_of` C++20 移除。
- **Fortran 标准**：F77 固定格式/`COMMON`/`IMPLICIT` 在现代化编译器中仍可编译，但限制模块化、接口检查与跨平台。
- **案例**：Code_Aster `IMPLICIT REAL*8`、BRL-CAD `register int i;`。

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|:--|:--|:-:|:--:|
| FOS-001：F77 固定格式/`COMMON`/`IMPLICIT`/`EQUIVALENCE` | 扩展名 + 1–6 列 + `-ffixed-form` + 关键字 | 40 | 高 |
| FOS-002：废弃 C++ API（`auto_ptr`/`register`/`throw(type)`/`strstream`/`bind1st`，`register` 仅 C++）| 剥离注释/字符串后关键字/符号匹配 | 40 | 高 |
| FOS-003：K&R C/非标准方言（隐式 `int`、旧式函数定义、GNU 扩展；含 C 的 `register`）| 函数定义形态 + 编译选项 + 扩展关键字 | 20 | 中 |

```
历史遗留得分 = max(0, 100 - Σ(命中的 FOS-001~003 赋分))   # 每规则命中一次扣一次
```

**算例**：

- 正例（触发）：Code_Aster `astest/umat001a.f:87` `IMPLICIT REAL*8 (A-H,O-Z)`，固定格式 → FOS-001 命中，扣 40。
- 负例（不触发）：Fortran 90 `module` + `implicit none` + `allocatable`；C++17 `std::unique_ptr` + `noexcept`。

**代码坏味道：时代方言残留（Era Dialect Residue）**

- **描述**：代码停留在 F77/固定格式/隐式类型，或使用已移除 API；能编译但升级即断。
- **典型表现**：`COMMON` 共享状态、`IMPLICIT REAL*8`、`auto_ptr` 转移所有权、`register` 修饰局部变量。
- **危害**：编译器升级阻塞、ABI 不兼容、跨平台失败、理解成本高。

### 2.2 死代码与不可达逻辑（20%）

**定义**：评估未被引用/不可达/被注释掉的代码，衡量可删除性与理解成本。

**置信度**：中（FOS-005）/ 中低（FOS-004/006）

**设计依据**：

- **引用图/符号表**：未引用函数/变量/文件是“可删性”的直接信号。
- **控制流**：`#if 0`、`return` 后语句、恒假条件是静态可判的不可达形态。
- **D1 边界**：FOS-006 计所有成块注释；标准 `calc_dead_code` 只保留备份文件（见 §六）。

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|:--|:--|:-:|:--:|
| FOS-004：未引用函数/变量/文件 | 符号引用图 + 入口点/FFI/插件白名单 | 50 | 中低 |
| FOS-005：不可达分支（`#if 0`/`return` 后/恒假）| 预处理块 + 控制流基本块 | 30 | 中 |
| FOS-006：成块注释代码 | 连续注释行 ≥3 行；>10 行 WARNING、≤10 行 INFO；两者均计 20 | 20 | 中低 |

```
死代码得分 = max(0, 100 - Σ(命中的 FOS-004~006 赋分))
```

**算例**：

- 正例（触发）：`#if 0 ... #endif` 包裹 5 行旧实现；未被调用的 `legacy_init()`；12 行 `//` 注释块。
- 负例（不触发）：`main`/导出符号/FFI 注册函数；可达的 `if (mode)` 分支；无注释代码块。

**代码坏味道：僵尸代码（Zombie Code）**

- **描述**：代码已无调用方/不可达/被注释，但仍留在仓库中。
- **典型表现**：`#if 0` 旧实现、`return` 后语句、未引用 `static` 函数、大段注释代码。
- **危害**：误导维护者、增加搜索/理解成本、误改风险。

### 2.3 重复代码与重复实现（20%）

**定义**：评估函数/文件级克隆、跨文件重复常量、同一算法多份实现，衡量一致性与修复遗漏风险。

**置信度**：中低（FOS-007/008/009）

**设计依据**：

- **克隆检测**：token 哈希/winnowing/SimHash 识别 Type-1/2/3 克隆。
- **重复常量**：同一常量在 ≥2 文件/≥3 处重复，修改时易漏。
- **D2 边界**：标准 `hardcode` 只抓 IP/密钥；FOS-008 只管跨文件常量，排除 IP/密钥/URL（见 §六）。

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|:--|:--|:-:|:--:|
| FOS-007：函数/文件级克隆 | token 哈希/winnowing，相似度 ≥0.80；同克隆对优先于 FOS-009 | 50 | 中低 |
| FOS-008：跨文件重复常量/魔法数 | 常量表，≥2 文件且 ≥3 处；排除 IP/密钥/URL | 20 | 中低 |
| FOS-009：同一算法多份实现 | 函数名/签名/调用图 + 语义近似 | 30 | 中低 |

```
重复得分 = max(0, 100 - Σ(命中的 FOS-007~009 赋分))
```

**算例**：

- 正例（触发）：两个文件各有一份相同的 `compute_flux()`；`0.85` 在 3 个文件重复；同一 RK4 在两处各写一遍。
- 负例（不触发）：公共工具函数被复用；常量集中在一个 `constants.h`；模板/泛型一份实现。

**代码坏味道：复制粘贴演化（Copy-Paste Evolution）**

- **描述**：同一逻辑被复制多份，后续只改一份，行为分叉。
- **典型表现**：函数级克隆、跨文件常量复制、同一算法多实现。
- **危害**：修复遗漏、行为不一致、测试成本翻倍。

### 2.4 技术债密度与可维护性（30%）

**定义**：评估债务标记密度、修复成本代理、遗留模块无测试，衡量债务规模与偿还优先级。

**置信度**：中（FOS-010）/ 中低（FOS-011/012）

**设计依据**：

- **Cunningham 1992**：技术债是“现在偷懒、未来付息”。
- **SQALE（方法/工具）**：规则违反映射修复成本；FOS-011 用代理比率，不是真实工时。
- **D3 边界**：FOS-012 只计“零测试且年龄 >5 年”的遗留模块；标准 `test_coverage` 对命中模块豁免（见 §六）。

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|:--|:--|:-:|:--:|
| FOS-010：`TODO/FIXME/HACK/XXX` 密度 | 计数/KLOC，阈值 >5/KLOC | 25 | 中 |
| FOS-011：SQALE 修复成本比率 | 结构性化石违规 × 代理成本 / 规模；排除 FOS-010 债务标记 | 50 | 中低 |
| FOS-012：遗留模块无测试 | git 年龄 >5 年 + 无测试文件/断言 | 25 | 中低 |

```
技术债得分 = max(0, 100 - Σ(命中的 FOS-010~012 赋分))
```

**算例**：

- 正例（触发）：`src/legacy/` 10 年未改、无测试；`TODO` 密度 8/KLOC；SQALE 比率 12%。
- 负例（不触发）：模块有单元测试/回归用例；TODO 密度 1/KLOC；SQALE 比率 2%。

**代码坏味道：债务沉淀（Debt Sedimentation）**

- **描述**：TODO/FIXME 长期不还，遗留模块无测试，修复成本逐年上升。
- **典型表现**：`TODO` 成片、`HACK` 绕过、老模块零测试。
- **危害**：预算失控、改动不敢动、现代化排期不可信。

## 三、综合分

```
若 is_fossil == False：overall = None（维度不适用）
若 is_fossil == True：
  子维得分_i = max(0, 100 - Σ(该子维命中规则的赋分))
  overall = Σ_{i=1..4} 子维得分_i × 权重_i
  权重 = [0.30, 0.20, 0.20, 0.30]，Σ=1
```

**算例**：

- 仅 FOS-001（40）+ FOS-002（40）命中：
  - 历史遗留 = 100−80 = 20；
  - 其余子维 = 100；
  - overall = 20×0.30 + 100×0.20 + 100×0.20 + 100×0.30 = **76**；
  - FOS-001 为 HIGH 且已确认 → 等级封顶“需改进”（即使 76 属“良好”）。
- FOS-001+002+003 全命中：历史遗留 = 0；overall = **70**；封顶“需改进”。
- 12 条全命中：overall = **0**。

**规则命中口径**：

- 同一规则在一个项目内**只扣一次赋分**（不按出现次数累加）；出现次数写入明细，用于排序/工单拆分。
- 子维得分下限 0，不出现负分。
- 未命中的规则不扣分；子维无命中 = 100。

**规则互斥（防同形态双扣）**：

- 同一符号同时命中 FOS-004（未引用）与 FOS-005（不可达）→ **只扣 FOS-004（50）**，FOS-005 记 INFO 不重复扣；
- 同一克隆对同时命中 FOS-007（克隆）与 FOS-009（同一算法多实现）→ **只扣 FOS-007（50）**，FOS-009 记 INFO 不重复扣；
- FOS-011（SQALE 成本代理）**排除 FOS-010 已计的债务标记**，只计结构性化石形态；
- FOS-002 的 `register` **仅 C++**；C 的 `register` 归 FOS-003（K&R C），避免同一关键字双扣。

**规模输出**：

- 评分为**存在性口径**（规则命中一次扣一次赋分）；
- 报告必须同时输出**命中次数/密度**（如 FOS-001 文件数、FOS-010 每 KLOC、FOS-012 模块数），避免“1 处=40 分”掩盖规模；
- 阶段 C 评估是否按密度缩放（默认不缩放，保持跨项目可比）。

**顶层融合**：

- `dim.fossil` 候选权重 0.15（`project` scope）；按激活子集全局归一化并入总分（与 H2 决策一致）。
- 报告输出 `dimensions.fossil`，并在 `structural.fossil_enhancement` 提供别名。
- 报告须输出 `is_fossil` 与 `score_scope=project`；`is_fossil=False` 时维度键为 `None`，不参与归一化。

**可比性**：

- 仅 `is_fossil=True` 的项目之间可比较；`is_fossil=False` 不参与排名。
- 不同 `applicability_set` 不存在（4 子维全适用）；但**不同语言构成**（纯 Fortran vs C++）的分数语义不同，跨项目对比须分组。

## 四、分数分级

| 综合分区间 | 等级 | 说明 | 建议动作 |
|:--:|:--|:--|:--|
| ≥ 85 | 优秀 | 化石形态少/可控 | 保持，纳入回归 |
| 70 ≤ x < 85 | 良好 | 有少量化石形态 | 按 Top 问题整改 |
| 50 ≤ x < 70 | 需改进 | 存在升级阻塞或债务累积 | 优先 FOS-001/002/011 |
| < 50 | 差 | 严重化石/债务 | 阻断级修复后再上线 |

**等级封顶与门禁状态**：

1. **等级封顶（仅对已确认违规）**：
   - 任一**已确认**的 **ERROR** 或 **HIGH** 级违规 → 等级**封顶“需改进”**；
   - 封顶取较低等级，不抬升；
   - 候选/中低置信默认不计入封顶，需人工确认。
2. **“已确认”定义**：
   - 高置信规则（FOS-001/002）直接命中；
   - 人工复核确认的候选；
   - **LLM/自动复核的 confirm 仅属候选级证据**，不单独构成“已确认”，除非人工采纳。
3. **门禁状态与分数分离**：

| 门禁状态 | 判定 | 行为 |
|:--|:--|:--|
| **BLOCK** | 存在**已确认**的 ERROR 级违规 | 阻断 PR |
| **WARN** | 存在 HIGH/MEDIUM | 提示，不阻断 |
| **PASS** | 仅 LOW/INFO 或无 | 通过 |

> **首期策略**：FOS-001~012 首期以 WARNING/INFO 输出；FOS-001 虽 severity=HIGH，但 output_level=WARNING，**HIGH 封顶仍生效**；校准误报率后再决定是否升 ERROR。

**展示规则**：数值分保持原值，等级取封顶后结果，写作“分数 X（等级受封顶：需改进）”；门禁状态单独呈现。

### 规则详细描述

#### FOS-001：F77 固定格式/`COMMON`/`IMPLICIT`

- **严重级别**：HIGH ｜ **检测置信度**：高 ｜ **赋分**：40
- **描述**：检测固定格式 Fortran、`COMMON`、`IMPLICIT`、`EQUIVALENCE` 等旧方言。
- **检测逻辑**：
  1. 扩展名 `.f/.f77/.for`；
  2. 第 1–6 列标签/续行，第 7 列起代码；或编译选项 `-ffixed-form`；
  3. 关键字 `COMMON`/`IMPLICIT`/`EQUIVALENCE`/`DIMENSION`。
- **边界**：`.f` 可能按自由格式编译，须结合列规则/编译选项；third_party/生成代码排除。
- **建议修复**：迁移 `MODULE` + `IMPLICIT NONE` + `allocatable`；`COMMON` 改派生类型/模块变量。

#### FOS-002：废弃 C++ API

- **严重级别**：MEDIUM ｜ **检测置信度**：高 ｜ **赋分**：40
- **描述**：检测 `auto_ptr`/`register`/`throw(type)`/`strstream`/`bind1st` 等已移除/弃用 API。
- **检测逻辑**：
  1. 剥离注释/字符串；
  2. 关键字/符号精确匹配；
  3. 区分 `throw(type)`（移除）与 `throw()`（弃用别名）；
  4. `register` 仅 C++；C 的 `register` 归 FOS-003。
- **边界**：`register` 作为普通词/注释不算；`auto_ptr` 在注释/文档不算。
- **建议修复**：`unique_ptr`、去 `register`、`noexcept`、`stringstream`、lambda/`bind_front`。

#### FOS-003：K&R C/非标准方言

- **严重级别**：MEDIUM ｜ **检测置信度**：中 ｜ **赋分**：20
- **描述**：检测旧式函数定义、隐式 `int`、GNU 扩展等非标准方言。
- **检测逻辑**：
  1. 函数头参数表与声明分离（K&R 形态）；
  2. 无返回类型/隐式 `int`；
  3. `__attribute__`/`typeof` 等非标准扩展（按编译标准）。
- **边界**：明确使用 GNU 扩展且编译器固定的项目可 `@fossil_deferred` 降级；不自动判死。
- **建议修复**：ANSI C/C99+ 原型、显式类型、标准替代。

#### FOS-004：未引用函数/变量/文件

- **严重级别**：MEDIUM ｜ **检测置信度**：中低 ｜ **赋分**：50
- **描述**：检测无调用方/无引用的符号与文件。
- **检测逻辑**：
  1. ctags/符号表 + 引用图；
  2. 排除入口点、导出符号、FFI/插件注册、反射/动态加载；
  3. 无引用 → 候选（WARNING）。
- **边界**：跨语言/动态调用静态不可判，列 FOS-013；`@fossil_not_dead` 可豁免。
- **建议修复**：删除或标注 `@fossil_not_dead`；先加回归再删。

#### FOS-005：不可达分支

- **严重级别**：MEDIUM ｜ **检测置信度**：中 ｜ **赋分**：30
- **描述**：检测 `#if 0`、`return` 后语句、恒假条件等不可达逻辑。
- **检测逻辑**：
  1. 预处理块 `#if 0`，或 `#if 1 ... #else` 的 `#else` 死分支；
  2. `return`/`break`/`continue` 后同块语句；
  3. 编译期常量恒假（`if (false)`/`if (0)`）。
- **边界**：平台条件编译（`#ifdef`）不算；模板/宏展开需 AST 或保守跳过。
- **建议修复**：删除死分支；保留必要平台分支并加注释。

#### FOS-006：成块注释代码

- **严重级别**：LOW ｜ **检测置信度**：中低 ｜ **赋分**：20
- **描述**：检测被注释掉的代码块（不是文档注释）；>10 行 WARNING、≤10 行 INFO，二者均计 20 分。
- **检测逻辑**：
  1. 连续注释行 ≥3 行；
  2. 含代码特征（`if/for/return/=`/函数调用）；
  3. >10 行 WARNING；≤10 行 INFO。
- **边界**：D1 已定：FOS-006 计所有成块注释；标准 `calc_dead_code` 只保留备份文件（§六）。
- **建议修复**：删除；需要保留则移入文档/示例。

#### FOS-007：函数/文件级克隆

- **严重级别**：MEDIUM ｜ **检测置信度**：中低 ｜ **赋分**：50
- **描述**：检测 Type-1/2/3 克隆（函数/文件级）。
- **检测逻辑**：
  1. token 化 + 哈希/winnowing；
  2. 相似度 ≥0.80（默认，阶段 C 校准）；
  3. 排除生成代码/模板/third_party。
- **边界**：语义级克隆（不同写法）列 FOS-014；宏/模板实例化需去重。
- **建议修复**：抽取公共函数/模板；加参数化。

#### FOS-008：跨文件重复常量

- **严重级别**：LOW ｜ **检测置信度**：中低 ｜ **赋分**：20
- **描述**：检测跨文件重复的数字/字符串常量。
- **检测逻辑**：
  1. 常量表（数字/字符串）；
  2. ≥2 文件且 ≥3 处；
  3. 排除 IP/密钥/URL/日志文案。
- **边界**：D2 已定：标准 `hardcode` 只抓 IP/密钥；FOS-008 只管跨文件常量；单文件数字魔法数是已知空白（不假装覆盖）。
- **建议修复**：集中到 `constants.h`/配置；命名常量。

#### FOS-009：同一算法多份实现

- **严重级别**：MEDIUM ｜ **检测置信度**：中低 ｜ **赋分**：30
- **描述**：检测同一算法（如 RK4、插值、通量）多份实现。
- **检测逻辑**：
  1. 函数名/签名/调用图相似；
  2. 关键步骤/常量序列比对；
  3. 语义近似 → 候选。
- **边界**：不同精度/后端/性能特化的实现不算；语义级归 FOS-014。
- **建议修复**：统一实现 + 特化接口；加对照测试。

#### FOS-010：债务标记密度

- **严重级别**：LOW ｜ **检测置信度**：中 ｜ **赋分**：25
- **描述**：检测 `TODO/FIXME/HACK/XXX` 密度。
- **检测逻辑**：
  1. 计数（排除文档/测试/示例中的 TODO；字符串字面量不计）；
  2. 密度 = 数量 / KLOC；
  3. >5/KLOC → INFO；同时作为 `is_fossil` 条件之一。
- **边界**：文档/测试中的 TODO 不计；`HACK` 需结合上下文。
- **建议修复**：转工单、定 owner/期限；清理过期 TODO。

#### FOS-011：SQALE 修复成本比率

- **严重级别**：MEDIUM ｜ **检测置信度**：中低 ｜ **赋分**：50
- **描述**：用 SQALE 方法估算化石形态的修复成本比率。
- **检测逻辑**：
  1. 结构性化石违规映射代理成本（按形态/规模，排除 FOS-010 债务标记）；
  2. 比率 = 估算成本 / 总规模（h/KLOC）；
  3. >8h/KLOC（默认，阶段 C 校准）→ 候选（WARNING）。
- **边界**：无真实工时基准，属代理；不单独触发 ERROR。
- **建议修复**：按成本排序，先修高比率模块。

#### FOS-012：遗留模块无测试

- **严重级别**：MEDIUM ｜ **检测置信度**：中低 ｜ **赋分**：25
- **描述**：检测年龄 >5 年且零测试的遗留模块。
- **检测逻辑**：
  1. git 首次提交 >5 年；
  2. 模块无测试文件/断言；
  3. 输出 `legacy_untested_modules`。
- **边界**：D3 已定：标准 `test_coverage` 对命中模块豁免重复扣分；无 git 的项目不计年龄。
- **建议修复**：补回归/特征测试；先加“金标准”输出比对。

## 九、豁免注解体系

### 9.1 为什么需要豁免

以下场景规则前提不成立，不豁免会产生虚假告警：

1. **ABI/兼容性保留**：必须保留旧 API/`COMMON` 以兼容插件/二进制接口（FOS-001/002/003）。
2. **已排期债务**：历史代码暂不整改，需登记而非阻断（全规则）。
3. **动态引用**：FFI/插件/反射调用，静态引用图看不到（FOS-004）。

### 9.2 注解类型

| 注解 | 用途 | 作用域 | 对 scoring 的影响 |
|:--|:--|:--|:--|
| `@fossil_legacy_ok` | ABI/兼容性保留旧 API | FOS-001/002/003 | **不计数**（影响评分） |
| `@fossil_deferred` | 已排期债务 | 全规则 | 仅降 `output_level`（HIGH→WARNING，MEDIUM→INFO） |
| `@fossil_not_dead` | 动态引用/FFI/插件 | FOS-004 | **不计数**（影响评分） |

**格式**：文件头 `/* @fossil_legacy_ok: reason */`；**reason 必填**，缺 reason 无效。

### 9.3 验证规则

- 作用域**同文件**，不跨文件传播；
- 引擎在**剥离注释之前**采集注解；
- 一条规则多注解取最宽松（legacy_ok/not_dead > deferred）；
- `waiver_audit` 记录无效/滥用。

### 9.4 反滥用守卫

| 守卫项 | 阈值 | 行为 |
|:--|:--|:--|
| 豁免文件占比（三通道合计） | **>30%** | `abuse_warning`，提示覆盖度可能失真 |
| 通道分离 | — | `@fossil_legacy_ok` 仅 FOS-001/002/003；`@fossil_not_dead` 仅 FOS-004 |
| 不提供“静音全部规则” | — | 禁止 |

### 9.5 门禁关系

- `@fossil_legacy_ok`/`@fossil_not_dead` 不计数 → 可降低分数扣减，但**不改变已确认 ERROR/HIGH 的封顶**（若同项目另有未豁免 HIGH）；
- `@fossil_deferred` 降级后不进入 BLOCK；
- **不存在通过豁免绕过 ERROR/HIGH 封顶的路径**；滥用由 30% 上限告警暴露。
