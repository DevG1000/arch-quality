# 模板元编程与编译时依赖膨胀验证案例库（4.1版）

本案例库作为《模板元编程与编译时依赖膨胀评估指南（4.1版）》的配套验证基准，已根据指南4.0版的新增内容（第八章：基线校准统计方法、豁免性能自动化验证方案）进行同步更新。

**4.0 版主要变更**：
- 新增“基线校准验证”章节，覆盖采样、统计计算、阈值设定的自动化验证。
- 新增“豁免性能自动化验证”章节，覆盖 CI 自动性能测试、豁免注释格式校验、验证通过/失败场景。
- 新增“跨规则豁免协调”验证用例（MLR-014 与 MLR-017 同时豁免）。
- 统一所有规则输出级别（ERROR/WARNING/INFO），并在案例中明确标注。
- 更新阳性/阴性/需审查分类，与指南4.0版完全对齐。

- **预期输出**：无告警。

## 2. 模板实例化重复率（MLR-014 + MLR-019）

### 2.1 阳性案例（无豁免）：Eigen `Matrix<double,3,3>` 重复实例化

- **描述**：47 个 `.cpp` 各自实例化，未使用 `extern template`。
- **预期输出级别**：WARNING (MLR-014), INFO (MLR-019)
- **预期输出**：

```text
[MLR-014] 模板重复实例化 (WARNING)
特化: Eigen::Matrix<double,3,3>
实例化次数: 47 → 重复率 97.9%
建议: 在头文件中添加 "extern template class ..."。

[MLR-019] 未使用 extern template 优化 (INFO)
```

### 2.2 需审查案例（豁免适用）：OpenFOAM `Tensor` 多精度实例化

- **描述**：`Tensor<scalar>` 与 `Tensor<vector>` 并存，多精度场景。
- **预期输出级别**：INFO（需审查）
- **预期输出**：

```text
[MLR-014] 模板重复实例化 (INFO - 需审查)
特化: Tensor<scalar>, Tensor<vector>
说明: 检测到多精度/多维度模板实例化。若各特化对应不同算法优化路径（如 SIMD），可在模板定义处添加
      // @template_specialization_required: multi-precision
      以豁免检查。否则建议使用 extern template 集中实例化。
```

### 2.3 阴性案例：deal.II 显式实例化管理

deal.II 是开源 FEM 库，使用显式实例化（explicit instantiation）管理模板膨胀：

- 头文件中使用 `extern template class Triangulation<1>` 等声明避免重复实例化。
- `.cc` 文件中集中实例化：`template class Triangulation<1>; template class Triangulation<2>; template class Triangulation<3>;`
- 各维度（dim=1,2,3）和各标量类型（double, float）的组合是必要的功能覆盖，非设计冗余。

**检测要点**：
- MLR-014 应区分“使用”与“实例化”：`Triangulation<dim>` 出现在函数签名中不等于重复实例化。
- 若项目已大量使用 `extern template`（MLR-019 为阳性，表示有管理），MLR-014 应降级或豁免。
- 工具需增加过滤：排除函数参数、typedef、using 声明中的 `<...>` 匹配。

**预期输出级别**：无 MLR-014/019 告警。

**预期输出**：
（无 MLR-014/019 违规）

若有 MLR-014 报出，应检查：

1. 是否匹配了非实例化的 `<...>` 用法（如函数参数 `Vector<double>&`、返回类型等）。
2. 是否已统计 `extern template` 声明的降权效果。
3. 若工具尚不支持显式实例化识别，可在项目根目录添加全局豁免注解：
   `// @template_specialization_required: explicit-instantiation-managed`
   将 MLR-014 整体降为 INFO。

### 5.1 需审查案例（无豁免）：OpenFOAM `Tensor` 膨胀率 47%

- **预期输出级别**：INFO（需审查）
- **预期输出**：

```text
[MLR-017] 二进制膨胀超标 (INFO - 需审查)

说明: 检测到高膨胀率。若此膨胀是为换取运行时性能，请在特化定义处添加豁免注释：
      // @allow_binary_bloat: <理由>; performance_gain: X%; compile_time_increase: Ys

[MLR-023] 同一模板在多个库中重复实例化 (WARNING)
特化: Tensor<double> 出现在 libA.so, libB.so, libC.so
```

- **预期输出**：无 MLR-017 告警（审计日志记录豁免）。

## 7. 基线校准验证（新增，对应指南8.1节）

### 7.1 场景：项目首次运行评估，需建立专属阈值

- **输入**：20 个模块的扇入值样本 `[12,15,18,20,22,25,28,30,35,38,42,45,48,52,55,60,68,75,82,95]`
- **预期计算**：
  - Q1=25, Q3=60, IQR=35
  - 校准后扇入阈值 = max(10, 60 + 1.5×35) = 113
- **验证点**：工具应输出校准后的阈值（113），并提示“默认阈值50已更新为113，基于当前项目基线”。

### 7.2 场景：验证误报率

- **输入**：测试集 20 个模块，已知其中 2 个为真实债务，工具告警 3 个（其中 1 个为误报）。
- **预期输出**：工具应报告误报率 = 1/20 = 5%，漏报率 = 0/2 = 0%，并提示“误报率低于10%，阈值合理”。

## 8. 豁免性能自动化验证（新增，对应指南8.2节）

### 8.1 豁免注释格式正确且性能验证通过

- **输入豁免注释**：

```cpp
// @allow_binary_bloat: SIMD optimization; performance_gain: 40%; compile_time_increase: 2.1s;
//    benchmark_script: ci/benchmarks/matrix_bench.cpp; threshold: gain>=30% and increase<=5s
```

- **CI 执行**：编译两个版本，性能测试结果：gain=42%，increase=1.8s。
- **预期输出**：豁免验证通过，MR 可合并，审计日志记录 `validated_at=2026-06-12`。

### 8.2 豁免注释格式正确但性能验证失败

- **输入豁免注释**：同上，但实际 gain=20%（低于 30%）。
- **预期输出**：

```text
[豁免验证失败] MLR-017 豁免无效
原因: performance_gain=20% < threshold_gain=30%
建议: 优化模板性能或调整 threshold 值。
```

MR 被阻断。

### 8.3 豁免注释缺少必填字段

- **输入豁免注释**：`// @allow_binary_bloat: SIMD optimization`（缺少 performance_gain、benchmark_script 等）。
- **预期输出**：

```text
[豁免语法错误] 缺少必填字段: performance_gain, benchmark_script, threshold
```

MR 被阻断。

## 9. 跨规则豁免协调验证（新增，对应指南4.2节）

### 9.1 场景：一个模板同时满足 MLR-014 多精度豁免和 MLR-017 性能豁免

- **代码注释**：

```cpp
// @template_specialization_required: multi-precision
// @allow_binary_bloat: multi-precision SIMD paths; performance_gain: 35%; compile_time_increase: 1.5s;
//    benchmark_script: ci/benchmarks/precision_bench.cpp; threshold: gain>=30%
```

- **预期行为**：
  - MLR-014 输出 INFO（需审查，但被豁免标记覆盖）。
  - MLR-017 仍需执行性能验证。若验证通过，无告警；若失败，阻断 MR。
- **验证点**：工具应分别处理两条规则，不因 MLR-014 豁免而跳过 MLR-017 验证。

## 10. 指标重叠与得分合并验证（对应指南4.2节）

### 10.1 MLR-014 与 MLR-023 重叠

- **输入**：某模板特化重复率 45%（MLR-014 得分 40），跨库重复出现（MLR-023 得分 70）。
- **预期综合分计算**：模板实例化重复率子维度取 40 分。
- **验证点**：工具输出综合分中该子维度得分为 40，而非 (40+70)/2=55 或 40+70=110。
