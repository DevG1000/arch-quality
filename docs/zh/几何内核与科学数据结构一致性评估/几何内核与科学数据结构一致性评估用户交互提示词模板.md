# 几何内核与科学数据结构一致性评估 — 用户交互提示词模板

> 文档编号：GCS-C3-用户提示词
> 说明：面向用户在 OpenCode 中使用的提示词模板，用于调用 `architecture-quality` 智能体执行几何内核与科学数据结构一致性评估。
> 关联文档：《几何内核与科学数据结构一致性评估指南》

---

## 1. 基础评估

```
请对 [项目路径] 执行几何内核与科学数据结构一致性评估，
汇报 4 维得分（几何内核一致性/精度与单位一致性/科学数据结构组织/数据访问规范）和 GCS 违规清单。
```

**示例**：
```
请对 D:/opensource/OCCT 执行几何内核与科学数据结构一致性评估，
汇报 4 维得分和 GCS 违规清单。
```

## 2. 单维度分析

```
请分析 [项目路径] 的几何内核一致性（geometry_kernel_consistency）：
闭合性校验是否缺失？Handle 裸指针是否有穿越？内核失败状态（IsDone）是否被检查？
```

## 3. GCS 规则排查

```
请检查 GCS-00X（规则名称）在 [项目路径] 中的具体情况，
说明违规的影响范围和建议修复方式。
```

**示例**：
```
请检查 GCS-002（Handle 裸指针穿越）在 D:/opensource/OCCT 中的具体情况，
说明哪些文件存在 Handle(Geom_XXX) 与裸指针混用，以及如何修复。
```

## 4. 改进建议

```
请基于最近一次评估结果，给出 [项目路径] 几何内核一致性改进建议，
按 P0/P1/P2 优先级分级，并预估每项改进的得分提升空间。
```

## 5. 历史对比

```
请将 [项目路径] 的当前几何一致性得分与历史基线对比，
报告得分偏移和 GCS 违规变化，判断是否出现退化。
```

## 6. 专项审查

```
请审查 [项目路径] 是否满足以下几何内核专项要求：
- 布尔操作失败检查（IsDone）在封装级 builder 是否覆盖
- 精度/单位魔法数字是否集中在命名常量
- 科学数据结构（VTK/gmsh/OpenFOAM）组织是否按单元统一
- 数据访问是否通过访问器封装而非裸成员访问
```

---

## 使用说明

- 所有评估由 `architecture-quality` 智能体执行，底层调用 `python -m arch_quality.arch_metrics_geometry_consistency <项目> --json`
- 评估过程只读，不修改被测项目源码
- GCS 违规 severity 与 output_level 遵循《几何内核与科学数据结构一致性评估指南》
