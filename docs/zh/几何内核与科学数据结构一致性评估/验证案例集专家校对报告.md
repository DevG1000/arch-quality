## P0-2：4.4 GCS-002 用例 `new Geom_Plane()` 不可编译 — 无默认构造函数（已实测）

**相悖点**：4.4 负例与正例均使用 `new Geom_Plane()`。

**OCCT V8.0.1 源码实测**（`src/ModelingData/TKG3d/Geom/Geom_Plane.hxx`）`Geom_Plane` 构造函数仅有 4 个，**全部要求参数**：

```cpp
Geom_Plane(const gp_Ax3& A3);
Geom_Plane(const gp_Pln& Pl);
Geom_Plane(const gp_Pnt& P, const gp_Dir& V);
Geom_Plane(const double A, const double B, const double C, const double D);
```

**逻辑相悖**：`new Geom_Plane()` 无匹配构造函数，两段用例代码**均无法编译**。AI 专家自评将抽象类 `Geom_Surface` 改为 `Geom_Plane` 以"修复抽象基类不可实例化"问题，却引入了"无默认构造函数"的新缺陷——修复未完成。此外正例 `Handle(Geom_Plane) get_plane(){return new Geom_Plane();}` 同样不可编译。

**建议**：改用有默认语义的构造（如 `new Geom_Plane(gp_Pln())` 或 `Handle(Geom_Plane)::DownCast(...)`），或改用 `BRepPrimAPI_MakeBox` 等可默认构造的 `TopoDS_` 对象。

## P0-3：4.8 GCS-009 负例依赖"注释意图"，静态检测无法判定 — 与检测逻辑矛盾

**相悖点**：4.8 负例：

```cpp
size_t n_vertices = grid->GetNumberOfPoints();
double* coords   = new double[n_vertices * 3];   // 正确
double* stresses = new double[n_vertices];        // 每点 6 分量却按 1 分配 → 维度不匹配
```

**逻辑相悖**：指南 GCS-009 检测逻辑为"数组长度声明与网格维度声明**不匹配**"。但本例中：
1. `stresses = new double[n_vertices]` 与 `n_vertices = grid->GetNumberOfPoints()` **完全一致**（数组长度 = 网格点数），静态分析判"匹配"而非"不匹配"；
2. "每点应有 6 分量"的信息**只存在于注释里**，代码中没有任何"应然维度 = 6"的信号（无 `*6`、无常量、无数据结构声明）——即使低置信度启发式，也不可能从注释推断触发。

**建议**：负例改为存在可检测信号的不匹配，如 `double* stresses = new double[n_vertices * 3];`（应 6 却 3）配合维度常量，或删除"每点 6 分量"注释并重写为"声明长度与引用长度不一致"的可检模式。

## P0-4：4.2 GCS-007 负例实为"跨格式转换适配"，与边界裁决（数据交换归 ACL/MPR-012）矛盾

**相悖点**：4.2 负例：

```cpp
void convert(vtkUnstructuredGrid* vtk, fvMesh& of) {  // VTK ↔ OpenFOAM 网格转换
    auto pts  = vtk->GetPoints();
    auto cells = of.cells();
}
```

**逻辑相悖**：指南 GCS-007 检测的是"**同一网格在多种语义中混用且无统一封装**"（语义混用）。但本例函数签名即"输入 VTK 网格 + 输入 OpenFOAM 网格"——这是一个**跨格式网格转换器（adapter/converter）**，属维度⑧ ACL 防腐（外部标准封装族）或 MPR-012（数据格式转换统一性）范畴。设计依据 §5 边界裁决明确"数据交换防腐归 ACL、格式转换统一性归 MPR-012"。**若转换器被 GCS-007 判 ERROR，则与边界裁决直接冲突**（同文件被 GCS 与 ACL 双重计分）。

**建议**：GCS-007 检测逻辑需补充边界——"**多语义混用发生在同一数据表示内（无转换意图）**"才触发；明确"跨格式转换适配器"豁免（归 ACL/MPR-012）；4.2 负例改写为"同一 `vtkUnstructuredGrid` 数据被当作 gmsh 语义直接索引"的混用（非转换器）。

## P1-5：C-1 Validation 案例与指南 1.3 版本漂移 — "GCS-003 ERROR 级"已过时

**相悖点**：C-1 关键数据（§三）称"GCS-003（异常传播 **ERROR**）+ GCS-007 告警"、"架构师针对 **ERROR 级** GCS-003 整改"。

**逻辑相悖**：指南 1.3（专家校对 P0-2 修订）已将 GCS-003 降为 **MEDIUM/WARNING**（非 ERROR 阻断）。案例集 C-1 仍按 GCS-003=ERROR 编写，与指南**版本漂移**——同一个文档包内，指南说"GCS-003 不阻断、需人工确认"，案例却演示"针对 ERROR 级整改并复评提分"。

**建议**：C-1 关键数据同步为"GCS-003（WARNING）+ GCS-007（ERROR）"，整改动作相应改为"人工确认 + 整改"，或改用 GCS-007（仍为 ERROR）作为阻断示范。
