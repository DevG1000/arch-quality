## 1. 设计概览

### 1.1 设计目标

实现指南定义的 4 维评分模型与 12 条 GCS 规则的**静态分析检测**，对几何内核（OCCT 等）与科学数据结构（VTK/gmsh/OpenFOAM 等）项目的"数据一致性"进行可复现、可门禁的量化评估。

### 1.2 架构定位

- 作为 `ComprehensiveReport` 的**结构质量增强维度**（引擎键 `geometry-consistency`），通过 profile 引擎集启用
- 遵循 `arch-core` 框架标准模式：`FileIndex` 扫描 → `_detect_geometry()` 启用判定 → 4 维 `calc_xxx()` → `check_gcs_rules()` → `all_metrics()`
- 与既有引擎（multilang/template/numerical/solver_physics）并行，不共享状态

### 1.3 技术选型

| 项 | 选择 | 理由 |
|:---|:-----|:-----|
| 语言 | Python 3.10+ | 与 arch-quality 框架一致 |
| 扫描 | `FileIndex` + `read_text_smart` | 复用既有缓存与编码兼容 |
| 检测 | 正则 + 类型清单 + 统计 | 对齐指南置信度分级（精确匹配→高，结构→中，启发式→低）|
| 权重 | `load_weights_from_skill` 运行时解析 | 与 Skill 文件权重一致，禁止硬编码 |

## 2. 整体架构

### 2.1 类结构

```
GeometryConsistencyMetrics
├── __init__: FileIndex + _detect_geometry + _scan_files
├── calc_geometry_kernel_consistency()  # 维度1（30%）
├── calc_precision_unit_consistency()   # 维度2（20%）
├── calc_scidata_organization()         # 维度3（25%）
├── calc_data_access_norm()             # 维度4（25%，含递进扣分）
├── check_gcs_rules()                   # 12 条 GCS 规则
└── all_metrics()                       # 综合输出
```

### 2.2 缓存机制

- `_dims_cache`：维度结果缓存（`_calc_cached`），避免 `check_gcs_rules` 重复计算 4 维
- 进程内内容由 `read_text_smart(use_cache=True)` 提供（mtime 失效）

### 2.3 数据流

```
FileIndex 扫描 → _detect_geometry（前 300 文件信号预筛）
  → _scan_files 预读全部源码内容
  → 4 维 calc_xxx（每维正则统计）
  → check_gcs_rules（复用维度 detail）
  → all_metrics（加权综合分 + gcs_violations）
```

### 2.4 性能优化

- 启用预筛：非几何项目**零成本**返回（不读文件）
- 单遍扫描：`_scan_files` 一次性缓存全部内容，各维度共用
- 第三方依赖目录跳过（`third_party`/`vendor` 等），减少误报与耗时

## 3. 维度 1：几何内核数据一致性（30%）映射

### 3.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| 内核闭合性校验测试存在（加分项）| 30 | 中 |
| Handle 智能指针一致（无跨作用域裸指针穿越）| 25 | 中 |
| 内核异常/失败状态传播（紧邻调用点检查）| 25 | 中 |
| 内核对象生命周期受管理（同作用域）| 20 | 中 |

### 3.2 工具实现映射（检测正则级）

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| 闭合性校验 | 引用存在性 | `CLOSURE_CHECK_RE`: `\b(BRepCheck\w*|BOPCheck|CheckShape|IsClosed)\b` |
| Handle 一致 | 裸 new 穿越 | `BARE_NEW_KERNEL_RE`: `return\s+new\s+(?:TopoDS_|Handle\(|BRep\w*|Geom_\w+)\b`（白名单排除内核自身目录）|
| 异常传播 | 调用点窄化 | `KERNEL_CALL_RE`（BRepAlgoAPI/BRepBuilderAPI/BRepPrimAPI 构造）+ 调用后 300 字符内查 `DONE_CHECK_RE`（IsDone/IsValid/IsNull/catch）|
| 生命周期 | 同作用域 | `SCOPE_NEW_DELETE_RE`: 同文件 `new 内核类型` 与 `delete` 并存 |

### 3.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| GCS-001 仅测"引用存在性"，不测"是否执行" | 闭合性运行时判定静态不可实现（KNOWN_HOLES）| 定位为**加分项**（存在加分、缺失 INFO 提示），不替代运行时判定 |
| GCS-003 仅判定"同语句块紧邻调用点" | 跨函数失败状态传递无法静态追踪 | 窄化判定降低误报（对齐 AI 自评第二轮 C-3）；跨函数延迟检查不判定，属 H3 |
| GCS-002/004 以"是否穿越作用域"分界 | 专家校对 P1-1：两者都以裸 new 为信号 | GCS-002 检测 `return new` 穿越；GCS-004 检测同作用域 new/delete，不重复触发 |

## 4. 维度 2：内核精度/单位一致性（20%）映射

### 4.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| 精度/容差无魔法数字（命名常量管理）| 50 | 低 |
| 单位换算无魔法因子（统一工具函数）| 50 | 低 |

### 4.2 工具实现映射

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| 精度魔法数字 | 硬编码字面量 + 命名常量对照 | `PRECISION_LITERAL_RE`: `1e-\s?\d+|[<>]=?\s*0\.0+[1-9]`；`NAMED_PRECISION_RE`: `(?:^|_)(?:TOL|TOLERANCE|PRECISION|CONFUSION|EPSILON)\b` |
| 单位换算因子 | 魔法因子 + 统一函数对照 | `UNIT_FACTOR_RE`: `\b(25\.4|3\.28084|0\.0254|0\.3048|2\.54|1\.60934)\b`；`UNIT_FUNC_RE`: `\b(convert|unit::|UnitsMethods|to_mm|to_inch|to_meter)\w*` |

### 4.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| 命名常量正则无法匹配标识符内关键词（`GEOM_TOLERANCE`）| 初版 `\bTOL\b` 在 `_` 后无词边界 | 修正为 `(?:^|_)(?:TOL|...)\b`（标识符起始或下划线后），经测试验证 |
| 魔法因子表为固定枚举 | 启发式低置信度 | 仅 INFO，不阻断；枚举可在校准期扩展 |
| "存在命名常量即豁免"策略偏宽松 | 避免误报科学常数 | 符合低置信度定位；细化（按文件/作用域）留 WP-2 校准 |

## 5. 维度 3：科学数据结构组织一致性（25%）映射

### 5.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| 网格单元类型一致（无跨语义混用）| 40 | 中 |
| 场量组织一致（pointData/cellData 命名）| 35 | 中 |
| 网格/场量维度匹配 | 25 | 低 |

### 5.2 工具实现映射

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| 网格语义混用 | ≥2 类型 + 交叉索引 | `GRID_TYPE_RE`: `\b(vtkUnstructuredGrid|vtkPolyData|gmsh::|fvMesh|volScalarField|GModel)\b`；`CROSS_INDEX_RE`: `gmsh::model::\w+\(` 或 vtk↔fvMesh 交叉参数 |
| 场量命名 | 命名体系混用 | `FIELD_INCONSISTENT_RE`: `pointData/cellData` 与 `cellField/pointField` 同文件并存 |
| 维度匹配 | 常量 vs 硬编码因子 | `COMPONENT_CONST_RE`（命名分量常量）与 `DIM_FACTOR_RE`（`new double[\w+\*(\d+)]`）对照 |

### 5.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| GCS-007 交叉索引简化为"gmsh::model 调用即算" | 初版要求 gmsh 调用参数含 "vtk" 字面量，漏检 `c->GetPointId(0)` 这类间接传递 | 放宽为文件含 vtk 类型 + gmsh::model 调用即判（中置信度权衡，指南已允许）；跨格式转换器豁免见 §7 |
| GCS-009 依赖命名分量常量存在 | 无分量常量时无法判"应然维度" | 低置信度，仅在有命名常量时触发；无信号不误报 |
| 场量命名检测依赖白名单 | VTK 命名约定 `pointData/cellData` | 白名单可扩展；非常规命名漏报（中置信度可接受）|

## 6. 维度 4：数据表示与访问规范性（25%）映射

### 6.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| 无裸数组替代科学数据结构（密度阈值内）| 35 | 中 |
| 深/浅拷贝使用正确 | 30 | 低 |
| 数据访问有封装 | 35 | 高 |

### 6.2 工具实现映射

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| 裸数组密度 | 文件级密度统计 | `BARE_ARRAY_RE`（`double*/float*`/`new double[]`）与 `SCIDATA_REF_RE`（vtkSmartPointer/vtkPoints/fvMesh）并存计数，密度 = bare/scidata，阈值 0.5 |
| 深/浅拷贝 | 共享底层缓冲模式 | `SHALLOW_COPY_RE`: 类成员 `vtkSmartPointer<T>` + 拷贝构造共享，或浅拷贝注释 |
| 数据访问封装 | 直接成员访问 | `DIRECT_MEMBER_ACCESS_RE`: `\w+->(?:data_|internal_|private_|coords|vertices_)\w*(?:\[[^\]]*\])?\s*[=;]` |

### 6.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| 密度阈值 0.5 为工程经验初值 | 需在真实项目校准 | 记为"待 WP-2 校准"，对齐 Skill §七 基线校准 |
| GCS-012 仅匹配固定命名（data_/internal_ 等）| 对齐 solver `DIRECT_MEMBER_ACCESS` 先例 | 可扩展名单；下标访问（`data_[0]`）已支持（B1 测试验证）|
| 递进扣分在维度 4 内部实现（2.1<60 折半）| 专家校对 P1-4 | 与指南 §2.4/§三 注一致；`_calc_cached` 复用维度 1 得分避免重复计算 |

## 7. GCS 规则映射（12 条对齐表）

| 规则 | 对应子项 | 触发条件 | output_level | 与评分档位对齐 |
|:----:|:---------|:---------|:------------:|:---------------|
| GCS-001 | 维度1 检查项1 | 闭合性校验引用缺失 | INFO | 加分项：存在 +30，缺失仅提示（非违规）|
| GCS-002 | 维度1 检查项2 | `return new 内核类型` 穿越 | WARNING | 触发 → 该子项 0 分 |
| GCS-003 | 维度1 检查项3 | 调用点 300 字符内无 IsDone/catch | WARNING | 触发 → 该子项 0 分 |
| GCS-004 | 维度1 检查项4 | 同作用域 new/delete | WARNING | 触发 → 该子项 0 分 |
| GCS-005 | 维度2 检查项1 | 硬编码精度且无命名常量 | INFO | 触发 → 该子项 0 分（有命名常量豁免）|
| GCS-006 | 维度2 检查项2 | 魔法因子且无统一函数 | INFO | 触发 → 该子项 0 分 |
| GCS-007 | 维度3 检查项1 | ≥2 网格类型 + 交叉索引 | ERROR | 触发 → 该子项 0 分 |
| GCS-008 | 维度3 检查项2 | 场量命名混用 | WARNING | 触发 → 该子项 0 分 |
| GCS-009 | 维度3 检查项3 | 维度因子与命名常量不一致 | WARNING | 触发 → 该子项 0 分 |
| GCS-010 | 维度4 检查项1 | 裸数组密度 > 0.5 | INFO | 触发 → 该子项 0 分 |
| GCS-011 | 维度4 检查项2 | 浅拷贝共享缓冲 | INFO | 触发 → 该子项 0 分 |
| GCS-012 | 维度4 检查项3 | 直接成员访问 | ERROR | 触发 → 该子项 0 分 |

**评分-规则对齐原则**：每条规则的触发条件与对应评分检查项的 0 分条件**一一对应**（触发即 0 分），无"评分满分 + 规则触发"矛盾；GCS-001 为唯一例外（加分项，非违规）。

## 8. 映射总表与一致性检查

### 8.1 四维度分值映射总表

| 维度 | 权重 | 检查项 | 分值 | 实现 |
|:-----|:----:|:-------|:----:|:-----|
| 几何内核数据一致性 | 30% | 闭合性校验/Handle/异常传播/生命周期 | 30/25/25/20 | §3.2 |
| 内核精度/单位一致性 | 20% | 精度魔法数字/单位因子 | 50/50 | §4.2 |
| 科学数据结构组织一致性 | 25% | 网格语义/场量命名/维度匹配 | 40/35/25 | §5.2 |
| 数据表示与访问规范性 | 25% | 裸数组密度/深浅拷贝/访问封装 | 35/30/35（2.1<60 折半）| §6.2 |

### 8.2 一致性检查方法

- **权重**：`load_weights_from_skill(SKILL_PATH)` 运行时解析，与 Skill §一 一致（校验和=100%）
- **规则 ID**：`scripts/consistency_check.py --engine geometry_consistency`（RULES GCS-001~012 三方一致）
- **评分-规则对齐**：§7 映射表人工审查（触发即 0 分原则）
- **置信度**：规则表/§7.1/§7.3 三处一致（高=GCS-012，中=GCS-001/002/003/004/007/008/010，低=GCS-005/006/009/011）

### 8.3 已知局限

| 局限 | 说明 | 归属 |
|:-----|:-----|:-----|
| 闭合性"执行率"不可测 | GCS-001 仅存在性 | KNOWN_HOLES（H3）|
| 欧拉公式约束不可测 | 运行时拓扑不变量 | KNOWN_HOLES（H3）|
| GCS-003 跨函数失败传递不判 | 语义级 | H3 |
| GCS-003 封装级/助手级检查不可判（B3.5）| OCCT 委托 BRepFeat/BRepFill builder `IsDone()`、CheckAndLoad 助手——静态不可见，检测仅覆盖"布尔操作直接提取结果"子集；OCCT 587→40、salome 61→0、freecad 174→0 | H3 语义级 |
| GCS-009 需命名分量常量信号 | 无信号不触发 | 低置信度校准 |
| 密度阈值 0.5 待校准 | 工程经验初值 | WP-2 校准 |
