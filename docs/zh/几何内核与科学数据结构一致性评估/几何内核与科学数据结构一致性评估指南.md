> **版本**：1.6（子维度章节补全，对齐求解器物理场指南结构）
> **编制**：AI 辅助编制（编制流程见《AI 架构评估文档编制指南 1.7》）
> **状态**：通过 AI 专家自评（两轮，P0 清零）+ 两轮专家校对（11 项意见全部处理），修订完成待复核后定稿为可用版本（作 WP-2 引擎实施基准）
> **适用范围**：使用几何内核（Open CASCADE Technology、CGAL、SALOME GEOM 等）或科学数据结构（VTK/gmsh/OpenFOAM 网格、场量容器等）的 CAE/工业软件

## 概述

### 评估目标

本指南定义**几何内核与科学数据结构一致性**评估维度（注册表维度④，引擎前缀 **GCS**）。评估对象是使用几何内核与科学数据结构的代码库，衡量其在以下方面的架构健康度：

1. **几何内核数据一致性**：对内核对象（B-Rep 实体、Handle 智能指针）的使用是否符合内核数据模型约束
2. **内核精度/单位一致性**：硬编码精度/容差、单位换算是否存在魔法因子
3. **科学数据结构组织一致性**：网格单元类型、场量组织的语义是否一致
4. **数据表示与访问规范性**：裸数组 vs 科学数据结构、深/浅拷贝、数据访问封装性

本维度**不评估**：几何内核本身的功能正确性（归数值算法维度）、外部内核的封装与防腐层（归维度⑧ ACL）、多物理场模块化（归维度⑤ MPR）。

### 适用范围

- **适用**：引用几何内核（如 `TopoDS_*`/`Handle_*`/`BRep*`）或科学数据结构（VTK/gmsh/OpenFOAM 网格、场量容器）的代码库
- **不适用**：无几何内核/科学数据结构引用的纯业务代码（此时引擎应判定不适用并返回 None）

### 行业标准映射

| 标准 | 对应关切 |
|:-----|:---------|
| ISO/IEC 25010 数据质量（准确性/一致性）| 网格/场量数据组织一致性、单位一致性 |
| ISO 10303（STEP）| 几何数据交换一致性、公差一致性（注：STEP 为**数据交换标准**，主要支撑 GCS-007/008 数据交换语义，非内核数据一致性关切）|
| Open CASCADE Technology 数据模型 | B-Rep 闭合性、Handle 智能指针、拓扑操作容差 |
| ASME Y14.5 几何公差 | 精度/容差一致性 |

## 置信度说明

本指南对每条规则与每个检测方法标注**三级置信度**：

| 置信度 | 含义 | 检测方式 | 使用建议 |
|:------:|:-----|:---------|:---------|
| **高** | 检测结果准确可靠，无需人工复核 | 精确符号匹配、文件存在性、统计计数 | 可作 CI 阻断（ERROR）|
| **中** | 检测结果基本可靠，边界情况需人工确认 | 结构检查、AST/类型清单 + 白名单 | 建议 WARNING 或需人工复核 |
| **低** | 检测为启发式推断，需人工复核 | 模式/关键词匹配、正则推断 | 仅 INFO，不阻断 |

**使用建议**：高置信度规则可纳入门禁；中置信度规则作为告警；低置信度规则仅作为参考信息，需结合人工评审判断。详见§七实施建议。

## 一、子维度与权重分配

几何内核与科学数据结构一致性评估由以下 **4 个子维度** 加权合成：

| 子维度 | 权重（默认） | 覆盖规则 | 置信度 | 对应风险 |
|--------|-------------|:--------:|:------:|---------|
| 几何内核数据一致性 | 30% | GCS-001~004 | 中 | B-Rep 实体未闭合/生命周期失控/异常未传播 |
| 内核精度/单位一致性 | 20% | GCS-005~006 | 低 | 硬编码精度、单位换算魔法因子导致结果错误 |
| 科学数据结构组织一致性 | 25% | GCS-007~009 | 中 | 网格/场量语义混用、维度不匹配 |
| 数据表示与访问规范性 | 25% | GCS-010~012 | 中 | 裸数组滥用、深/浅拷贝错误、数据直接暴露 |

**权重设计依据**：
- **几何内核数据一致性**权重最高（30%），因为内核对象的数据一致性是最基础且影响面最大的约束——B-Rep 不闭合、Handle 生命周期失控会导致后续所有几何操作失效。
- **科学数据结构组织一致性**（25%）与**数据表示与访问规范性**（25%）次之，两者共同决定场量/网格数据的正确组织与访问。
- **内核精度/单位一致性**（20%）权重最低，因魔法因子检测为低置信度启发式，且其对架构可维护性影响相对间接。

**权重来源标注**：默认权重为**工程经验校准（待定）**，将在 WP-7 交叉验证后定案（H2 决策：激活子集归一化实施归 H3，本维度以候选权重占位展示）。

## 二、子维度定义与评分算法

### 2.1 几何内核数据一致性（30%）

**定义**：评估对几何内核对象（B-Rep 实体、Handle 智能指针）的使用是否遵循内核数据模型约束，包括闭合性校验测试的存在性、Handle 智能指针一致性、内核异常/失败状态传播、内核对象生命周期管理。内核数据一致性是几何/多物理场平台架构的**必要条件**。

**置信度**：中

**设计依据**：
- **OCCT B-Rep 数据模型**：B-Rep 拓扑一致性、Handle 引用计数是几何内核对象正确性的基础约束；`BRepCheck_*` 闭合性校验工具是行业参照
- **ISO/IEC 25010 数据质量（准确性/一致性）**：内核对象生命周期与异常传播是几何数据正确性的前提
- **Handle 智能指针设计（OCCT 引用计数）**：生命周期自动管理是内核对象内存安全的基础

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|--------|---------|------|--------|
| 内核闭合性校验测试存在（加分项）| 检测 `BRepCheck`/`BOPCheck`/`CheckShape` 引用存在性 | 30分 | **中** |
| Handle 智能指针一致（无跨作用域裸指针穿越）| 内核类型清单 + 裸指针穿越检测 + 白名单 | 25分 | **中** |
| 内核异常/失败状态传播（紧邻调用点检查）| 调用点上下文 `IsDone()`/`IsValid()` 检查 | 25分 | **中** |
| 内核对象生命周期受管理（同作用域）| 同作用域裸 new/delete 窄化检测 | 20分 | **中** |

```
内核数据一致性得分 = sum(各检查项得分)
```

**置信度说明**：
- 闭合性校验测试存在性可静态判定（引用检测），但"是否真正执行"无法确认，置信度为**中**。
- Handle 一致性检测依赖类型清单 + 白名单，需避免误报，置信度为**中**。
- 异常传播检测为紧邻调用点窄化判定，跨函数传递无法追踪，置信度为**中**（非高）。
- 生命周期检测需区分合法手动管理场景，置信度为**中**。

**对应行业实践**：
- OCCT 全程使用 `Handle_*`/`TopoDS_*` 智能指针，配合 `BRepCheck_Analyzer` 闭合性校验
- SALOME GEOM 通过 `GEOMImpl` 封装层集中管理内核操作与生命周期

**代码坏味道：内核对象生命周期失控（Kernel Object Lifetime Escaping）**

- **描述**：内核对象以裸 `new`/裸指针形式跨作用域传递或手动管理，异常/失败状态未被检查。
- **典型表现**：`return new TopoDS_Shape()` 穿越函数边界；布尔运算后未检查 `IsDone()`；同作用域手动 `new`/`delete` 内核对象。
- **危害**：悬垂引用、内存泄漏、失败静默吞没导致后续几何操作级联失败。

**算例**：
- 正例：OCCT 使用 `BRepCheck_Analyzer` 校验 B-Rep 闭合，`Handle(Geom_Surface)` 全程智能指针
- 负例：裸 `new TopoDS_Shape` 分配内核对象且跨模块传递裸指针

### 2.2 内核精度/单位一致性（20%）

**定义**：检测几何内核相关代码中是否存在硬编码精度/容差魔法数字与单位换算魔法因子，衡量数值参数的一致性管理。

**置信度**：低（启发式）

**设计依据**：
- **OCCT 精度管理实践**：`Precision::Confusion()`/`Precision::PConfusion()` 命名常量集中管理内核精度
- **OCCT UnitsMethods 单位制管理**：STEP 单位换算由统一工具函数处理，避免魔法因子散布
- **ISO 10303（STEP）单位制解析**：几何数据交换中的单位一致性

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|--------|---------|------|--------|
| 精度/容差无魔法数字（命名常量管理）| 检测 `1e-<n>`/`0.00<n>` 硬编码 + 命名常量对照 | 50分 | **低** |
| 单位换算无魔法因子（统一工具函数）| 检测换算魔法因子（3.28084/25.4 等）| 50分 | **低** |

```
内核精度/单位一致性得分 = sum(各检查项得分)
```

**置信度说明**：
- 硬编码精度检测为启发式，可能误报科学常数（如 1e-10 可能是合法物理常数），置信度为**低**。
- 单位换算魔法因子检测依赖上下文判断，可能误报常量定义，置信度为**低**。

**对应行业实践**：
- OCCT 用 `Precision::Confusion()` 等命名常量管理内核精度
- OCCT `UnitsMethods` 统一管理 STEP 单位换算

**代码坏味道：魔法数字（Magic Number）**

- **描述**：精度/容差/单位换算参数以裸数字硬编码，未集中命名管理。
- **典型表现**：多处直接写 `1e-6`、`0.001`；单位换算直接乘 `25.4`、`3.28084`。
- **危害**：跨场景结果不一致，排障成本高；修改容差需全文搜索替换。

**算例**：
- 正例：容差集中定义为 `const double TOL = 1e-6;`，单位换算调用统一工具函数
- 负例：多处硬编码 `1e-6`/`0.001` 且单位换算直接乘 `3.28084` 等魔法因子

### 2.3 科学数据结构组织一致性（25%）

**定义**：评估网格单元类型与场量数据的组织语义是否一致，网格/场量维度是否匹配。

**置信度**：中

**设计依据**：
- **VTK 数据结构设计**：`vtkUnstructuredGrid`/`vtkPoints` 内建维度与组织语义，`pointData`/`cellData` 命名约定
- **ISO/IEC 25010 数据一致性**：网格/场量数据组织一致性是计算结果正确性的基础
- **gmsh/OpenFOAM 网格语义差异**：不同网格体系单元/节点组织语义不同，直接混用导致数据解释错误

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|--------|---------|------|--------|
| 网格单元类型一致（无跨语义混用）| 检测 ≥2 种网格类型引用 + 直接交叉索引符号 | 40分 | **中** |
| 场量组织一致（pointData/cellData 命名）| 命名模式检测 + 白名单 | 35分 | **中** |
| 网格/场量维度匹配 | 命名分量常量 vs 硬编码维度因子对照 | 25分 | **低** |

```
科学数据结构组织一致性得分 = sum(各检查项得分)
```

**置信度说明**：
- 网格语义混用检测需"多格式引用 + 直接交叉索引"语义确认，置信度为**中**。
- 场量命名一致性检测依赖命名白名单，非常规命名可能漏报，置信度为**中**。
- 维度匹配检测为启发式推断（命名常量 vs 硬编码因子），置信度为**低**。

**对应行业实践**：
- VTK 统一使用 `vtkUnstructuredGrid` + `pointData`/`cellData` 命名约定
- MOOSE/libMesh 使用带维度的场量容器（`Field`），避免手写长度推导

**代码坏味道：网格语义混用（Mesh Semantics Mixing）**

- **描述**：同一网格数据被多种网格语义（VTK/gmsh/OpenFOAM）无封装地直接复用，场量命名体系混用。
- **典型表现**：同一 `vtkUnstructuredGrid` 数据被按 gmsh 单元顺序直接索引；`pointData` 与 `cellField` 命名体系混杂。
- **危害**：单元/节点解释错误导致场量计算错误，结果不可信。

**算例**：
- 正例：统一使用 VTK `vtkUnstructuredGrid`，场量按点/按单元命名规则一致（`pointData`/`cellData`）
- 负例：同一网格语义被 VTK 与 gmsh/OpenFOAM 混用，数组长度声明与网格维度不匹配

### 2.4 数据表示与访问规范性（25%）

**定义**：评估是否以科学数据结构替代裸数组、深/浅拷贝是否正确、数据访问是否封装。

**置信度**：中

**设计依据**：
- **信息隐藏与封装原则（Parnas）**：数据成员私有 + 公开访问器是模块可维护性的基础
- **VTK 引用计数设计**：`vtkSmartPointer` 自动管理网格/场量对象生命周期
- **ISO/IEC 25010 可修改性**：数据访问封装性直接影响变更影响面

**评分算法**：

| 检查项 | 检测方法 | 分值 | 置信度 |
|--------|---------|------|--------|
| 无裸数组替代科学数据结构（密度阈值内）| 科学数据结构引用 + 裸数组声明密度统计 | 35分 | **中** |
| 深/浅拷贝使用正确 | 共享底层缓冲（浅拷贝）模式检测 | 30分 | **低** |
| 数据访问有封装 | 复用 DIRECT_MEMBER_ACCESS 检测 | 35分 | **高** |

```
数据表示与访问规范性得分 = sum(各检查项得分)

# 递进扣分（专家校对 P1-4 修订）：基础层内核数据一致性 < 60 时，增强层折半
if 子维度 2.1（几何内核数据一致性）得分 < 60:
    得分 = int(得分 * 0.5)
```

**递进扣分说明**：数据表示与访问规范性（2.4）为**增强层**，其价值依赖基础层（2.1 内核数据一致性）数据正确性。当 2.1 < 60（内核数据正确性存在风险）时，2.4 得分折半——对齐设计依据 §2.1 的层级主张（基础层是必要条件，增强层在正确组织基础上进一步增强）。

**置信度说明**：
- 裸数组密度检测为结构化统计，阈值需校准，置信度为**中**。
- 深/浅拷贝检测为启发式，置信度为**低**。
- 数据访问封装检测复用 `DIRECT_MEMBER_ACCESS` 精确匹配，置信度为**高**。

**对应行业实践**：
- VTK 用 `vtkSmartPointer` 管理网格/场量对象生命周期
- 良好封装的模块数据成员私有 + 访问器（如 `MeshField::at()/set()`）

**代码坏味道：数据暴露（Data Exposure）**

- **描述**：核心数据以裸数组/裸指针直接暴露，或浅拷贝共享底层缓冲导致数据竞争。
- **典型表现**：`double* coords` 作为公有成员直接访问；默认拷贝构造共享网格底层缓冲；跨模块直接 `f->data_[0] = ...`。
- **危害**：维度不匹配、数据竞争、变更影响面失控。

**算例**：
- 正例：网格数据用科学数据结构（`vtkUnstructuredGrid`/`MeshField`）而非裸 `double*`；数据成员私有 + 访问器
- 负例：裸数组 `double* coords` 直接暴露、浅拷贝共享底层缓冲导致数据竞争

## 三、几何内核与科学数据结构一致性综合分

```
综合分 = Σ(子维度得分 × 子维度权重)
       = 2.1×30% + 2.2×20% + 2.3×25% + 2.4×25%
```

> 注：2.4 得分已含递进扣分（2.1 < 60 时折半，见 §2.4）。评分区间为 0-100。

## 四、分数分级

| 综合分区间 | 等级 | 说明 | 建议动作 |
|:---------:|:----:|:-----|:---------|
| ≥ 85 | 🟢 优秀 | 几何内核与科学数据结构使用规范，数据一致性良好 | 维持现状，关注演进 |
| 70-84 | 🟡 良好 | 基本规范，存在少量魔法因子或封装不足 | 优化低分项 |
| 50-69 | 🟠 需改进 | 存在明显的裸数组滥用、异常未传播或语义混用 | 优先整改几何内核一致性 |
| < 50 | 🔴 差 | 内核数据一致性存在严重风险 | 系统性重构数据访问层 |

| GCS-003 | 内核异常/失败状态传播 | MEDIUM | WARNING | 中 | 2.1 |
| GCS-004 | 内核对象生命周期 | MEDIUM | WARNING | 中 | 2.1 |
| GCS-005 | 硬编码精度/容差魔法数字 | LOW | INFO | 低 | 2.2 |
| GCS-006 | 单位换算魔法因子 | LOW | INFO | 低 | 2.2 |

| GCS-008 | 场量组织一致性 | MEDIUM | WARNING | 中 | 2.3 |
| GCS-009 | 网格/场量维度匹配 | MEDIUM | WARNING | 低 | 2.3 |

> **GCS-001 定位说明（专家校对 P0-1 修订）**：GCS-001 为**评分加分项对应的缺失提示**（非违规扣分规则）。其存在性在 §2.1 评分算法中加分（score += 30），规则清单中仅当测试缺失时给 INFO 提示，**不参与违规扣分**。B-Rep 闭合性运行时判定为 KNOWN_HOLES（归 H3），本规则不替代运行时判定。

**KNOWN_HOLES（归 H3）**：
- 欧拉公式约束（运行时拓扑不变量，静态不可判）
- B-Rep 闭合性运行时判定（需构建 + 运行内核）
- 封装级/助手级失败状态检查识别（B3.5 实测：OCCT 将布尔操作失败检查委托给封装级 builder 的 `IsDone()`（BRepFeat/BRepFill 模式）或助手函数（CheckAndLoad），静态不可判——GCS-003 仅判定可识别的布尔操作直接提取模式）

> 注（AI 专家自评第二轮 P1-1 修订）：**内核升级 API 影响面兼容测试**属维度⑧ ACL 的 KNOWN_HOLES（H2 §2.3），不归 GCS；GCS KNOWN_HOLES 保持 2 项（与案例集覆盖注、consistency_check 注册口径一致）。

### 规则详细描述

#### GCS-001：内核闭合性校验测试存在性（加分项）

- **严重级别**：LOW（非违规扣分规则）
- **检测置信度**：中
- **描述**：检测项目是否包含内核闭合性校验测试（如 OCCT `BRepCheck_*`/`BOPCheck` 的使用或等价闭合性验证）。本规则为**加分项对应提示**：存在则 §2.1 评分加分；缺失时给 INFO 提示，不扣分。
- **检测逻辑**：
  1. 扫描源码中是否引用闭合性校验类/函数（`BRepCheck`、`BOPCheck`、`CheckShape`、`IsClosed`、`BRepCheck_Analyzer`）
  2. 存在 → 满足加分条件；缺失 → INFO 提示"缺少闭合性校验测试"
- **置信度说明**：存在性可静态判定（引用检测），但"是否真正执行"无法确认，置信度为**中**；B-Rep 闭合性运行时判定属 KNOWN_HOLES（归 H3），本规则不替代。
- **建议修复**：对 B-Rep 构造/布尔运算结果使用 `BRepCheck_Analyzer` 等闭合性校验工具并纳入测试。

#### GCS-002：Handle 智能指针一致性

- **严重级别**：MEDIUM
- **检测置信度**：中
- **描述**：检测内核对象是否全程使用 `Handle_`/`TopoDS_` 智能指针，是否存在裸 `new`/裸指针**跨作用域穿越**内核边界。
- **检测逻辑**（窄化边界，对齐指南专家校对 P1-1）：
  1. 识别内核类型清单（`Handle_*`、`TopoDS_*`）
  2. 检测裸 `new` 分配内核对象后未经 `Handle` 包装，**经 `return`/参数传递跨函数/跨模块穿越**出作用域
  3. 白名单排除内核自身目录（避免误报）
- **边界说明**：本规则管**跨作用域裸指针穿越**；同一作用域内手动 new/delete 生命周期管理归 **GCS-004**，两者以"是否穿越作用域"为界，不重复触发。
- **置信度说明**：类型清单 + 裸指针穿越模式可静态检测，但需白名单防误报，置信度为**中**。
- **建议修复**：内核对象一律用 `Handle()`/`TopoDS_` 封装，禁止裸指针跨模块穿越。

#### GCS-003：内核异常/失败状态传播

- **严重级别**：MEDIUM
- **检测置信度**：中
- **描述**：检测内核调用点是否检查异常或失败状态（如 `IsDone()`、异常捕获），避免失败被静默吞没。
- **检测逻辑**（窄化，防误报）：
  1. 扫描内核调用点（`BRep*`、`TopoDS_*` 构造/操作）
  2. **仅检测同一语句块内、紧邻调用点**的失败状态检查（`IsDone()`/`IsNull()`/`!IsValid()` 或 try/catch）
  3. 同一语句块内无检查即继续使用返回值 → 触发 GCS-003（WARNING）
  4. 跨函数/跨语句块的失败状态检查（延迟检查、返回值传递）**不判定**（避免误报，属 H3 语义级）
- **置信度说明**：紧邻调用点的检查缺失可较可靠地静态检测，但内核 API 失败检查模式多样、跨函数传递无法静态追踪，综合置信度为**中**（非高）。
- **建议修复**：每个内核操作后检查 `IsDone()`/`IsValid()`，异常型内核用 try/catch 包裹。

#### GCS-004：内核对象生命周期

- **严重级别**：MEDIUM
- **检测置信度**：中
- **描述**：检测内核对象在**同一作用域内**的裸 new/delete 手动生命周期管理，是否存在未用 Handle 自动管理的内核对象。
- **检测逻辑**（窄化边界，对齐指南专家校对 P1-1）：
  1. 检测同一作用域内 `new`/`delete` 直接作用于内核类型（`TopoDS_*`/`Handle_*`/`BRep*`）的手动生命周期管理
  2. 建议改为 `Handle()` 自动管理
- **边界说明**：本规则管**同一作用域内手动 new/delete 生命周期**；跨模块/跨函数裸指针穿越归 **GCS-002**，两者以"是否穿越作用域"为界，不重复触发。
- **置信度说明**：裸 new/delete 模式可检测，但需区分合法的手动管理场景，置信度为**中**。
- **建议修复**：内核对象使用引用计数 Handle 自动管理生命周期。
- **边界裁决**：本规则归属 GCS-004（维度④），ACL 侧（维度⑧）不设生命周期规则，避免双重计分。

#### GCS-005：硬编码精度/容差魔法数字

- **严重级别**：LOW
- **检测置信度**：低
- **描述**：检测内核/几何操作中的硬编码精度或容差魔法数字。
- **检测逻辑**：
  1. 扫描含几何操作的文件中 `1e-<n>`/`0.00<n>` 硬编码常量
  2. 若未定义命名常量（如 `TOL`/`PRECISION`）而直接使用 → 触发（INFO）
- **置信度说明**：硬编码精度检测为启发式，可能误报科学常数，置信度为**低**。
- **建议修复**：将精度/容差集中定义为命名常量。

#### GCS-006：单位换算魔法因子

- **严重级别**：LOW
- **检测置信度**：低
- **描述**：检测单位换算中的魔法因子（如 3.28084、0.0254、25.4 等）。
- **检测逻辑**：
  1. 扫描单位换算上下文中的魔法因子
  2. 若未调用统一换算函数 → 触发（INFO，低置信度）
- **置信度说明**：单位换算魔法因子为启发式检测，低置信度。
- **建议修复**：单位换算集中为统一工具函数。

#### GCS-007：网格单元类型一致性

- **严重级别**：HIGH
- **检测置信度**：中
- **描述**：检测**同一数据表示内**是否混用不同网格语义（VTK/gmsh/OpenFOAM 网格类型），无转换意图地直接跨语义索引同一数据。
- **检测逻辑**（窄化，对齐 AI 专家自评第二轮 C-3）：
  1. 识别网格头文件引用（`vtkUnstructuredGrid`/`gmsh`/`fvMesh`）
  2. **窄化触发**：同一文件**同时引用 ≥2 种网格类型**，且存在**直接交叉索引符号**（将 A 格式指针/对象直接传入 B 格式接口，如把 `vtk*` 指针传给 `gmsh::model::*`/`fvMesh` 接口）→ 触发 ERROR
  3. 仅"同时引用多种网格头文件但各自独立使用"（无交叉索引）**不触发**
  4. **跨格式转换适配器豁免**：显式转换函数（输入/输出分属不同网格格式，如 VTK→OpenFOAM 转换器）不触发，归维度⑧ ACL 防腐 / MPR-012 格式转换统一性
- **置信度说明**：窄化后以"多格式引用 + 直接交叉索引符号"为检测信号，可较可靠判定，但"交叉索引"仍需语义确认（如函数参数类型推断），置信度为**中**（非高）。
- **建议修复**：统一网格语义，通过封装层或独立转换器（归 ACL/MPR-012）转换而非直接混用。

#### GCS-008：场量组织一致性

- **严重级别**：MEDIUM
- **检测置信度**：中
- **描述**：检测场量（Field）容器/按点按单元命名的一致性。
- **检测逻辑**：
  1. 识别场量容器类型与命名（`pointData`/`cellData`/`Field`）
  2. 检测命名规则是否混用
- **置信度说明**：命名一致性为模式检测，需白名单，置信度为**中**。
- **建议修复**：统一场量命名与组织规范。

#### GCS-009：网格/场量维度匹配

- **严重级别**：MEDIUM
- **检测置信度**：低
- **描述**：检测数组长度/维度声明与网格维度是否匹配。
- **检测逻辑**：
  1. 检测数组长度声明（如 `size = n_vertices*3`）与网格维度声明
  2. 不匹配 → 触发（WARNING，低置信度）
- **置信度说明**：维度匹配为启发式推断，低置信度。
- **建议修复**：使用带维度的科学数据结构而非裸数组，减少手写长度推导。

#### GCS-010：裸数组替代科学数据结构

- **严重级别**：LOW
- **检测置信度**：中
- **描述**：检测同一文件中科学数据结构引用与裸数组（`double*`/`float*` 等核心数据容器）的**并存密度**。仅当裸数组成为数据组织主流且与科学数据结构并存密度超阈值时触发，**不评判合理性能热路径中的受控裸数组**（对齐设计依据 §2.2 定位）。
- **检测逻辑**（密度阈值判定）：
  1. 统计文件内科学数据结构引用数（`vtk*`/`fvMesh`/`gmsh`/场量容器）与裸数组声明数
  2. 若科学数据结构引用存在 **且** 裸数组声明占比 > 阈值（校准，默认 50%）→ 触发（INFO）
  3. 若文件无科学数据结构引用（纯裸数组场景）→ **不触发**（不评判数据结构选型）
- **置信度说明**：密度阈值判定为结构化统计，可靠性中等，但阈值需 WP-2 校准，置信度为**中**。
- **建议修复**：核心数据容器（网格/场量）用科学数据结构封装，仅在明确性能热路径保留受控裸数组。

#### GCS-011：深拷贝 vs 浅拷贝

- **严重级别**：LOW
- **检测置信度**：低
- **描述**：检测数据复制时深拷贝/浅拷贝的使用是否正确。
- **检测逻辑**：
  1. 检测共享底层缓冲的浅拷贝模式（默认拷贝构造/赋值共享指针）
  2. 触发（INFO，低置信度）
- **置信度说明**：深/浅拷贝检测为启发式，低置信度。
- **建议修复**：需要独立数据时显式深拷贝，避免共享底层缓冲。

#### GCS-012：数据访问封装性

- **严重级别**：HIGH
- **检测置信度**：高
- **描述**：检测跨模块是否直接访问内核/数据结构内部成员（而非接口调用）。
- **检测逻辑**：
  1. 复用既有 `DIRECT_MEMBER_ACCESS` 检测模式（跨模块直接成员访问）
  2. 检测 `obj->internal_/data_/private_` 直接访问
- **置信度说明**：直接成员访问可精确检测，置信度为**高**。
- **建议修复**：封装内部数据结构，通过公开 API 访问。

## 七、实施建议

### 7.1 工具集成

本维度通过静态分析工具实现（WP-2 `arch_metrics_geometry_consistency.py`）：
- GCS-012：高置信度，正则/符号精确匹配 + 存在性检测
- GCS-001/002/003/004/007/008/010：中置信度，类型清单 + 白名单 + 窄化调用点/交叉索引/密度统计
- GCS-005/006/009/011：低置信度，启发式（INFO）

### 7.2 门禁设置

- GCS-012（数据访问封装）：**ERROR 可阻断**
- GCS-007（网格语义混用）：**ERROR 级，但中置信度——门禁须人工复核后生效**（避免语义级误报阻塞开发）
- 其余规则：WARNING/INFO，建议人工复核（GCS-003 为 WARNING，需结合人工确认）

### 7.3 置信度使用指南

- 高置信度（GCS-012）可直接门禁
- 中置信度（GCS-001/002/003/004/007/008/010）作为告警，配合人工确认（GCS-007 为 ERROR 级中置信度规则，门禁须人工复核）
- 低置信度（GCS-005/006/009/011）仅 INFO，不阻断
- **占比说明**：子维度 2.2（内核精度/单位一致性）全部为低置信度规则（GCS-005/006），其得分占综合分 20%。当该子维度因启发式检测计分时，报告应标注"低置信度，建议人工复核"，且该子维度得分不单独作为门禁判据。

### 7.4 遗留代码库渐进式评估

对既有使用几何内核但历史包袱重的代码库，建议先整改 GCS-012（数据访问封装，ERROR 级）与 GCS-003（异常传播，WARNING 级需人工复核），再处理魔法因子与裸数组。

### 7.5 与现有评估体系衔接

本维度作为结构质量的增强维度，通过 profile 引擎集启用（`profile: geometry-consistency`，WP-0 已支持扩展引擎注册）。

### 7.6 重构优先级

P0：GCS-007/012（ERROR 级，影响正确性与安全；GCS-007 中置信度需人工复核）→ P1：GCS-002/003/004/008（中置信度 WARNING）→ P2：GCS-001/005/006/009/010/011（INFO）。

## 八、启用条件（供 WP-2 实现）

本维度引擎（`arch_metrics_geometry_consistency.py`）启用检测（`_detect_geometry()`）：

- 源码中出现几何内核类型/头文件信号（任一）：`TopoDS_`、`Handle_`、`BRep*`、`Geom_*`、`vtk*`、`fvMesh`、`gmsh`、`CGAL`、`NCollection_`
- 或项目路径/描述含几何内核关键词（`occt`/`opencascade`/`cascade`/`geometry kernel`/`brep`）

满足任一信号 → 判定适用，返回各子维度得分；否则返回 None（不适用）。
