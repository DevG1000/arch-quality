# 求解器物理场模块化架构评估 — 用户交互提示词模板

> 文档编号：SP-C3-用户提示词
> 面向最终用户的 OpenCode 交互提示词模板，便于调用 `architecture-quality` 智能体进行求解器物理场模块化架构评估。
> 关联：求解器与物理场模块化架构模式识别评估指南.md

---

## 1. 完整评估

```
请对 [项目路径] 运行求解器和物理场模块化架构模式识别评估，
输出 4 维评分（边界清晰度/耦合架构/扩展支持/数据传递）和 MPR 违规详情。
```

**示例**：
```
请对 D:/opensource/OpenFOAM-v2512 运行求解器和物理场模块化架构模式识别评估，
输出 4 维评分和 MPR 违规详情。
```

## 2. 单维度分析

```
请分析 [项目路径] 的多物理场耦合架构合理性，
检查耦合逻辑是否集中、求解算法是否可替换、收敛稳定性如何。
```

## 3. MPR 解读

```
请解释 MPR-00X（规则名）在 [项目路径] 中的具体情况，
说明触发条件、影响范围和建议修复方案。
```

**示例**：
```
请解释 MPR-005（耦合逻辑集中度）在当前项目中的具体情况，
说明哪些文件导致耦合逻辑分散，以及如何集中管理。
```

## 4. 改进建议

```
根据最近一次的评估结果，给出 [项目路径] 在耦合架构方面的改进建议，
按 P0/P1/P2 优先级分级，并预估每个建议的提分空间。
```

## 5. 与基线对比

```
请将 [项目路径] 的当前评估结果与回归基线对比，
输出评分偏移和 MPR 规则变化，判断是否出现退化。
```

## 6. 专项检查

```
请检查 [项目路径] 是否满足以下专项：
- 独立编译单元（模块边界清晰）
- FMI 协同仿真标准支持
- 插件扩展机制完整
- 耦合收敛控制（含 OpenFOAM residualControl）
```

---

## 使用说明

- 所有提示词通过 `architecture-quality` 智能体执行（`opencode run --agent architecture-quality`）
- 项目路径支持本地目录或外部目录（需权限配置）
- 完整评估建议加 `--json` 或 `--md` 获取结构化/可读输出
- 评估命令：`python -m arch_quality.arch_report <项目路径> [--json] [--md]`
