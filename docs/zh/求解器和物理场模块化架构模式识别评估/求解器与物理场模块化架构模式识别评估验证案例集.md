## 案例集设计原则

### 原则一：案例分类与使用场景

本案例集包含三类案例，用途不同：

| 类别 | 定义 | 用途 | 验收要求 |
|------|------|------|----------|
| **A类：可复现案例** | 基于开源框架或构造测试用例，可下载源码运行工具验证 | 验证工具检测逻辑是否正确（工具验收的主力） | 必须100%通过 |
| **B类：参考案例** | 来自工业实践但源码不可公开的架构模式 | 帮助理解“真实架构问题长什么样” | 仅作参考，不纳入工具验收 |
| **C类：Validation案例** | 展示评估报告如何被解读和应用的实战场景 | 帮助用户理解告警含义、做出合理决策 | 不作为工具验收依据 |

**A类案例同时包含阳性和阴性**：
- **阴性案例**：验证工具不误报（架构良好，不应触发告警）
- **阳性案例**：验证工具能发现真正问题（架构违规，应触发告警）

**B类案例的价值**：A类案例验证工具“能不能测对”，B类案例辅助团队“测完了怎么理解和决策”。前者是技术验证，后者是实践应用。

**C类案例的价值**：服务于评估实施者、架构管理者和初学者三类用户——帮助理解告警的工程含义、支持基于数据的架构决策、建立问题模式的识别能力。

> **术语说明**：本案例集中 C 类 Validation 案例与 ASME V&V 标准中的 Validation 概念在本质上是统一的——都是“验证是否满足用户需求”的不同环节。ASME V&V 标准中的 Validation 聚焦于仿真结果的模型误差评估（将仿真结果与实验数据比较）；本案例集 C 类 Validation 聚焦于评估结果在工程决策中的有效性（帮助用户理解告警含义并做出合理决策）。两者针对不同的验证对象，但服务于同一个顶层目标——验证是否满足用户需求。C 类案例是 ASME V&V 标准中 Validation 概念在评估工具验收场景下的自然延伸。

**构造用例与真实工业场景的差距说明**：
构造用例设计为单一违规模式的理想化测试，代码量通常只有几十到几百行，违规模式纯粹可控，用于验证工具检测逻辑的正确性（Verification）。在真实工业场景中，架构问题往往以混合模式出现（如模块边界模糊与耦合逻辑散落同时存在），代码量可达数万至数百万行。建议在完成构造用例验收后，进一步使用 B 类参考案例进行模式识别训练，并逐步在真实项目中验证工具的实用性。

### 原则二：置信度分层验收

- **高置信度规则**（MPR-002、MPR-008、MPR-010）：阳性案例必须 100% 命中，阴性案例误报率必须为 0%
- **中置信度规则**（MPR-001、MPR-003、MPR-005、MPR-007、MPR-009、MPR-012）：允许边界情况下的少量偏差
- **中低置信度规则**（MPR-004）：允许标记为“需人工复核”，不作为阻断性验收条件

## 1. 物理场模块边界清晰度（MPR-001～MPR-003）


### 1.1 模块边界识别（MPR-001）

#### 1.1.1 阴性案例：Kratos Multiphysics 的模块化架构（A类，可复现）

- **项目**：Kratos Multiphysics
- **复现条件**：`git clone https://github.com/KratosMultiphysics/Kratos.git --branch v9.0`
- **架构特征**：Kratos 采用“核心框架 + 应用插件”的模块化架构。核心（`kratos/`）定义了公共框架和基础数据结构，各物理场作为独立的应用（Application）以插件形式存在。
- **检测方法**：扫描 CMakeLists.txt 识别 `add_subdirectory` 目标；检查各物理场应用是否有独立的源代码目录；验证各应用是否可独立编译为动态库。
- **预期输出**：无 MPR-001 告警。各物理场以独立编译单元存在，模块边界清晰。

#### 1.1.2 阳性案例：物理场混杂在同一编译单元（A类，可复现，构造用例）

- **类型**：构造测试用例
- **复现条件**：创建一个包含结构、热、流体三个物理场求解器代码的单一 `.cpp` 文件
- **代码特征**：
  ```cpp
  // 单一编译单元中包含多个物理场，通过条件编译宏切换
  #ifdef STRUCTURAL
  class StructuralSolver { void solve() { /* 结构分析代码 */ } };
  #endif
  #ifdef THERMAL
  class ThermalSolver { void solve() { /* 热分析代码 */ } };
  #endif
  #ifdef FLUID
  class FluidSolver { void solve() { /* 流体分析代码 */ } };
  #endif
  ```
- **预期输出**：
  ```
  [MPR-001] 物理场模块边界识别 (HIGH) [置信度: 中] [类别: A类阳性-构造用例]
  问题: 结构、热、流体求解器混杂在同一编译单元中
  建议: 将每个物理场模块拆分为独立的编译单元。
  ```

  ```
  问题2: 未检测到最大迭代次数限制
  建议: 增加误差容忍度参数（不应低于机器精度的10倍，双精度约为1e-14）和最大迭代次数限制（建议 ≤ 200）。
  ```
