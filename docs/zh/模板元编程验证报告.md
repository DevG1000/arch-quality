## 三、修复的 Bug（4.0 周期）

### 3.1 MLR-022 递归模板漏报

**问题**: 正则 `template<[^>]*>` 无法匹配 `struct fold_impl<-1,First,...> : fold_impl<...>`

**修复**: 去掉 `template<...>` 前缀，改用 `(?!\w)` 确保完整类名 + 注释过滤

**效果**:
| 项目 | 修复前 | 修复后 |
|:----|:-----:|:-----:|
| Boost.MPL | MLR-022 未触发 | 99 处真阳性 |
| 假阳性（`string.hpp` `nttp.hpp`） | 5 处 | 0 处 |

### 3.2 MLR-014 假阳性过滤

**问题**: 匹配了 typedef、using、函数参数等非实例化上下文

**修复**: 上下文正则过滤 + extern template 降级

**效果**（deal.II）:
| 指标 | 改进前 | 改进后 |
|:----|:-----:|:-----:|
| 匹配总数 | 94,501 | 94,501 |
| 上下文过滤 | — | 42,479 (45%) |
| 参数类型过滤 | — | 22,707 (24%) |
| per-template extern 排除 | — | 43 |
| MLR-014 违规 | 3,043 | **1,320 (↓57%)** |

### 3.3 FileIndex 性能优化

**问题**: `Path.rglob("*")` 遍历 178K 文件极慢，LLVM 5分钟超时。

**修复**: 用 `os.walk` + `LANG_MAP` 过滤替换，惰性 lines 计数。

**效果**: LLVM 178K 文件扫描从 >5min 降至 **11.7s**。

### 3.4 Include 图 O(n²) → O(1)

**问题**: 每个 `#include` 线性扫描全部节点做后缀匹配。56K节点 × 270K include = 151亿次比较。

**修复**: `norm_lookup` + `stem_lookup` 哈希表 O(1) 查找。

**效果**: LLVM 从 >30min 超时降至 **52s**。

### 3.5 权重解析混入校准表

**问题**: `load_weights_from_skill` 匹配 §8.1 校准表的 `重复率 40%`，导致权重和 175%。

**修复**: 只解析 `## 权重分配` 段落。

### 3.6 报告 `--json --md` 互斥

**问题**: `if not args.md` + `if not args.json` 导致两参数同时传入时都不输出。

**修复**: 改用 `output_json = args.json or not args.md`。
