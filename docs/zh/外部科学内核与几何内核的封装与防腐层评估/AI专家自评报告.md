## 角色 A：架构专家

**评审维度**：逻辑完整性、分层一致性、层级递进关系

**发现**：
1. **[P0] 内网文本混入错别字与虚构工具名**：设计依据 §2.2 出现虚构工具名"**Mephisto 类工具链**"（无真实来源）；§4.3 表格"**类拉版守卫**"系"标准版本守卫"笔误。**已修正**：删除虚构工具名、改"标准版本守卫（ACL-010）"。
2. **[P1] ACL-001/007 高置信度 ERROR 的依赖前提需显式声明**：两者均依赖 wrapper/import-export 白名单配置。指南 §7.2 门禁设置已注明"白名单配置正确为前提"，但 §2.1/§2.3 置信度说明应同步强调——**已核对**，两处均已注明"白名单需项目配置正确"。
3. **[P2] 递进扣分取"更严格"的语义**：指南 §2.4 写"两基础层取更严格（任一 < 60 即折半）"，与设计依据 §2.1 一致。建议 WP-4 实现时以代码注释强调该语义，避免实现为"两基础层都 < 60 才折半"。

## 角色 B：业务专家

**评审维度**：行业经验覆盖、术语准确性、真实场景

**发现**：
1. **[P0] Evans 原书年份有误**：设计依据 §4.4 与指南 §2.1 引用"Evans (2004)"，DDD 原书实为 **2003** 年出版。**已修正**为 2003。
2. **[P1] SALOME GEOM 的 ACL-002 预期"中违规范"需复核**：GEOMImpl 对冷门内核 API 的直连比例未经实测，作为 A 类预期可能偏高/偏低。已标注为"作校准点"，留 WP-4 B3.5 实测校准。
3. **[P2] OCCT A-1 的 ACL-006 round-trip 断言偏强**：`TKDETEST` 是否覆盖全部数据类型往返无法静态确认，案例集已改为"预期命中，B3.5 实测确认"，避免未经实测的强断言。

## 角色 C：验证专家

**评审维度**：可验证性、可复现性、实施路径

**发现**：
1. **[P1] 覆盖矩阵 ACL-009 仅有合成用例**（A 类 OCCT/SALOME 未覆盖公差换算魔法因子），与指南"12 条规则每条 ≥1 用例"口径一致（合成正反例即满足），但建议 WP-4 B3.5 实测对 OCCT 公差上下文补充验证信号。
2. **[P2] C-2 案例缺"整改后工具响应量化"的前后对比**：已给出综合分 55 → 74，与 GCS C-1 先例一致，可接受。
3. **[P2] 合成案例 4.1 正例的 `MatShape::wrap()` 依赖 wrapper 目录白名单**：若项目未配置白名单，正例也可能被 ACL-001 误报。已在指南 §7.2 注明白名单配置前提，案例集正例注释已标注"wrapper 目录白名单内"。

## 角色 D：标准专家

**评审维度**：ISO 标准、行业标准一致性

**发现**：
1. **[P1] DDD 防腐层的标准领域属性需注明**：防腐层（Evans 2003）是 DDD 战术模式而非 ISO 标准，指南"行业标准映射"表将其列为标准之一，属"领域标准/方法论"性质，建议标注"领域方法论"以免与 ISO 标准混淆。**已核对**，映射表以"行业标准映射"标题涵盖领域方法论（GCS 先例同样含 OCCT 数据模型），接受现状。
2. **[P2] ISO 10303 各 AP 版本语义差异**：AP203（配置管理）/AP214（汽车）/AP242（新一代聚合）已在注释中体现，无需展开。
