# 外部内核防腐层评估 Skill — 场景与提示词应用

> **文档编号**：ACL-C5-技能场景与提示词应用
> **说明**：介绍 `anti-corruption` 技能（外部科学内核与几何内核的封装与防腐层评估）的适用场景与用户交互提示词应用方式
> **关联文档**：《外部科学内核与几何内核的封装与防腐层评估指南（1.3版）》《外部科学内核与几何内核的封装与防腐层评估用户交互提示词模板》
> **对应智能体**：`architecture-quality`

---

## 一、适用场景（Skill 定义）

ACL 技能在**检测到外部内核/数据交换标准引用**时自动启用，覆盖 4 类场景：

| 场景 | 用户诉求 | 对应维度 |
|:-----|:---------|:---------|
| **外部内核封装审计** | 评估 CAD/CAE 平台的外部内核（OCCT/CGAL）wrapper 质量、升级影响面 | 外部内核访问防腐（30%）|
| **类型泄漏排查** | 检查 `TopoDS_Shape`/`Handle_*` 是否从 wrapper 公开接口泄漏到业务层 | 外部内核访问防腐 |
| **数据交换防腐** | 检查 STEP/IGES/IFC 读写是否集中在 import/export 模块、错误是否处理 | 数据交换防腐（30%）|
| **升级可行性评估** | 评估升级 OCCT 内核时的影响文件范围、版本守卫缺口 | Wrapper 覆盖与演进守卫（15%）|

触发信号（满足任一）：源码含 `TopoDS_/Handle_/BRep*/CGAL/STEPControl_*/IGESControl_*/IFC/OCC_VERSION`，或路径含 `wrapper/import-export/防腐/occt`。

**不适用**：不接入任何外部内核/数据交换标准的纯业务代码（引擎返回 `is_acl=false`）。

## 二、7 个提示词模板（怎么用）

在 OpenCode 中对 `architecture-quality` 智能体直接粘贴以下提示词，把 `[项目路径]` 换成实际路径：

### 1. 基础评估 —— 快速体检

```
请对 [项目路径] 执行外部科学内核与几何内核的封装与防腐层评估，
汇报 4 维得分和 ACL 违规清单。
```

> 适用：日常体检、首次接触。返回 overall + 4 维 + 违规清单。

### 2. 单维度分析 —— 深挖访问防腐

```
请分析 [项目路径] 的外部内核访问防腐（external_access）：
业务层是否绕过 wrapper 直连内核 API？wrapper 公开签名是否泄漏内核类型（TopoDS_/Handle_）？
内核调用失败（IsDone/异常）是否被封装层捕获？
```

> 适用：锁定"直连/泄漏/错误处理"三个子项的具体问题。

### 3. ACL 规则排查 —— 单规则溯源

```
请检查 ACL-00X（规则名称）在 [项目路径] 中的具体情况，
说明违规的影响范围和建议修复方式。
```

> 示例：`请检查 ACL-007（STEP/IGES/IFC 读写防腐）...哪些文件在 import/export 模块外直接使用 STEPControl_*`
> 适用：对某条 ERROR/WARNING 违规追根溯源到具体文件。

### 4. 改进建议 —— 可落地整改

```
请基于最近一次评估结果，给出 [项目路径] 外部内核防腐层改进建议，
按 P0/P1/P2 优先级分级，并预估每项改进的得分提升空间。
```

> 适用：规划重构投入、给团队排优先级。

### 5. 历史对比 —— 防退化

```
请将 [项目路径] 的当前防腐层得分与历史基线对比，
报告得分偏移和 ACL 违规变化，判断是否出现退化。
```

> 适用：CI 回归守护、版本迭代后复查。

### 6. 专项审查 —— 5 项合规检查

```
请审查 [项目路径] 是否满足以下外部内核防腐专项要求：
- wrapper 目录是否收敛全部内核调用（无业务层直连 TopoDS_/BRep*）
- STEP/IGES/IFC 读写是否集中在 import/export 模块
- reader/writer 调用点是否检查 IFSelect_ReturnStatus
- 是否存在 round-trip 往返保真度测试
- 是否声明外部标准版本（AP203/214/242）守卫
```

> 适用：架构评审、技术尽调。

### 7. 内核升级影响面 —— 升级决策

```
请评估 [项目路径] 升级其外部内核（OCCT 等）时的影响面：
基于 ACL-001/002/003 违规情况，估算被业务层直连的内核 API 数量，
并建议 wrapper 收敛与版本守卫（#if OCC_VERSION）的改造范围。
```

> 适用：内核升级前的风险评估。

## 三、推荐使用流程

```
1 (体检)  → 2 (定位维度) → 3 (溯源规则) → 4 (排优先级)
                              ↓
                          6 (合规审查) / 7 (升级影响面)
                              ↓
                     5 (迭代后对比基线防退化)
```

**实战示例**：
- `salome-geom`：任务 1→7 全跑，发现 ACL-007"散落"实为 `STEPPlugin` 白名单漏识别
- `occt`：任务 6/7 专项，发现 `#if OCC_VERSION` 仅 1 处、升级影响 1,911 文件

---

## 四、注意事项

1. **内核自身 vs 消费方**：若被评估对象**就是内核**（如 OCCT 源码），ACL-001/002/004 会失真（定义者≠违规者）——需在报告中按"双层判读"处理，或加 `@acl_exempt` 排除
2. **门禁**：ACL-001/007 是 ERROR 级可阻断——仅当 wrapper/import-export 白名单配置正确时启用
3. **路径提醒**：评估前确认路径存在（如 `D:/opensource/OCCT` 实际是 `D:\opensource\gcs-baselines\occt`）
4. **底层命令**：提示词由智能体转译为 `python -m arch_quality.arch_metrics_anti_corruption <path> --json`，也可直接执行
