## 1. 设计概览

### 1.1 设计目标

实现指南定义的 4 维评分模型与 12 条 ACL 规则的**静态分析检测**，对通过防腐层接入外部内核（OCCT/CGAL 等）与外部标准数据交换（STEP/IGES/IFC）的项目的"封装与防腐形态"进行可复现、可门禁的量化评估。

### 1.2 架构定位

- 作为 `ComprehensiveReport` 的**结构质量增强维度**（引擎键 `anti-corruption`），通过 profile 引擎集启用
- 遵循 `arch-core` 框架标准模式：`FileIndex` 扫描 → `_detect_acl()` 启用判定 → 4 维 `calc_xxx()` → `check_acl_rules()` → `all_metrics()`
- 与既有引擎（multilang/template/numerical/solver_physics/geometry_consistency）并行，不共享状态

### 1.3 技术选型

| 项 | 选择 | 理由 |
|:---|:-----|:-----|
| 语言 | Python 3.10+ | 与 arch-quality 框架一致 |
| 扫描 | `FileIndex` + `read_text_smart` | 复用既有缓存与编码兼容 |
| 检测 | 正则 + 外部符号清单 + 白名单 + 统计 | 对齐指南置信度分级（精确匹配→高，结构→中，启发式→低）|
| 权重 | `load_weights_from_skill` 运行时解析 | 与 Skill 文件权重一致，禁止硬编码 |
| 防腐边界 | wrapper/import-export 目录白名单（可配置）| 对齐 Skill §6 外部符号清单 |

## 2. 整体架构

### 2.1 类结构

```
AntiCorruptionMetrics
├── __init__: FileIndex + _detect_acl + _scan_files + 防腐边界目录
├── calc_external_access()      # 维度1（30%）：ACL-001/004/005
├── calc_wrapper_coverage()     # 维度2（15%）：ACL-002/003
├── calc_data_exchange()        # 维度3（30%）：ACL-007/011/012
├── calc_fidelity()             # 维度4（25%，含递进扣分）：ACL-006/008/009/010
├── check_acl_rules()           # 12 条 ACL 规则
└── all_metrics()               # 综合输出
```

### 2.2 缓存机制

- `_dims_cache`：维度结果缓存（`_calc_cached`），避免 `check_acl_rules` 重复计算 4 维
- 进程内内容由 `read_text_smart(use_cache=True)` 提供（mtime 失效）

### 2.3 数据流

```
FileIndex 扫描 → _detect_acl（前 300 文件信号预筛）
  → _scan_files 预读全部源码内容（豁免注解从原始内容采集）
  → 4 维 calc_xxx（每维正则统计，防腐边界白名单判定）
  → check_acl_rules（复用维度 detail）
  → all_metrics（加权综合分 + acl_violations + waiver_audit）
```

### 2.4 性能优化

- 启用预筛：非 ACL 项目**零成本**返回（不读文件）
- 单遍扫描：`_scan_files` 一次性缓存全部内容，各维度共用
- 第三方依赖目录跳过（`third_party`/`vendor` 等），减少误报与耗时
- 防腐边界目录判定为路径级（`Path(rel).parts` 检查），O(1) 每文件

## 3. 维度 1：外部内核访问防腐（30%）映射

### 3.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| 无直连内核 API（wrapper 白名单外无内核符号）| 40 | 高 |
| 内核类型无泄漏（wrapper 公开签名隔离）| 30 | 中 |
| 内核调用失败已封装（区分异常型/状态码型）| 30 | 中 |

### 3.2 工具实现映射（检测正则级）

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| 直连内核 API | wrapper 白名单外符号统计 | `RAW_KERNEL_USE_RE`: `\b(TopoDS_|BRep[A-Za-z_]*|Handle\s*\([^)]+\)|CGAL)\b`；跳过 wrapper 目录内文件 |
| 类型泄漏 | wrapper 公开头文件签名 | `PUBLIC_SIG_LEAK_RE`（返回类型 `TopoDS_/Handle(` 开头函数）+ `TYPE_LEAK_RE`（public/protected 内签名出现外部类型）|
| 错误处理封装 | 调用点紧邻检查 | `KERNEL_CALL_STMT_RE`（BRep*API 构造）+ 调用后 400 字符查 `ERROR_CHECK_RE`（IsDone/IsValid/catch/IFSelect）；**格式调用点排除**（`FORMAT_CALL_RE`，专家校对 P1-2 修订）|

### 3.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| ACL-001 依赖 wrapper 目录白名单 | 防腐边界是项目配置，非通用信号 | 提供目录白名单可配置（`wrapper_dirs` 参数 + 默认常见名）；白名单配置错误会误报——指南 §7.3 门禁注明前提 |
| ACL-004 仅解析"签名形态" | 静态 AST 解析成本高 | 正则匹配 public 签名返回类型 + 参数中的外部类型；私有实现内类型不判（不误报）|
| ACL-005 仅判定"紧邻失败检查" | 跨函数失败传递静态不可追踪 | 窄化 400 字符窗口降低误报；封装级/助手级检查静态不可判（KNOWN_HOLES，对齐 GCS-003 先例）|

## 4. 维度 2：Wrapper 覆盖度与演进守卫（15%）映射

### 4.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| 核心 API wrapper 覆盖度 | 50 | 低 |
| 内核版本守卫存在性 | 50 | 低 |

### 4.2 工具实现映射

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| 覆盖度 | 核心类清单 vs wrapper 声明 | `CORE_KERNEL_CLASS_RE`（12 个 OCCT 高频类）+ `CORE_KERNEL_DECL_RE`（wrapper 目录声明比对）；覆盖度 = 交集/并集，阈值 0.6 |
| 版本守卫 | 条件编译存在性 | `GENERIC_VERSION_GUARD_RE`: `#\s*if\s+(?:defined\s*\(\s*)?(?:[A-Z_]+_VERSION\|OCC_VERSION)\b` |

### 4.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| 覆盖度依赖核心类清单人工维护 | 外部内核 API 面广，全量跟踪成本高 | 固定 12 类高频核心类清单（skill-audit P1 观察），作为已知漏报源登记 |
| 覆盖度阈值 0.6 为初值 | 需真实项目校准 | WP-4 校准记录登记（对齐 GCS 阈值校准纪律）|
| 版本守卫仅测"存在性" | "守卫覆盖全部版本差异点"无法静态判定 | 低置信度 INFO；密度过低提示仅在规则 detail 中给出（不强阻断）|

## 5. 维度 3：数据交换防腐（30%）映射

### 5.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| STEP/IGES/IFC 读写集中（专用模块外无直出）| 45 | 高 |
| 导入导出错误已处理 | 30 | 中 |
| 无格式直连（引用密度阈值内）| 25 | 中 |

### 5.2 工具实现映射

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| 读写防腐 | import/export 模块外格式符号统计 | `FORMAT_SYMBOL_RE`: `\b(STEPControl_[A-Za-z_]+|IGESControl_[A-Za-z_]+|IFSelect_[A-Za-z_]+|IFC[A-Za-z_]*)\b`；跳过 import/export 目录内文件 |
| 错误处理 | reader/writer 对象读写调用检查 | `READER_OBJ_RE`/`WRITER_OBJ_RE` 识别对象 + 调用后 800 字符查 `IFSelect_RetDone`/catch（`RET_STATUS_CHECK_RE`）|
| 直连密度 | 格式符号密度统计 | `FORMAT_USE_RE` 命中文件 vs import/export 目录外文件；密度 = outside/format，阈值 0.30 |

### 5.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| ACL-007 vs ACL-012 信号重叠（专家校对 P1-1）| 两者都以"白名单外格式符号"为信号 | 明确：ACL-007 管**姿态/位置**（ERROR），ACL-012 管**密度计数**（WARNING，仅散落场景叠加）——避免同一散落 ERROR+WARNING 双扣 |
| ACL-011 仅判定紧邻窗口 | 错误检查可延迟到函数尾部 | 800 字符窗口内查 RetDone/catch；窗口后延迟检查不判（降低误报）|
| 直连密度阈值 0.30 为初值 | 需真实项目校准 | WP-4 校准记录登记 |

## 6. 维度 4：保真度与外部标准一致性（25%）映射

### 6.1 指南算法原文

| 检查项 | 分值 | 指南置信度 |
|--------|:----:|:----------:|
| round-trip 往返保真度测试存在（加分项）| 40 | 高 |
| 单位换算无魔法因子（集中工具函数）| 20 | 低 |
| 公差换算无魔法因子 | 20 | 低 |
| 外部标准版本守卫 | 20 | 低 |

### 6.2 工具实现映射

| 检查项 | 实现模式 | 关键正则/逻辑 |
|--------|---------|--------------|
| round-trip | 存在性检测 | `ROUND_TRIP_RE`（round_trip/roundtrip/write_read 等标识）+ `WRITE_READ_ASSERT_RE`（writer+reader+assert 组合模式）|
| 单位换算 | 魔法因子启发式 | `EXCH_UNIT_FACTOR_RE`: `\b(25\.4|0\.0254|3\.28084|0\.3048|2\.54|1\.60934|0\.0393701)\b`；`EXCH_UNIT_FUNC_RE`（convert/unit::/to_mm 等，命中即豁免）|
| 公差换算 | 魔法因子启发式 | `TOL_FACTOR_RE`: `\b(0\.0254|0\.001|0\.0001|1e-\d+)\b`；`TOL_FUNC_RE`（tolerance/SetTolerance）|
| 标准版本守卫 | 声明/守卫存在性 | `AP_VERSION_RE`: `\bAP-?(203\|214\|242)\b`；`STEP_PROFILE_SET_RE`（SetProfile/SetCVal("write.step...")/SUPPORT_APxxx）|

### 6.3 工程化偏差

| 偏差 | 原因 | 处置 |
|:-----|:-----|:-----|
| ACL-006 测"存在性"不测"覆盖率" | 测试覆盖广度无法静态确认 | 定位为**加分项**（存在加分、缺失 INFO 提示）；置信度高的恰当组合 |
| 单位/公差魔法因子启发式可能误报科学常数 | 25.4 等也可能是合法物理常数 | 低置信度 INFO；同文件有统一换算函数（`EXCH_UNIT_FUNC_RE`/`TOL_FUNC_RE`）即豁免 |
| 递进扣分联动（指南 §2.4）| 基础层防腐缺失 → 保真度无意义 | 实现"任一基础层（2.1/2.3）< 60 → 2.4 折半"，在 detail 输出 `progressive_deduction` |

### 8.2 一致性检查方法

- `scripts/consistency_check.py --engine anti_corruption`：验证指南 ↔ Skill ↔ 工具三方的规则 ID 集（12 条连续）、版本绑定（GUIDE_VERSION=1.3/SKILL_VERSION=1.0）、维度命名、案例集关键词
- `calc_overall`/`all_metrics` 权重和 = 100% 由 `load_weights_from_skill` 强制
- `check_acl_rules` 的 rule ID 与 `calc_xxx` detail 键一一对应（§7 对齐表）

### 8.3 已知局限

| 局限 | 影响 | 处置 |
|:-----|:-----|:-----|
| 核心类清单 12 类人工维护 | ACL-002 覆盖度漏报冷门核心 API | 作为已知误报源登记；案例集 B3.5 校验 |
| 白名单目录名启发式（wrapper/import-export 默认名）| 非常规目录名漏检 | 提供 `wrapper_dirs`/`import_export_dirs` 显式配置 |
| 科学内核符号（PETSc/deal.II 等）| 维度⑧ 当前版仅几何内核 + 数据交换（WP-3 处置 b）| 作用域声明明确，科学内核符号集列入后续版本 |
