## 一、设计原则

| 原则 | 说明 |
|:-----|:------|
| **中国时间基准** | 所有日期、文件名、记录时间均以 UTC+8 为准 |
| **与系统时间解耦** | 不依赖系统时区设置，脚本内强制使用中国时间 |
| **自动提取** | 从日报自动生成知识库条目，减少人工操作 |
| **Git 管理** | 知识库与项目同仓库管理，可 diff、可回溯 |

## 三、文件命名与时间规范

### 3.1 日期来源

```python
from datetime import datetime, timezone, timedelta
CHINA_TZ = timezone(timedelta(hours=8))

def today_china():
    """返回中国当前日期 YYYY-MM-DD"""
    return datetime.now(CHINA_TZ).strftime('%Y-%m-%d')
```

所有文件命名中的日期必须使用此函数生成，严禁使用 `date.today()` 或系统默认时区。

### 3.2 文件命名对照

| 文件 | 命名规则 | 示例 |
|:-----|:---------|:------|
| 日报文件名 | `dailyreport{日期}.md` | `dailyreport2026-06-24.md` |
| 知识库亮点 | `{日期}.md` | `2026-06-24.md` |
| 评审材料 | `{描述}.md` | `评审结论.md` |

### 3.3 内容中的时间标记

日报和知识库文件头部的日期、评估报告中的时间戳，均使用中国时间：

```markdown
# 每日工作总结 — 2026-06-24        ← 中国日期
**日期**: 2026-06-24 17:30:00 CST   ← 中国时间 + 时区标记
```

### 5.3 每日亮点自动提取

`extract_highlights.py` 脚本：

```bash
# 手动运行（提交前）

# 使用中国时间
```

4. 输出到 `daily-highlights/YYYY-MM-DD.md`

## 六、时区处理代码

### 6.1 中国时间工具函数

在所有需要日期时间的脚本中统一使用：

```python
from datetime import datetime, timezone, timedelta

CHINA_TZ = timezone(timedelta(hours=8))

def now_china() -> datetime:
    """获取当前中国时间"""
    return datetime.now(CHINA_TZ)

def today_china() -> str:
    """获取中国日期字符串 YYYY-MM-DD"""
    return now_china().strftime('%Y-%m-%d')

def now_china_str() -> str:
    """获取中国时间字符串 YYYY-MM-DD HH:mm:ss"""
    return now_china().strftime('%Y-%m-%d %H:%M:%S')
```

## 七、FAQ

### Q1: 为什么不用系统时区？

系统可能设置为 UTC，而团队在中国时间工作。所有日期相关操作必须显式指定中国时区，避免跨时区协作时产生日期混淆。

### Q2: 日报和历史记录如果跨时区怎么办？

日报以**中国日期**为准。如果团队在其他时区工作，日报日期以工作结束时的中国时间为准。

### Q3: 知识库是否可以多人协作？

知识库文件是纯 Markdown + Git 管理，天然支持多人协作。按标准 Git 流程提交 PR 即可。
