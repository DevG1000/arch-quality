# 数值算法正确性与精度保障评估指南（1.7版）

> 本指南参照《软件架构质量评估指南》及《模板元编程与编译时依赖膨胀评估指南》的结构编写，定义了一套专门用于评估工业软件中数值算法正确性与精度保障的架构质量指标体系。适用于 CAD/CAE/CAx/CFD 等涉及大量数值计算的工业软件场景。
>
> **行业标准映射**：本指南的评估框架基于 ASME V&V 20-2009（计算流体力学与传热验证与确认标准）、ASME V&V 10-2019（计算固体力学验证与确认标准）及 ISO 17534-1:2015（声学计算软件质量要求与质量保证标准）构建。
>
> **1.7 版核心更新**：参照《软件架构质量评估指南（2.3版）》的做法，为所有评估子维度和内置规则增加**置信度标注**，明确区分“精确测量”“结构化检查”与“启发式检测”三类检测方法，帮助用户理解各指标的可靠程度和适用场景。


## 概述

**数值算法正确性与精度保障**是指：在工业软件中，数值算法（包括线性方程组求解、数值积分、微分方程离散、几何求交、优化迭代等）在有限精度计算环境下，能够正确实现其数学定义、保持数值稳定性、控制误差累积，并输出满足工程精度要求的结果的能力。

在工业软件（CAD/CAE/CAx/CFD）中，数值算法是仿真与设计决策的数学基础。然而，传统架构质量评估模型（ISO 25010、CK 度量集）仅关注代码结构与运行时行为，完全忽略数值算法的正确性与精度属性，导致“代码逻辑正确但数值结果错误”的架构债务无法被量化。

本指南作为《软件架构质量评估指南》的补充，定义了一套专门针对数值算法正确性与精度保障的评估指标。这些指标可纳入**结构质量**中的可靠性子维度（建议权重占结构质量的 10%~15%），也可作为工业软件场景下的独立评估项。

**评估目标**：量化数值算法带来的正确性风险与精度退化债务，识别数值不稳定、舍入误差敏感、验证缺失等架构风险，提升仿真结果的可信度与工程决策的有效性。


## 置信度说明

本指南中的每个评估子维度均标注**检测置信度**，用于说明该维度评分的可靠程度。置信度分为三级：

| 置信度 | 含义 | 典型检测方法 | 示例 |
|--------|------|-------------|------|
| **高** | 检测结果精确可靠，无需人工复核 | 精确测量（行数统计、AST 精确匹配、配置文件解析） | NVR-003 灾难性抵消的静态模式识别 |
| **中** | 检测结果可靠，但存在边界情况需关注 | 结构化检查（关键词存在性检查、AST 模式匹配） | NVR-001 隐式格式检测、NVR-005 MMS 测试用例存在性检查 |
| **低** | 检测结果为启发式推断，需人工复核确认 | 启发式检测（正则匹配、模式推断） | NVR-004 的静态累加次数推断 |

**使用建议**：
- 高置信度规则的告警应**强制处理**，误报率极低。
- 中置信度规则的告警应**优先处理**，但在边界场景（如非常规编码风格）可能存在误报。
- 低置信度规则的告警应**由人工复核**后决定是否处理，不作为阻断性门禁的唯一依据。


## 一、子维度与权重分配

数值算法正确性与精度保障评估由以下 **6 个子维度** 加权合成：

| 子维度 | 权重 | 对应风险类型 | 置信度 |
|--------|------|-------------|--------|
| 数值稳定性保障 | 25% | 算法缺乏稳定性机制，在病态输入下结果失稳 | **中** |
| 舍入误差与数值敏感度控制 | 20% | 浮点累加误差、灾难性抵消、精度退化 | **中低** |
| 代码验证完备性 | 20% | 缺乏制造解验证（MMS），算法实现正确性未确认 | **中** |
| 解验证与误差量化 | 15% | 离散化误差、迭代误差未估计，解的精度未知 | **中** |
| 数值回归测试覆盖 | 10% | 关键数值模块缺乏回归测试，变更引入精度退化 | **高** |
| 数值技术债务密度 | 10% | 历史积累的数值不稳定代码占比 | **高** |

**置信度说明**：
- **数值稳定性保障（中）**：基于 AST 和配置文件解析检测稳定性机制的存在性，检测逻辑清晰但依赖代码编写风格的一致性。
- **舍入误差控制（中低）**：静态模式识别（中） + 运行时动态分析建议（高），混合置信度。
- **代码验证完备性（中）**：检查 MMS 测试用例是否存在，依赖测试文件命名规范和目录结构约定。
- **解验证与误差量化（中）**：检查误差量化报告是否存在，依赖文档和配置的结构化程度。
- **数值回归测试覆盖（高）**：基于精确的文件统计和路径匹配，检测结果可靠。
- **数值技术债务密度（高）**：基于其他规则的汇总统计，计算过程精确可复现。


## 二、子维度定义与评分算法

### 2.1 数值稳定性保障

**定义**：衡量数值算法是否具备必要的稳定性保障机制。工业软件的数值算法应通过算法设计（隐式格式、迎风格式等）或运行时检查（CFL 条件）来确保数值稳定，而非依赖用户经验或试错。

**置信度**：中

**设计依据**：
- 数值分析经典理论：隐式格式无条件稳定，显式格式受 CFL 条件约束
- ASME V&V 20-2009 将验证标准不确定度与数学模型的误差作为核心评估对象
- 工业案例：显式时间推进在 CFL 条件不满足时发散；无主元高斯消元在病态矩阵下失败

**评分算法**：

本规则采用**静态代码分析**方式，检查算法是否具备以下稳定性机制。检测结果分为三级：

| 检测结果 | 评分 | 说明 |
|---------|------|------|
| **PASS** | 100 | 发现至少一种有效的稳定性保障机制 |
| **WARNING** | 50 | 部分机制存在但不完整（如显式格式有 CFL 检查但未配置） |
| **FAIL** | 0 | 未发现任何稳定性保障机制 |

**稳定性机制检测项**：

| 检测项 | 检测方法 | 说明 | 置信度 |
|--------|---------|------|--------|
| **隐式格式** | 检测 `fvm::ddt`、`solve(implicit)`、`EulerImplicit` 等关键词 | 隐式格式通常无条件稳定，是最高等级的稳定性保障 | **高** |
| **CFL 条件检查** | 检测 `Co` 数计算、`adjustTimeStep`、`maxCo` 等配置 | 显式格式的必要保障措施 | **高** |
| **迎风格式** | 检测 `upwind`、`linearUpwind`、`bounded` 等数值格式选择 | 对流占优问题的稳定格式 | **中** |
| **人工粘性/限制器** | 检测 `artificialViscosity`、`limiter`、`slopeLimiter` 等关键词 | 中心差分格式的必要补充 | **中** |
| **源项线性化** | 检测 `SuSp`、`SemiImplicitSource`、`sourceImplicit` 等关键词 | 刚性源项问题的隐式处理 | **中** |
| **稳定性注解** | 检测 `// @stability_assured` 等开发者注解 | 为特殊场景提供人工确认机制 | **高** |

**置信度说明**：
- **高**：隐式格式关键词、CFL 配置、稳定性注解均为精确匹配，误报率极低。
- **中**：迎风格式、限制器、源项线性化的检测依赖命名约定（如 `upwind` 可能以多种形式出现），在非常规命名风格下可能漏报。

**评分规则**：
- 检测到**隐式格式** → 直接 PASS（隐式格式在大多数情况下无条件稳定）
- 显式格式但检测到 **CFL 条件检查** → PASS
- 检测到**迎风格式**或**人工粘性/限制器** → PASS
- 检测到**源项线性化**（`SuSp`、`SemiImplicitSource`） → PASS
- 检测到**稳定性注解** `// @stability_assured` → PASS
- 显式格式且**无任何稳定机制** → FAIL
- 显式格式且有 CFL 检查但**未配置**（定义为存在但被注释） → WARNING

**代码坏味道：数值失稳（Numerical Instability）**

**1.7 版说明**：原 NVR-001 为“数值不稳定检测”，依赖运行时残差监测，难以在 CI 门禁中落地。新版改为静态检查“算法稳定性机制是否存在”，使其成为可自动化执行的设计规范检查。


### 2.2 舍入误差与数值敏感度控制

**定义**：衡量浮点数累加、灾难性抵消（两个相近数相减）、大数吃小数等基础浮点计算问题是否得到有效管理。

**置信度**：中低（静态分析部分为**中**，动态分析部分为**高**）

**设计依据**：
- **CADNA 库**基于 CESTAC 方法，通过概率方法估计舍入误差传播。
- **Verificarlo** 基于 LLVM 编译时插桩，通过蒙特卡洛算术评估浮点不确定性。
- **Verrou** 基于 Valgrind 动态插桩，通过随机舍入检测浮点误差。Verrou 由 EDF R&D 开发，用于 code_aster 等核工程代码的舍入误差检测。

**置信度说明**：
- **静态模式识别（中）**：识别 `a - b` 模式为启发式检测，存在误报（识别出模式但实际未发生抵消）和漏报（实际发生抵消但模式未被识别）的可能。
- **动态分析（高）**：通过 CADNA/Verificarlo/Verrou 进行的运行时检测结果为精确测量，置信度高。

**工具选择指南**：

| 工具 | 插桩方式 | 适用场景 | 置信度 |
|------|---------|---------|--------|
| **CADNA** | 源代码级（需编译时插桩） | 中小规模程序，需要精确估计有效位数 | **高** |
| **Verificarlo** | LLVM 编译时插桩 | 需要大规模代码覆盖、编译器 flag 影响分析 | **高** |
| **Verrou** | Valgrind 动态运行时插桩 | 大型遗留代码，无需重新编译即可分析 | **高** |

**评分算法**：
```
let S = 舍入误差敏感度评分（通过随机算术方法估计）
    D = 灾难性抵消检测（存在相近数相减则扣分）
    A = 累加误差控制（Kahan求和等）

基础分 = 100
if S < 1e-12: 基础分 -= 20
if D == TRUE: 基础分 -= 25
if A == FALSE: 基础分 -= 15
score = max(0, 基础分)
```

**置信度说明**：
- 灾难性抵消的静态检测（模式识别）为**中**置信度，动态验证（CADNA/Verrou）为**高**置信度。
- 累加误差控制的检测为**中**置信度（依赖 Kahan 求和等特定模式识别）。


### 2.3 代码验证完备性

**定义**：衡量数值算法是否通过制造解方法（Method of Manufactured Solutions, MMS）进行了系统性的代码验证。

**置信度**：中

**设计依据**：
- **制造解方法（MMS）** 是代码验证中最强有力的工具。
- ASME V&V 20-2009 和 V&V 10-2019 均将代码验证作为 V&V 流程的基础环节。

**前提条件**：MMS 验证必须在**至少三套系统加密的网格**上执行，方可计算有意义的观测收敛阶。

**评分算法**：
```
let V = 是否在 ≥3 套加密网格上执行过 MMS 验证（TRUE/FALSE）
    O = 观测收敛阶与理论阶数的偏差

if V == FALSE: score = 0
else if abs(O) <= 0.1: score = 100
else if abs(O) <= 0.2: score = 80
else if abs(O) <= 0.5: score = 50
else: score = max(0, 50 - (abs(O)-0.5)*50)
```

**置信度说明**：
- **MMS 测试用例存在性检查（中）**：通过检测测试目录中是否包含 `*_mms*`、`*_verification*` 等模式命名的文件来判断。依赖命名约定，可能存在漏报。
- **观测收敛阶计算（高）**：若 MMS 测试结果以结构化格式（如 JSON）输出，收敛阶的计算为精确测量。


### 2.4 解验证与误差量化

**定义**：衡量离散化求解过程中产生的数值误差（离散化误差、迭代误差）是否被量化估计。

**置信度**：中

**ASME V&V 20 概念层级说明**：

| 层级 | 概念 | 定义 | 评估方法 |
|------|------|------|---------|
| **验证层面** | 数值误差 δ_num | 模型方程数值求解产生的误差 | 网格收敛性研究、Richardson 外推 |
| **验证层面** | 输入误差 δ_input | 仿真输入参数的误差 | 参数敏感性分析 |
| **确认层面** | 比较误差 E = S - D | 数值解与实验数据的差异 | 实验数据比较 |
| **确认层面** | **确认不确定度 u_val** | 模型误差的最终量化产出 | ASME V&V 20 不确定性聚合方法 |

**评分算法**：
```
let E_d = 离散化误差是否被估计（TRUE/FALSE）
    E_i = 迭代误差是否被估计（TRUE/FALSE）

score = (E_d * 50) + (E_i * 50)
```

**置信度说明**：
- 检测误差量化报告是否存在（**中**）：依赖文档和报告的结构化程度。若项目使用标准化的验证报告格式（如 JSON/YAML），检测置信度可提升至**高**。
- 当前默认置信度为**中**，因误差量化信息可能以自由文本形式存在，难以自动解析。


### 2.5 数值回归测试覆盖

**定义**：衡量关键数值模块是否建立了自动化回归测试。

**置信度**：高

**验证层级概念**（基于 ASME V&V 10-2019）：

| 层级 | 定义 | 本指南对应 |
|------|------|-----------|
| **组件级验证** | 单个求解器的独立验证 | 单个数值算法模块的 MMS 验证 |
| **子系统级验证** | 多个组件耦合的验证 | 多物理场接口的联合验证 |
| **系统级验证** | 完整工程系统的整体验证 | 端到端仿真流程的整体回归测试 |

**关键数值模块判定**：模块满足以下任一条件时，自动标记为关键模块：
1. 条件数 > 1e6（NVR-002 触发，已调整为静态检测）
2. 未通过 MMS 验证（NVR-005 触发）
3. 数值不稳定检测触发（NVR-001 触发）

**评分算法**：
```
let N_critical = 触发 NVR-001 或 NVR-002 或 NVR-005 的模块总数
    N_tested = 上述模块中具有回归测试的模块数
    coverage = N_tested / N_critical

score = coverage * 100
```

**置信度说明**：
- **高**：回归测试的存在性通过精确的文件路径匹配和 CI 配置解析检测，结果可靠。
- 回归测试的基准解管理（版本化、可追溯）通过结构化元数据验证，同样为**高**置信度。


### 2.6 数值技术债务密度

**定义**：衡量历史积累的数值不稳定代码、未验证算法、未量化误差模块在代码库中的占比。

**置信度**：高

**评分算法**：
```
let N_total = 数值算法模块总数
    N_debt = 满足以下任一条件的模块数：
              - 数值稳定性评分 < 50（NVR-001 或 NVR-002 触发）
              - 代码验证评分 = 0（NVR-005 触发）
              - 解验证评分 < 40（NVR-007 或 NVR-008 触发）
    debt_ratio = N_debt / N_total

score = max(0, 100 - debt_ratio * 200)
```

**置信度说明**：
- **高**：债务密度基于其他规则的计算结果汇总统计，计算过程精确可复现，无主观判断。


## 三、数值算法正确性与精度保障综合分

```
数值算法综合分 = 
    数值稳定性保障 × 25% +
    舍入误差与数值敏感度控制 × 20% +
    代码验证完备性 × 20% +
    解验证与误差量化 × 15% +
    数值回归测试覆盖 × 10% +
    数值技术债务密度 × 10%
```

### 规则详细描述

#### NVR-001：算法稳定性机制检查

- **严重级别**：ERROR 或 WARNING
- **检测置信度**：中
- **描述**：检查数值算法是否具备必要的稳定性保障机制。
- **置信度说明**：基于 AST 和配置文件解析检测稳定性机制的存在性，检测逻辑清晰，但对非常规编码风格（如自定义宏封装隐式格式）可能存在漏报。


#### NVR-002：预处理机制检查

- **严重级别**：ERROR 或 WARNING
- **检测置信度**：中
- **描述**：检查大规模矩阵求解是否配置了预条件器或稳定求解器。
- **置信度说明**：配置文件解析精确可靠（**高**），但矩阵规模推断（**中**）和代码模式匹配（**中**）依赖命名约定和配置结构。


#### NVR-003：灾难性抵消检测

- **严重级别**：HIGH
- **检测置信度**：中低
- **描述**：代码中两个相近数相减可能导致有效位数大量损失。
- **置信度说明**：静态模式识别为**中**置信度（存在误报/漏报可能），动态分析（CADNA/Verrou）为**高**置信度。混合置信度，建议优先采用动态分析确认。


#### NVR-004：浮点累加误差检测

- **严重级别**：MEDIUM
- **检测置信度**：中
- **描述**：大量浮点数累加未使用补偿算法，可能导致累加误差累积。
- **置信度说明**：累加次数 > 1000 的判定依赖静态代码分析，存在漏报（循环次数运行时确定）和误报（编译时已知的固定小规模循环）。建议结合运行时 profiling 提高置信度。


#### NVR-005：MMS 验证缺失

- **严重级别**：HIGH
- **检测置信度**：中
- **描述**：数值算法模块未通过制造解方法进行代码验证。
- **置信度说明**：通过检测测试目录中是否包含 `*_mms*`、`*_verification*` 等模式命名的文件来判断。依赖命名约定，在非常规命名风格下可能漏报。若项目使用标准化的测试用例注册机制，可通过解析测试注册表提升至**高**置信度。


#### NVR-006：观测收敛阶偏差过大

- **严重级别**：HIGH
- **检测置信度**：高
- **描述**：MMS 验证中观测收敛阶与理论阶数的偏差超过 0.2。
- **置信度说明**：若 MMS 测试结果以结构化格式（如 JSON）输出，收敛阶计算为精确测量。若为自由文本输出，需人工解析，置信度降为**中**。默认按结构化格式处理。


#### NVR-007：离散化误差未量化

- **严重级别**：MEDIUM
- **检测置信度**：中
- **描述**：数值解的离散化误差未被量化估计。
- **置信度说明**：依赖文档和报告的结构化程度。若项目使用标准化的验证报告格式（如 JSON/YAML），检测置信度可提升至**高**。


#### NVR-008：迭代误差未估计

- **严重级别**：MEDIUM
- **检测置信度**：中
- **描述**：迭代求解器的迭代误差未被估计。
- **置信度说明**：同 NVR-007。


#### NVR-010：数值回归测试缺失

- **严重级别**：MEDIUM
- **检测置信度**：高
- **描述**：关键数值模块缺乏自动化回归测试。
- **置信度说明**：通过精确的文件路径匹配（如 `test/`、`tests/`、`*_test.*` 等模式）和 CI 配置解析检测，结果可靠。


#### NVR-011：回归测试精度阈值缺失

- **严重级别**：LOW
- **检测置信度**：高
- **描述**：数值回归测试未定义可接受的精度偏差范围。
- **置信度说明**：通过解析回归测试配置文件（如 `*.toml`、`*.yaml`、`*.json`）中的阈值字段检测，精确可靠。


#### NVR-012：数值债务密度超标

- **严重级别**：LOW
- **检测置信度**：高
- **描述**：数值技术债务密度超过 30%。
- **置信度说明**：基于其他规则的汇总统计，计算过程精确可复现。

## 七、实施建议

1. **工具集成**：
   - 数值稳定性检查：实现基于 AST 的静态分析
   - 预处理检查：解析 `fvSolution` 等配置文件
   - 舍入误差分析：集成 CADNA、Verificarlo 或 Verrou
   - 代码验证：支持 MMS 测试框架的自动化执行

2. **门禁设置**：
   - NVR-001 和 NVR-002 采用三级评分：PASS（通过）、WARNING（警告）、FAIL（阻断）
   - 高置信度规则（NVR-006、NVR-010~012）：建议强制阻断
   - 中低置信度规则（NVR-003、NVR-004）：建议触发人工复核，而非自动阻断
   - 数值算法综合分 < 50 时阻止合并

3. **置信度使用指南**：
   - 工具应明确标注每条告警的置信度等级
   - 低置信度告警应在报告中标注“建议人工复核”
   - CI 门禁中，高置信度规则的权重应高于低置信度规则

4. **注解豁免机制**：
   - `// @stability_assured`：豁免 NVR-001 检查
   - `// @preconditioner_configured`：豁免 NVR-002 检查
   - `// @small_scale_problem`：标记小规模问题，豁免 NVR-002 的预处理要求
