## 二、维度定义与评分算法

每个维度包含：代码坏味道名称、检测方法、评分算法。评分算法从指南的文字描述中提取为可执行的分段函数。

### 2.1 几何内核数据一致性（30%）

**代码坏味道：** "内核对象生命周期失控（Kernel Object Lifetime Escaping）"——内核对象以裸 new/裸指针跨作用域传递或手动管理，异常/失败状态未被检查。

**检测方法：**
- 内核类型清单：`Handle_`、`TopoDS_`、`BRep*`、`Geom_*`、`NCollection_`
- 裸指针穿越：`new 内核类型` 后经 return/参数传递出作用域
- 失败状态检查：内核调用点紧邻 `IsDone()`/`IsNull()`/`!IsValid()` 或 try/catch
- 生命周期：同作用域 `new`/`delete` 直接作用于内核类型

**评分算法：**

```
score = 0
if 存在内核闭合性校验测试引用(BRepCheck/BOPCheck/CheckShape):  score += 30   # GCS-001 加分项
if 无跨作用域裸指针穿越内核对象:                        score += 25   # GCS-002
if 内核调用点有紧邻失败状态检查:                        score += 25   # GCS-003
if 无同作用域手动 new/delete 内核对象:                  score += 20   # GCS-004
```

### 2.2 内核精度/单位一致性（20%）

**代码坏味道：** "魔法数字（Magic Number）"——精度/容差/单位换算参数以裸数字硬编码，未集中命名管理。

**检测方法：**
- 硬编码精度：`1e-<n>`/`0.00<n>` 且无命名常量（`TOL`/`PRECISION`）对照
- 换算魔法因子：`3.28084`/`25.4`/`0.0254` 等且未调用统一换算函数

**评分算法：**

```
score = 0
if 无硬编码精度/容差魔法数字:  score += 50   # GCS-005
if 无单位换算魔法因子:        score += 50   # GCS-006
```

### 2.3 科学数据结构组织一致性（25%）

**代码坏味道：** "网格语义混用（Mesh Semantics Mixing）"——同一网格数据被多种网格语义（VTK/gmsh/OpenFOAM）无封装地直接复用，场量命名体系混用。

**检测方法：**
- 网格类型引用：`vtkUnstructuredGrid`/`gmsh`/`fvMesh`
- 交叉索引：≥2 种网格类型同文件 + 直接交叉索引符号（A 格式指针传入 B 格式接口）
- 场量命名：`pointData`/`cellData`/`Field` 命名一致性
- 维度匹配：命名分量常量 vs 硬编码维度因子

**评分算法：**

```
score = 0
if 无网格语义混用(无≥2格式交叉索引):  score += 40   # GCS-007
if 场量组织命名一致:                 score += 35   # GCS-008
if 网格/场量维度匹配:                score += 25   # GCS-009
```

### 2.4 数据表示与访问规范性（25%）

**代码坏味道：** "数据暴露（Data Exposure）"——核心数据以裸数组/裸指针直接暴露，或浅拷贝共享底层缓冲导致数据竞争。

**检测方法：**
- 裸数组密度：科学数据结构引用与裸数组声明并存密度（默认阈值 50%）
- 深/浅拷贝：默认拷贝构造/赋值共享底层缓冲
- 直接成员访问：复用 DIRECT_MEMBER_ACCESS 模式（`obj->internal_/data_/private_`）

**评分算法：**

```
score = 0
if 裸数组未成为主流(密度≤阈值):  score += 35   # GCS-010
if 深/浅拷贝使用正确:            score += 30   # GCS-011
if 数据访问有封装:               score += 35   # GCS-012

# 递进扣分（对齐指南 §2.4）：基础层内核数据一致性 < 60 时，增强层折半
if 子维度 2.1 得分 < 60:
    score = int(score * 0.5)
```

## 三、综合评分

### 3.1 几何内核与科学数据结构一致性综合分

```
综合分 = Σ(子维度得分 × 子维度权重)
       = 2.1×30% + 2.2×20% + 2.3×25% + 2.4×25%
```

> 注：2.4 得分已含递进扣分（2.1 < 60 时折半，见 §2.4）。

### 3.2 与结构质量综合分的合并

本维度作为结构质量的增强维度，通过 profile 引擎集启用（`profile: geometry-consistency`）。合并权重与归一化规则见主报告引擎（`arch_report.py`）。

## 四、等级划分

| 综合分区间 | 等级 | 说明 | 建议动作 |
|:---------:|:----:|:-----|:---------|
| ≥ 85 | 🟢 优秀 | 几何内核与科学数据结构使用规范，数据一致性良好 | 维持现状，关注演进 |
| 70-84 | 🟡 良好 | 基本规范，存在少量魔法因子或封装不足 | 优化低分项 |
| 50-69 | 🟠 需改进 | 存在明显的裸数组滥用、异常未传播或语义混用 | 优先整改几何内核一致性 |
| < 50 | 🔴 差 | 内核数据一致性存在严重风险 | 系统性重构数据访问层 |

## 五、12 条 GCS 规则

### 规则总览

| 规则 | 名称 | severity | output_level | 置信度 | 所属维度 |
|:----:|:-----|:--------:|:------------:|:------:|:--------:|
| GCS-001 | 内核闭合性校验测试存在性（加分项）| LOW | INFO | 中 | 2.1 |
| GCS-002 | Handle 智能指针一致性 | MEDIUM | WARNING | 中 | 2.1 |
| GCS-003 | 内核异常/失败状态传播 | MEDIUM | WARNING | 中 | 2.1 |
| GCS-004 | 内核对象生命周期 | MEDIUM | WARNING | 中 | 2.1 |
| GCS-005 | 硬编码精度/容差魔法数字 | LOW | INFO | 低 | 2.2 |
| GCS-006 | 单位换算魔法因子 | LOW | INFO | 低 | 2.2 |
| GCS-007 | 网格单元类型一致性 | HIGH | ERROR | 中 | 2.3 |
| GCS-008 | 场量组织一致性 | MEDIUM | WARNING | 中 | 2.3 |
| GCS-009 | 网格/场量维度匹配 | MEDIUM | WARNING | 低 | 2.3 |
| GCS-010 | 裸数组替代科学数据结构 | LOW | INFO | 中 | 2.4 |
| GCS-011 | 深拷贝 vs 浅拷贝 | LOW | INFO | 低 | 2.4 |
| GCS-012 | 数据访问封装性 | HIGH | ERROR | 高 | 2.4 |

**KNOWN_HOLES（归 H3）**：欧拉公式约束、B-Rep 闭合性运行时判定（注册进 consistency_check）。

### 规则详细描述

每条规则包含：触发条件、检测逻辑（可执行）、建议修复。

#### GCS-001：内核闭合性校验测试存在性（加分项）
- **触发**：缺失时 INFO 提示（非违规扣分）
- **检测**：`BRepCheck`/`BOPCheck`/`CheckShape`/`IsClosed`/`BRepCheck_Analyzer` 引用存在性
- **建议修复**：对 B-Rep 构造/布尔运算结果使用 `BRepCheck_Analyzer` 校验并纳入测试

#### GCS-002：Handle 智能指针一致性
- **触发**：裸 `new` 内核对象经 return/参数跨作用域穿越
- **检测**：内核类型清单 + 裸指针穿越模式 + 白名单排除内核自身目录
- **建议修复**：内核对象用 `Handle()`/`TopoDS_` 封装，禁止裸指针跨模块穿越

#### GCS-003：内核异常/失败状态传播
- **触发**：同一语句块内、紧邻内核调用点无 `IsDone()`/`IsNull()`/`!IsValid()`/try-catch
- **检测**：调用点上下文窄化判定（跨函数延迟检查不判定）
- **建议修复**：每个内核操作后检查 `IsDone()`/`IsValid()`，异常型内核 try/catch 包裹

#### GCS-004：内核对象生命周期
- **触发**：同作用域 `new`/`delete` 直接作用于内核类型
- **检测**：同作用域裸 new/delete 窄化检测
- **建议修复**：使用引用计数 Handle 自动管理生命周期

#### GCS-005：硬编码精度/容差魔法数字
- **触发**：`1e-<n>`/`0.00<n>` 硬编码且无命名常量（INFO，低置信度）
- **检测**：硬编码精度常量启发式
- **建议修复**：精度/容差集中为命名常量

#### GCS-006：单位换算魔法因子
- **触发**：换算魔法因子（3.28084/25.4/0.0254）且未调用统一换算函数（INFO）
- **检测**：换算魔法因子启发式
- **建议修复**：单位换算集中为统一工具函数

#### GCS-007：网格单元类型一致性
- **触发**：同文件 ≥2 种网格类型引用 + 直接交叉索引符号（ERROR）
- **检测**：多格式引用 + 交叉索引符号窄化；跨格式转换器豁免（归 ACL/MPR-012）
- **建议修复**：统一网格语义，通过封装层或独立转换器转换

#### GCS-008：场量组织一致性
- **触发**：场量命名体系混用（`pointData` vs `cellField`）
- **检测**：命名模式检测 + 白名单
- **建议修复**：统一场量命名与组织规范（`pointData`/`cellData`）

#### GCS-009：网格/场量维度匹配
- **触发**：裸数组维度因子与命名分量常量不一致（WARNING，低置信度）
- **检测**：命名分量常量 vs 硬编码维度因子对照
- **建议修复**：使用带维度的科学数据结构，或与命名常量一致

#### GCS-010：裸数组替代科学数据结构
- **触发**：科学数据结构引用存在 且 裸数组声明占比 > 阈值（INFO）
- **检测**：密度阈值判定（默认 50%，WP-2 校准）
- **建议修复**：核心数据容器用科学数据结构封装

#### GCS-011：深拷贝 vs 浅拷贝
- **触发**：共享底层缓冲的浅拷贝模式（INFO，低置信度）
- **检测**：默认拷贝构造/赋值共享指针启发式
- **建议修复**：需要独立数据时显式深拷贝

#### GCS-012：数据访问封装性
- **触发**：跨模块直接访问内部成员（`obj->internal_/data_/private_`）（ERROR）
- **检测**：复用 DIRECT_MEMBER_ACCESS 模式
- **建议修复**：封装内部数据结构，通过公开 API 访问

## 六、跨规则协调

### 6.1 GCS-002 与 GCS-004 边界（防双重计分）
- GCS-002 管**跨作用域裸指针穿越**（return/参数传递出作用域）
- GCS-004 管**同作用域手动 new/delete 生命周期**
- 以"是否穿越作用域"为界，同一代码不重复触发

### 6.2 递进扣分（2.1 → 2.4）
子维度 2.1（内核数据一致性）< 60 时，子维度 2.4（数据访问规范性）得分折半——对齐设计依据层级主张。

### 6.3 GCS-007 与 ACL/MPR-012 边界
跨格式转换适配器（显式转换函数输入/输出分属不同格式）不触发 GCS-007，归维度⑧ ACL 防腐 / MPR-012 格式转换统一性。

### 6.4 与数值算法（NVR）边界
单位制错误/数值正确性归 NVR；数据组织一致性归本维度。单位换算魔法因子（GCS-006）与 ACL-008（数据交换单位制）不重复计分。

## 七、基线校准

### 7.1 校准方法
- GCS-010 裸数组密度阈值（默认 50%）需 WP-2 在真实项目上校准
- 各规则触发阈值（如 GCS-009 维度因子对照）需统计验证
- 校准遵循 H1 基线纪律：统计分布 + 默认值回退

### 7.2 校准数据来源
| 项目 | 用途 |
|:-----|:-----|
| OCCT（V8.0.1）| GCS-001/002/004/005/006 正样本校准 |
| SALOME GEOM（固定 commit）| GCS-002/004/012 正样本校准 |
| 合成项目（4.1-4.12）| 各规则触发/不触发阈值校准 |

## 八、豁免注解体系

### 8.1 注解类型

| 注解 | 用途 | 格式 |
|:-----|:-----|:-----|
| `@gcs_waiver` | 声明受控裸数组（性能热路径）| 行尾注释 `// @gcs_waiver:reason` |
| `@kernel_exempt` | 声明内核自身目录豁免 | 文件头注释 `/* @kernel_exempt */` |

### 8.2 验证规则
- 豁免注解仅对**同文件/同语句**生效（不全局生效）
- 未声明理由的豁免无效
- 豁免注解不改变 scoring，仅将对应规则的 output_level 降为 INFO

## 九、启用条件

本 Skill 在检测到几何内核/科学数据结构引用时自动启用，权重占结构质量的候选 10%~15%（H2 排期中归一化定案）。

**几何内核项目判定标准**（满足任一）：

| 判定条件 | 检测方式 |
|:---------|:---------|
| 内核类型引用 | 源码含 `TopoDS_`/`Handle_`/`BRep*`/`Geom_*`/`NCollection_` |
| 科学数据结构引用 | 源码含 `vtk*`/`fvMesh`/`gmsh`/`CGAL` |
| 项目路径/描述 | 含 `occt`/`opencascade`/`cascade`/`geometry kernel`/`brep` |
