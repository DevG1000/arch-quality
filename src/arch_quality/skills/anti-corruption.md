# 外部科学内核与几何内核的封装与防腐层评估技能

本技能提供外部科学内核与几何内核的封装与防腐层（Anti-Corruption Layer）评估的领域知识，包括 4 个评估维度定义、评分算法、12 条 ACL 规则、基线校准方法和豁免验证框架。

> **版本绑定**
> - 对应《外部科学内核与几何内核的封装与防腐层评估指南》**1.3 版**
> - 对应实现：`arch_metrics_anti_corruption.py`
> - 技能版本：**1.0**（`SKILL_VERSION = "1.0"`，对齐指南 1.3）
> - **三方一致性**：指南 §2.x ↔ Skill §2.x ↔ Tool `calc_xxx()` 的评分算法应保持一致。修改任一方时需同步其他两方。

## 二、维度定义与评分算法

每个维度包含：代码坏味道名称、检测方法、评分算法。评分算法从指南的文字描述中提取为可执行的分段函数。

### 2.1 外部内核访问防腐（30%）

**代码坏味道：** "直连内核 + 类型泄漏（Direct Kernel Access & Type Leakage）"——业务代码直接调用内核 API，或 wrapper 公共接口把外部类型当作普通参数暴露。

**检测方法：**
- 内核符号清单：`TopoDS_`、`BRep*`、`Handle_*`（见 §7.1 外部符号清单）
- 直连检测：内核符号在 wrapper 目录白名单**之外**引用
- 类型泄漏：wrapper 公开头文件签名中出现外部内核类型
- 失败封装：内核调用点紧邻 try/catch 或错误码检查（异常型/状态码型）

**评分算法：**

```
score = 0
if 无白名单外内核符号直连（ACL-001）:   score += 40
if 无内核类型泄漏进 wrapper 公开签名（ACL-004）:  score += 30
if 内核调用失败已封装（ACL-005）:      score += 30
```

### 2.2 Wrapper 覆盖度与演进守卫（15%）

**代码坏味道：** "防腐缺口（Anti-Corruption Gap）"——核心内核 API 无 wrapper 覆盖，或版本差异点无守卫，升级影响面失控。

**检测方法：**
- 覆盖度：外部内核核心类清单 vs wrapper 头文件声明引用比对
- 版本守卫：`#if OCC_VERSION`/`VERSION` 条件编译存在性 + 守卫密度

**评分算法：**

```
score = 0
if 核心 API wrapper 覆盖度达标（ACL-002）:  score += 50
if 内核版本守卫存在（ACL-003）:            score += 50
```

### 2.3 数据交换防腐（30%）

**代码坏味道：** "数据交换散落（Data Exchange Scatter）"——格式读写符号散落各业务模块，绕过集中 import/export；错误未处理。

**检测方法：**
- 格式符号清单：`STEPControl_*`、`IGESControl_*`、IFC、`IFSelect_*`（见 §7.1）
- 读写集中度：格式符号在 import/export 模块白名单之外引用
- 错误处理：reader/writer 调用点错误码检查（`IFSelect_ReturnStatus`/异常）
- 直连密度：格式符号在专用模块外的引用密度

**评分算法：**

```
score = 0
if 无白名单外格式符号读写散落（ACL-007）:  score += 45
if reader/writer 错误已处理（ACL-011）:   score += 30
if 格式直连密度 ≤ 阈值（ACL-012）:        score += 25
```

### 2.4 保真度与外部标准一致性（25%）

**代码坏味道：** "语义失真（Semantic Loss）"——数据交换无往返保真度校验、单位/公差换算散落、标准版本未声明守卫。

**检测方法：**
- round-trip：`round_trip`/write+read 比对断言存在性
- 单位换算：魔法因子（25.4/0.0254/3.28084 等）且未调用统一换算函数
- 公差换算：公差魔法因子
- 标准版本守卫：AP203/AP214/AP242 声明/守卫存在性

**评分算法：**

```
score = 0
if round-trip 测试存在（ACL-006 加分项）:  score += 40
if 无单位换算魔法因子（ACL-008）:          score += 20
if 无公差换算魔法因子（ACL-009）:          score += 20
if 标准版本守卫存在（ACL-010）:            score += 20

# 递进扣分（对齐指南 §2.4）：任一基础层 < 60 时，增强层折半
if 子维度 2.1 得分 < 60 或 子维度 2.3 得分 < 60:
    score = int(score * 0.5)
```

## 三、综合评分

### 3.1 外部内核防腐层综合分

```
综合分 = Σ(子维度得分 × 子维度权重)
       = 2.1×30% + 2.2×15% + 2.3×30% + 2.4×25%
```

> 注：2.4 得分已含递进扣分（任一基础层 < 60 时折半，见 §2.4）。

### 3.2 与结构质量综合分的合并

本维度作为结构质量的增强维度，通过 profile 引擎集启用（`profile: anti-corruption`）。合并权重与归一化规则见主报告引擎（`arch_report.py`）。

## 五、12 条 ACL 规则

### 规则总览

| 规则 | 名称 | severity | output_level | 置信度 | 所属维度 |
|:----:|:-----|:--------:|:------------:|:------:|:--------:|
| ACL-001 | 直连内核 API | HIGH | ERROR | 高 | 2.1 |
| ACL-002 | 核心 API wrapper 覆盖度 | LOW | INFO | 低 | 2.2 |
| ACL-003 | 内核版本守卫 | LOW | INFO | 低 | 2.2 |
| ACL-004 | 内核类型泄漏 | MEDIUM | WARNING | 中 | 2.1 |
| ACL-005 | 错误处理封装 | MEDIUM | WARNING | 中 | 2.1 |
| ACL-006 | 数据交换往返保真度测试存在性（加分项）| LOW | INFO | 高 | 2.4 |
| ACL-007 | STEP/IGES/IFC 读写防腐 | HIGH | ERROR | 高 | 2.3 |
| ACL-008 | 单位换算魔法因子 | LOW | INFO | 低 | 2.4 |
| ACL-009 | 公差换算魔法因子 | LOW | INFO | 低 | 2.4 |
| ACL-010 | 标准版本守卫 | LOW | INFO | 低 | 2.4 |
| ACL-011 | 导入导出错误处理 | MEDIUM | WARNING | 中 | 2.3 |
| ACL-012 | 格式直连检测 | MEDIUM | WARNING | 中 | 2.3 |

**KNOWN_HOLES（归 H3）**：内核升级 API 影响面兼容测试（注册进 consistency_check）。

### 规则详细描述

每条规则包含：触发条件、检测逻辑（可执行）、建议修复。

#### ACL-001：直连内核 API
- **触发**：wrapper 目录白名单外引用内核符号（`TopoDS_*`/`BRep*`/`Handle_*`）（ERROR）
- **检测**：内核符号清单 × wrapper 白名单外定位
- **边界**：与 ACL-007 信号互斥（内核符号→001，格式符号→007/012）
- **建议修复**：业务层依赖统一 wrapper 接口，内核调用收敛到防腐边界内

#### ACL-002：核心 API wrapper 覆盖度
- **触发**：核心内核 API 类在 wrapper 无声明，覆盖度 < 阈值（INFO，低置信度）
- **检测**：内核核心类清单（人工维护）vs wrapper 声明引用比对
- **建议修复**：核心内核 API 全部收敛到 wrapper，避免业务层直连

#### ACL-003：内核版本守卫
- **触发**：`#if OCC_VERSION` 类版本守卫缺失或密度过低（INFO，低置信度）
- **检测**：条件编译宏存在性 + 守卫密度统计
- **建议修复**：内核版本差异统一用 `#if OCC_VERSION` 块隔离在 wrapper 内维护

#### ACL-004：内核类型泄漏
- **触发**：wrapper **公开**头文件签名出现外部内核类型（`TopoDS_Shape`/`Handle_*`）（WARNING）
- **检测**：wrapper 头文件 public 签名外部类型解析
- **建议修复**：wrapper 公开接口用自有值类型，内部转换到内核类型

#### ACL-005：错误处理封装
- **触发**：内核调用点无 try/catch（异常型）或无错误码检查（状态码型）（WARNING）
- **检测**：调用点上下文紧邻检查；格式读写调用点**明确排除**（归 ACL-011）
- **建议修复**：在 wrapper 内统一捕获内核失败并转换为业务异常

#### ACL-006：数据交换往返保真度测试存在性（加分项）
- **触发**：缺失时 INFO 提示（非违规扣分）
- **检测**：`round_trip`/write+read 比对断言存在性
- **建议修复**：为核心数据交换路径补充 round-trip 保真度测试

#### ACL-007：STEP/IGES/IFC 读写防腐
- **触发**：格式符号在 import/export 模块白名单外引用（ERROR）
- **检测**：格式符号清单 × import/export 白名单外定位
- **边界**：与 ACL-012 区分——007 管读写封装形态（位置），012 管直连密度（计数）
- **建议修复**：所有格式读写收敛到集中 import/export 模块

#### ACL-008：单位换算魔法因子
- **触发**：数据交换上下文单位换算魔法因子且未调用统一换算函数（INFO，低置信度）
- **检测**：魔法因子启发式（25.4/0.0254/3.28084）
- **边界裁决**：数据交换场景归 ACL-008，内核操作场景归 GCS-006，不重复计分
- **建议修复**：单位换算集中为统一工具函数

#### ACL-009：公差换算魔法因子
- **触发**：公差换算魔法因子（INFO，低置信度）
- **检测**：公差魔法因子启发式
- **建议修复**：公差换算与单位换算统一集中管理

#### ACL-010：标准版本守卫
- **触发**：外部标准版本（AP203/AP214/AP242）未声明或未守卫（INFO，低置信度）
- **检测**：AP 版本声明/守卫存在性
- **建议修复**：数据交换模块显式声明支持的标准版本并加守卫

#### ACL-011：导入导出错误处理
- **触发**：reader/writer 调用点无错误码检查（WARNING）
- **检测**：格式读写符号调用点 + `IFSelect_ReturnStatus`/异常检查
- **边界**：格式读写调用点的错误处理**只归 ACL-011**；ACL-005 排除此类调用点
- **建议修复**：每次读写后检查 `IFSelect_ReturnStatus`/异常

#### ACL-012：格式直连检测
- **触发**：格式符号在专用模块外引用密度 > 阈值（WARNING）
- **检测**：引用密度统计（阈值 WP-4 校准）
- **边界**：仅在已由 ACL-007 判定散落的场景叠加密度计数，避免重复惩罚
- **建议修复**：消除专用模块外的格式符号直连

## 六、外部符号清单（对齐指南 §7.1）

检测信号集中于下表，作为工具检测正则与白名单的**单一事实来源**。两清单**互斥**：

| 清单 | 符号 | 归属规则 | 白名单 |
|:-----|:-----|:---------|:-------|
| **内核符号集** | `TopoDS_*`、`BRep*`、`Handle_*`、`CGAL` | 仅 ACL-001/004/005 | wrapper 目录 |
| **格式符号集** | `STEPControl_*`、`IGESControl_*`、IFC、`IFSelect_*` | 仅 ACL-007/011/012 | import/export 模块目录 |

> **归属原则（专家校对 P1 修订）**：同一符号引用**只被其所属清单的规则评估**——内核符号不触发格式规则，格式符号不触发内核规则。格式读写调用点的错误处理只归 ACL-011，ACL-005 不重复。

## 八、豁免注解体系

### 8.1 防腐边界目录排除（引擎内建）

**匹配目录**：wrapper/封装层目录、import/export 模块目录（项目配置声明）

**作用域**：涉及"白名单外直连/散落"的全部 ACL 规则判定（ACL-001/007/012）。默认防腐边界设为引擎内建，业务侧非法位置一目了然；目录级排除与注解级为 OR 关系。

### 8.2 注解类型

| 注解 | 用途 | 格式 | 作用域 |
|:-----|:-----|:-----|:-------|
| `@acl_exempt` | 文件级防腐排除（vendored 内核/第三方 SDK）| 文件头 `/* @acl_exempt: reason */` | **全部 12 条规则** |
| `@acl_waiver` | 声明受控的直连/散落（性能或历史债务）| 行尾注释 `// @acl_waiver: reason` | **仅指定规则**（默认 ACL-001/012）|

**与其它引擎的差异（重要）**：标准/数值/模板/求解器四类引擎的豁免**只降级 `output_level`、不改变 scoring**。ACL 的两个注解**均会影响评分**，原因如下：

- `@acl_exempt`：缩小统计范围（12 条规则的计数基数），等价于把该文件移出评估集（vendored 内核实为内核自身）
- `@acl_waiver`：默认已受控/INFO，单纯降级无任何效果；真实痛点是受控直连/散落使计数超阈值、拿不到对应分。故本注解显式例外于"豁免不改 scoring"约定

### 8.3 验证规则

- **reason 必填**：缺失 reason 的注解**无效**（如 `/* @acl_exempt */`、`// @acl_waiver`），并在 `waiver_audit.invalid_waivers` 中记录告警
- 作用域为**同文件**：`@acl_exempt` / `@acl_waiver` 仅对所在文件生效，不跨文件传播
- 注解须写在**注释**中（`/* */` 或 `//`），引擎在剥离注释前采集
- 路径级与注解级为 **OR** 关系：目录命中 **或** 注解命中，任一成立即排除

### 8.4 反滥用守卫

| 守卫项 | 阈值 | 行为 |
|:-------|:-----|:-----|
| `@acl_exempt` 排除文件数 / 受评文件数 | **> 30%** | `waiver_audit.abuse_warning` 输出告警，提示 12 条规则覆盖度可能失真 |
| 防腐边界目录覆盖占比 | **> 30%** | 项目整体被声明为 wrapper/import-export，防腐评估失真 |

审计字段（`all_metrics().waiver_audit`）：`acl_exempt`（count/ratio/scope/files）、`acl_waiver`（同上）、`boundary_dir_exclusion`、`invalid_waivers`、`abuse_limit`、`abuse_warning`。

## 九、启用条件

本 Skill 在检测到外部内核/数据交换标准引用时自动启用，权重占结构质量的候选 10%~15%（H2 排期中归一化定案）。

**外部内核/防腐项目判定标准**（满足任一）：

| 判定条件 | 检测方式 |
|:---------|:---------|
| 外部内核类型引用 | 源码含 `TopoDS_`/`Handle_`/`BRep*`/`CGAL` |
| 外部标准数据交换引用 | 源码含 `STEPControl_*`/`IGESControl_*`/IFC |
| 版本守卫 | 源码含 `OCC_VERSION` |
| 项目路径/描述 | 含 `wrapper`/`import-export`/`anti-corruption`/`封装`/`防腐`/`occt`/`opencascade` |

> **实现现状**：参照 GCS §8 先例，`_detect_acl()` 路径/描述关键词判定与源码信号检测的实施状态将在工具中显式声明（对齐 H2-002）。
